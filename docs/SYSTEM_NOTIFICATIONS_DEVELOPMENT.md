# 系统通知开发文档

## 目标与分类

手机应用进入后台时，Codex 回复完成或会话需要批准操作后，在 Android 通知栏显示系统通知；点击通知回到对应聊天。本次属于新增功能 / MINOR，目标版本为 `0.9.0-dev.1`。

通知由现有网页实时连接触发，不新增云推送服务。Android 进程仍运行且隧道连接可用时可收到通知；进程被系统结束或隧道断开时无法收到，届时需要单独接入 FCM 等推送服务。

## 实施步骤

1. 在设置页增加系统通知开关；用户主动开启并授予 Android 通知权限后才发送通知。
2. 将回复完成和待批准事件接入通知；应用在前台时继续使用现有页面提示，避免重复打扰。
3. 在 Android WebView bridge 中实现原生通知权限、通知栏展示和点击聊天跳转；普通 HTTPS 浏览器使用 Notification API。
4. 更新 Web、服务端和 Android 版本号；构建 Web 资源与新的 debug APK，不覆盖已有安装包；递增 Android `versionCode`。
5. 检查权限与通知导航代码，运行 Web 和 Android 构建、差异检查；不运行测试，不安装 APK，不推送 GitHub。

## 完成标准

- 用户可在设置中开启系统通知；权限被拒绝时显示明确提示。
- Android 应用在后台且连接仍在线时，回复完成和待批准事件显示通知。
- 点击通知后打开对应会话；前台使用时不额外发系统通知。
- 新 APK 使用版本号命名，现有 APK 保留；用户已有文档修改不进入提交。
