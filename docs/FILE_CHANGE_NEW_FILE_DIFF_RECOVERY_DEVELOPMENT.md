# 新增文件差异格式恢复开发文档

## 目标与分类

修复文件变更记录把新增文件的原文误当作统一 diff，导致审核预览不显示新增颜色、增删行数为零的问题。属于 PATCH / 修复：恢复既有文件变更统计与审核显示，目标版本为 `0.56.4-dev.3`。

## 交互设计

- 只有包含有效 unified diff hunk 的字符串才作为差异预览。
- 已明确标记为新增文件、但只提供文件原文时，将原文转成全新增 unified diff，并按实际文本行数统计。
- 真实 unified diff 的 hunk 行数用于统计，避免接口元数据与预览行数互相矛盾。
- 合并工作区兜底变化时，优先有效 unified diff；原生事件中的无效差异不得覆盖有效兜底差异。
- 对无法可靠解析为差异的普通修改，保留路径并退回文件全文预览，不伪造颜色或行数。

## 实施步骤

1. 在前端文件变更解析中校验 unified diff hunk，规范新增文件原文和有效差异的行数。
2. 更新原生事件与工作区兜底差异的合并优先级，并兼容缓存、历史数据中的旧格式。
3. 更新版本及 CHANGELOG；生产构建并检查差异，不新增或运行测试。
4. 创建仅包含本次修改的本地提交，不推送 GitHub。

## 验收标准

- 新增 Markdown 文档显示准确的绿色新增行，新增数等于文件正文行数，删除数为 0。
- 更新、删除文件的有效 unified diff 仍按 hunk 标注颜色和行号。
- 无效原生 diff 不遮盖有效的工作区兜底 diff；无法恢复时显示全文而不是虚假的 0/0 差异预览。
- `pnpm build` 成功，`git diff --check` 无输出；不新增或运行测试。

## 完成记录

- 前端现验证 unified diff hunk，并从 hunk 实际内容统计新增、删除行数；新增文件原文会生成全新增 diff。
- 合并事件与本地缓存时统一规范化差异；无效原生差异不再覆盖有效工作区差异。
- 版本更新为 `0.56.4-dev.3`。`pnpm build` 成功；未新增或运行测试。构建仍有大型 JavaScript chunk 的既有提醒。
