# SSH 凭据隔离开发文档

本次让 AI 继续使用设置页保存的 SSH 密码或私钥连接服务器，同时无法直接读取 Code Remote 保存的凭据，属于**修复 / PATCH**：连接能力和填写流程保持不变，修正已有凭据隔离不足。目标版本 `0.83.1-dev.1`。

## 现状与目标

- 当前网页后端、Codex、Claude 和 SSH MCP 均以同一宿主机账号运行；MCP 子进程直接读取 `ssh-secrets`。仅把凭据移到另一个 Python 对象或子进程并不能隔离 AI 的本机命令。
- Linux 上由网页后端保管凭据、检查逐台权限并执行 SSH。MCP 子进程只通过本地 Unix socket 提交服务器编号与操作，返回输出和退出码，不传递凭据。
- Codex 和 Claude CLI 及其子进程进入私有用户、PID 和挂载命名空间。宿主机文件系统只读，工作区和 CLI 所需目录可写；Code Remote 的状态目录被遮蔽，只显式挂入聊天附件和 SSH 代理 socket。宿主机 Codex daemon 的 Unix socket 同样被遮蔽。
- 设置页保存密码、首次确认指纹、连接检查、远端 SSH 账户权限及聊天操作记录维持现有流程。

## 实施步骤

1. 增加 Linux AI 进程隔离启动器，使用 bubblewrap 封闭宿主机状态目录和进程视图；只把工作区与必要的 CLI 目录开放给 AI。隔离不可用时，不以可读取凭据的方式启动 AI。
2. 增加由后端持有的 SSH Unix socket 代理，统一处理 MCP 的三个现有工具。代理每次执行时读取最新服务器配置，检查启用状态和逐台权限，并继续写入原有聊天日志。
3. Codex 与 Claude 的 MCP 配置只传代理 socket 地址及聊天上下文，不再传配置、日志和凭据路径。MCP 子进程不再创建凭据存储对象。
4. 更新设置页对隔离范围的说明、版本号和简短更新记录；构建并本地提交，不推送 GitHub。

## 安全边界

- 这是当前 Linux 服务实例的运行时隔离。拥有宿主机 root 权限的其他进程或将来被人为执行的已修改后端代码仍能读取凭据；若要防住这类情况，必须把凭据代理和网页后端拆为不同系统权限域。
- AI 仍可通过获准的 SSH 工具执行目标账户允许的操作；目标账户本身的权限不会被削减。逐台勾选权限是代理的强制检查。聊天中的 MCP 确认属于交互授权，不作为阻止 AI 绕过本地 socket 的唯一安全边界。
- 其他在宿主机上本来可读的凭据和用户自己提供给 AI 的秘密不在此次隔离范围内。
- Linux 以外平台暂不宣称具备同等的进程隔离，保留现有连接流程。
