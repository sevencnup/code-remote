# 代码选区编号与附件单行栏开发记录

## 目标

让同一条待发送消息中的多个代码选区可以通过序号直接指代，并将待发送附件从纵向列表改为单行横向滚动条。

## 交互约束

- 代码选区附件按当前待发送选区顺序编号为 1、2、3……。
- 序号同时显示在附件名称中并写入 Markdown 正文，方便用户在消息提示中指代某个选区。
- 普通上传文档不占用代码选区序号。
- 删除附件后，剩余选区原编号保持不变；新添加的选区使用当前最大序号加一，避免已显示编号发生漂移。
- 多个文档附件在一行排列，窄屏/超出宽度时横向滚动，不换行、不改变原有移除操作。

## 实施步骤

1. 在 Composer 附件追加 API 中识别代码选区附件，分配下一个稳定编号并同步写入名称与 Markdown 正文。
2. 将待发送文档容器改为不换行的横向滚动条，约束附件卡片宽度并保留可访问名称。
3. 补充分配编号的单元测试，运行前端测试、构建和差异检查。
4. 更新版本记录并创建本地提交；不推送 GitHub，除非收到明确命令。

## 验收标准

- 连续添加多个选区后能看到顺序编号，Codex 文档内容也能读取相同编号。
- 移除一个选区不会重排其余编号；后续选区使用新的最大序号加一。
- 多个待发送文档始终占一行，超出容器时可左右滑动查看与移除。
