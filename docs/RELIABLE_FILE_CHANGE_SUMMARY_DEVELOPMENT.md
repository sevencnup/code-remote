# 稳定文件改动汇总开发文档

## 目标

让“已编辑 N 个文件”卡片在每一轮 Codex 实际修改工作区文件后稳定显示，并绑定在对应对话轮次的回复下方；切换聊天、刷新历史或开始下一轮都不能覆盖之前的记录。

## 问题与边界

- 原生 `FileChange` 事件可提供 diff，但部分工具调用和命令直接写文件时只会产生 `CommandExecution`，不会发送该事件。
- 仅靠单一的前端全局状态会在浏览器重连、热更新、切换聊天或下一轮开始时覆盖旧卡片。
- 工作区可以不是 Git 仓库，因此不能将 Git diff 作为唯一兜底来源。
- 监听仅覆盖网页端启动的一轮 Codex 任务，忽略 `.git`、依赖目录和 Python 虚拟环境等默认忽略目录；不会扫描或展示工作区以外的文件。
- 原生事件的 diff 和增删行数优先；监听兜底仅对本轮开始快照与结束内容均可可靠读取的文本文件补充 diff 和行数。快照超限、二进制或读取失败时只补充路径，不伪造行数。

## 方案

1. 后端在 `turn/start` 前启动该轮工作区文件监听器。
2. 在 `turn/completed` 时停止监听，归并新增、修改、删除路径；对可可靠比较的文本文件生成 unified diff 和增删行数，并通过 WebSocket 发送 `turn/workspaceChanges` 通知。
3. 后端按线程/轮次暂存该结果，并在 `thread/read` 返回的对应轮次上附带结果，支持页面刷新后的恢复。
4. 前端以轮次 ID 保存文件改动组；原生 `FileChange` 与工作区兜底结果合并，同一路径已有原生事件时保留原生 diff，不重复计数。
5. 消息渲染时将卡片插入该轮最后一条 Codex 回复之后，不再在消息流末尾渲染一个全局卡片。
6. 没有可靠行数时隐藏 `+0/-0`，仍显示已编辑文件数和路径。

## 验收标准

- 原生 `fileChange`、`FileChange` 和 snake_case 字段均能解析。
- 仅通过命令修改文件的一轮任务结束后，页面显示对应文件汇总卡片。
- 原生文件变更与工作区监听同时出现时，卡片文件数不重复、原生 diff 和行数优先且可审核；监听兜底补充原生事件缺失的路径及其可计算 diff。
- 同一聊天的多轮文件修改各自显示在对应回复下方；切换到任意历史聊天仍可看到其对应卡片。
- 刷新页面或重新读取当前对话后，服务尚未重启时可恢复各轮兜底卡片。
- 工作区外、`.git`、`node_modules`、`.venv` 等路径不会出现在卡片中。
- 前端生产构建、后端单元测试和差异检查均通过。
