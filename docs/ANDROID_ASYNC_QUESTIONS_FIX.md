# Android 助手提问显示与回答修复

## 目标与分类

修复已承诺的助手选择题在 APP 中仍为纯文本、AI 等待回答时无法选择并继续的问题，属于 PATCH。期间网页版已提交到 `0.76.6-dev.1`，本次最终版本顺延为 `0.76.7-dev.1`，Android `versionCode 361`。保留已构建的 `0.76.5-dev.1` 包；最终包补充旧接口切换到结构化题目时的选择状态保留。

## 现场证据

- 当前聊天的 `request_user_input_async` 在原始记录中已生成 `AgentMessage`，带有 `delivery: async` 及 `questions`，包含题目和选项。
- `browser_item()` 只保留助手正文，过滤了这些结构化字段，手机缓存因此只剩文字。
- Android 把同轮助手消息合并，且仅在整轮结束、最后一条正文以选项列表结尾时显示选择卡；异步提问所在的进行中回复无法显示或提交选择。

## 实施步骤

1. 保留结构化提问数据经过历史接口和实时消息后的含义，增加针对实际记录格式的回归检查。
2. Android 优先按结构化题目生成选项和其他答案输入框，保持题目身份与编辑状态稳定；历史题目也能看见题目卡片。
3. 当前未回答的异步提问允许在回复进行中回答，复用现有插队接口；普通已完成提问沿用正常发送流程。保留主输入框草稿并处理失败及重复点击。
4. 更新版本与更新记录，构建独立 APK。检查题目渲染和提交分支后覆盖安装并核对手机界面。
5. 服务端承载当前对话，安排全部回复空闲后自动重启加载字段修复；客户端兼容旧服务端的异步题目文本，使安装后即可显示真实题目。清理本次临时文件和进程，本地提交，不推送 GitHub。

## 完成标准

- 真实异步问题的数据能够完整到达 APP，回复进行中也显示选项、其他答案与发送按钮。
- 选项和自定义答案互斥，发送绑定原聊天和题目；流式更新不清空选中项或自定义答案。
- 不把普通操作列表转为选择题；已有草稿、排队编辑和正常发送保持可用。

## 实施结果

- 历史精简和实时事件都保留 `questions`、`delivery`、`phase`。使用当前聊天的真实异步提问记录核对，新代码输出包含原题目与两个选项。
- Android 将结构化提问独立呈现；兼容旧服务保留的 `call_` 提问消息，支持没有问号的标题和纯文本回答。题目身份不随后续进度文字改变，正在填写答案时暂缓聊天重绘。
- 异步答案先通过可靠提交接口保存，再对该条消息执行立即发送；重试复用同一内容和编号，其他排队消息不受影响。
- 服务端历史、消息精简与队列共 62 项测试通过；Android 5 项题目解析与回答格式测试通过；`testDebugUnitTest` 和 `assembleDebug` 成功。
- `0.76.5-dev.1` 真机截图已确认，进行中的真实提问显示两个选项、其他答案输入框与发送按钮。未向用户聊天提交测试答案。
- 最终 `0.76.7-dev.1` 已覆盖安装，设备核对为 `versionCode 361`；两个版本 APK 均保存在 `artifacts/`，没有覆盖历史包。
- 服务端当前仍承载活动回复，已安排 `code-remote-questions-activate-0767.service` 在所有回复空闲后重启加载补丁；最多等待 30 分钟，服务 PID 改变时退出，避免重复重启。
