# 消息发送长时间等待修复

## 现场依据

- 当前后端在 2026-10-13 09:13:49 UTC 重启，已加载 0.0.204；本次延迟发生在新版本。
- 工作区 `/code` 实际指向 `/mnt/data/code`，发送前每轮都会遍历全部项目并重新建立递归文件监听。
- 隔离复现：原启动准备约 9.99 秒，快照约 3.96 秒，后端事件循环连续阻塞约 6.06 秒。把监听放入线程仍阻塞约 5.56 秒，不能仅用线程包装解决。
- 共享发送分支缺少本地消息即时显示及已有的精确送达回执处理；消息展示依赖启动后重新下载长会话历史。
- 使用目录项自带的文件元信息扫描相同工作区，约 19,673 个文件用时约 0.59 秒。

## 实施步骤

1. 优化快照扫描，复用目录项元信息，保留文件数、文本大小、符号链接和忽略目录限制。
2. 文件审核的补充数据改为轮次开始/结束快照比较，移除每次发送前的递归文件监听。结束扫描与差异计算继续后台执行；原生文件修改通知继续提供回复期间的进度。不能把未完整扫描到的路径误判成新增或删除。
3. 共享发送恢复本地即时消息及精确送达回执；真正入队或明确失败时撤回本地占位。自身发送不再依赖整段历史下载后才能显示消息。
4. 补充有意义的快照差异、慢后台审核、送达与去重回归；测量同一工作区修复后的发送准备耗时，运行相关检查和构建。
5. 更新版本说明并本地提交，保留原有 Android 文档改动。记录运行服务是否已加载补丁，避免把隔离测量当作线上端到端结果。

## 验证结果

- 同一工作区约 19,674 个文件，完整发送准备从约 9.99 秒降至约 0.72 秒；采样的事件循环最大间隔从约 6.06 秒降至约 0.011 秒。
- 上述数据是本机隔离测量，不包含模型回复耗时和设备网络耗时。
- 79 项后端测试、91 项前端测试及生产构建通过，覆盖目录增删、二进制变更、截断扫描、符号链接边界、下一轮内容不会覆盖已捕获的差异，以及现有消息去重与送达恢复。
- 临时诊断进程已退出。后端变更安排在当前回复完成且其他已加载会话空闲后重启生效；重启任务需确认原进程身份、只操作本项目启动器并检查服务健康，完成后删除临时脚本。
