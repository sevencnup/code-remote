# 排队消息编辑时 Esc 误暂停对话修复

## 问题与分类

排队消息在主输入框编辑时，页面级 Esc 处理器只先尝试关闭输入框菜单，随后会中断正在运行的回复；它没有优先取消排队消息编辑。现有“取消编辑”操作会解锁队列并恢复编辑前的草稿与附件。

本次属于修复 / PATCH：修正已有快捷键在编辑状态下的错误动作，不增加新任务能力。目标版本为 `0.70.4-dev.1`。

## 实施步骤

1. 通过输入框句柄提供“若正在编辑则取消编辑”的操作，复用已有取消流程。
2. 输入框菜单关闭时标记 Esc 已处理；页面级 Esc 在关闭菜单之后、暂停或取消续接之前调用该操作，编辑时消费 Esc，避免同一次按键暂停回复。
3. 保留输入法组合、弹窗和菜单已有的优先级；编辑提交中也不让 Esc 落到暂停回复。
4. 更新版本记录和统一版本，构建前端供 `4173` 页面加载，检查差异并创建本地提交。

## 验收标准

- 编辑排队消息时按 Esc 取消编辑，恢复原草稿和附件；正在进行的回复继续运行。
- 输入框菜单打开时，第一次 Esc 仍先关闭菜单。
- 非编辑状态下，Esc 仍按现有逻辑暂停回复或取消续接。
