# Claude 网页回复延迟修复

## 问题与分类

本次属于修复 / PATCH：恢复已有 Claude 回复的及时显示，目标版本 `0.73.1-dev.1`。

代码检查发现三个相关问题：

- Claude 历史接口把仍在执行的轮次标为 `completed`，且不包含已收到的流式正文。网页刷新或重连后会据此关闭该轮次，并将后续正文增量当成迟到事件忽略，直到完整历史可读。
- CLI 消息处理只读取 `stream_event` 中的文本增量，忽略 `assistant` 消息中的正文和内容块起始文本。缺少部分流式事件时，已有正文会等到最终 `result` 才显示。
- 本机 Claude 会话导入后仅发送侧栏变更通知，正文刷新受 15 秒侧栏节流影响；扫描节流期间的最后一次文件变化也可能被丢弃。

## 实施步骤

1. 用隔离的模拟 CLI 和临时数据库复现运行中历史状态错误、完整正文晚转发及重连正文缺失，避免调用真实模型或改动用户会话。
2. 为 Claude 活跃轮次保留内存正文快照，历史接口返回正确的运行状态和已接收正文；完成与取消后清理快照。
3. 按 Claude 消息及内容块合并流式正文和完整正文，收到即可转发，确保最终结果、重复快照及工具后的回复不会重复或遗漏。
4. 本机历史导入后发送指定会话的正文更新通知，复用网页现有的正文刷新通道；为扫描节流保留一次尾部刷新。
5. 运行对应的后端回归和现有历史/消息转发检查，完成前端构建及差异检查，更新版本记录并仅提交本地 Git。
6. 后端变更需重新加载；若当前服务包含活跃任务，使用已有空闲重启脚本安排更新，并明确记录实际生效状态。

## 验收标准

- 运行中的历史响应保持 `inProgress`，刷新页面可读取已收到的正文并继续接收增量。
- CLI 已发出的完整正文在 `result` 到达前可见，正文合并无重复，工具后的多段回复保持顺序。
- 本机历史正文变化能通知当前会话刷新，无需等待侧栏刷新周期，节流期内的最后一次变化不会漏掉。
