# Android 大型代码文件预览性能

## 分类与版本

- 分类：修复 / PATCH。文件预览和编辑能力已经存在；本次降低大文件打开时的主线程排版和语法着色压力，保持原有读取、编辑、保存能力。
- 目标版本：`0.56.4-dev.4`，Android `versionCode 320`。

## 问题与方案

- 当前代码在后台读取文件和生成语法标记，但随后把整份带大量 span 的内容一次性放入 `EditText`。Android 需要在主线程创建编辑缓冲区并测量数千行，导致文件预览卡死。
- 小文件保持现有完整预览。
- 大文件按行数和字符数分页；一次只向编辑框加载当前页，并只对当前页做语法高亮。
- 页面切换时保留各页未保存的编辑内容；保存时按原顺序合并全部页并提交完整文件，继续使用原有 revision 校验。
- 翻页及语法着色放在后台准备，避免把大段处理放到 UI 线程。

## 实施步骤

1. 为大文件预览增加页切分、页导航和当前页状态。
2. 将语法高亮限制在当前页；翻页保留未保存内容，保存时完整合并。
3. 更新 Android PATCH 版本和简短版本记录。
4. 编译 Android Debug APK；如设备在线，检查大文件预览及翻页保存流程，不运行独立测试套件。
5. 检查变更并创建本地提交，不推送 GitHub。

## 验收标准

- 几千行代码文件打开时不再一次性排版和高亮全文。
- 用户能逐页浏览和编辑文件；翻页后返回时编辑内容仍在。
- 保存仍提交完整文件，并保留现有 revision 冲突保护。
- 小文件维持原来的预览体验。

## 实施结果

- 超过 600 行或 96 KB 的文本预览会分页；每页最多约 300 行或 48 KB。分页边界优先落在换行处，遇到超长单行时按字符数拆分，拼接保存不会改动原有换行。
- 仅当前页生成语法高亮。用户翻页时，各页编辑内容暂存于页面状态，保存时重新合并整个文件；成功后使用服务端返回的新 revision。
