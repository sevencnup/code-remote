# 设备群聊选择已有 Codex 聊天开发文档

## 目标与分类

在设备群聊侧栏选择本机已有 Codex 聊天。此后群聊中的 `@本机` 消息继续发往该聊天，保留原有项目上下文；群聊消息仍显示在共用聊天页面。每台设备独立选择自己的聊天。用户因此可以使用已有聊天完成跨设备协作，属于新增功能 / MINOR，目标版本 `0.69.0-dev.1`。

## 实施步骤

1. 扩展房间本机 Codex 会话绑定接口。设置前验证房间、会话存在及引擎类型；允许恢复自动创建专用会话的模式。状态接口返回本机会话绑定。
2. 执行群聊任务时使用所选会话及其原工作目录，避免把旧会话切换到 Code Remote 默认目录；自动创建模式继续沿用现有行为。
3. 在设备群聊侧栏提供可搜索的本机 Codex 聊天列表和当前选择。使用现有聊天历史数据，选择后即时保存并在刷新后恢复；不把其他设备的会话 ID 当成本机会话。
4. 更新版本记录及网页、后端、Android 版本名。不生成 Android 安装包，不递增 `versionCode`。
5. 运行针对绑定与执行路径的测试、前端生产构建、差异检查，然后仅提交本次文件到本地仓库。

## 验收

- 已加入群聊的 Linux 或 Windows 设备可在群聊侧栏选择本机已有 Codex 聊天；刷新后仍显示绑定。
- `@该设备` 使用所选会话的原有上下文和工作目录，回复继续同步到群聊。
- 选择自动创建专用会话后，群聊可继续按原行为执行；普通聊天页面与其他设备的会话不被切换。
- 无效会话、Claude 会话及群聊任务正在运行时的切换得到明确错误提示。

## 验证结果

- 使用项目虚拟环境运行针对旧 SQLite 表迁移、已有聊天绑定、原工作目录执行、拒绝 Claude 会话和恢复自动模式的临时内存测试，全部通过；未保留一次性脚本。
- `./node_modules/.bin/tsc -b`、`./node_modules/.bin/vite build`、Python 编译检查及 `git diff --check` 通过。
- `pnpm build` 被上层 pnpm workspace 中无关项目 `wotty-agentCluster` 缺失的 `@agentforge/protocol` workspace 包阻断；直接使用当前项目已安装的 TypeScript 与 Vite 完成等价生产构建。
