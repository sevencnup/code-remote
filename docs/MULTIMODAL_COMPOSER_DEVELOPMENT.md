# 多模态输入与模型选择开发文档

## 目标

优化 Codex Remote 的聊天阅读体验，并让手机网页能选择本机账户可用的 Codex 模型、附加图片后向 Codex 发送。

## 协议依据

依据 OpenAI 官方 [Codex App Server 文档](https://developers.openai.com/codex/app-server/)：

- 使用 `model/list` 获取当前账户可选择的模型及其 `inputModalities`，不在网页硬编码模型名称。
- `turn/start` 可带 `model` 覆盖该 thread 的模型设置。
- `turn/start.input` 支持 `text`、远程 `image` URL 和本机路径 `localImage`；网页图片在本机服务认证后写入私有临时目录，并以 `localImage` 传给 App Server。

## 范围

- 用户消息置于聊天区右侧，以 `#2d2d2e` 边框包裹；助手消息保持左侧。
- 将未输出回复时的活动状态放到助手消息正文的左对齐位置。
- 在聊天头部提供从 `model/list` 动态加载的模型下拉选择；模型选择会随下一条消息传给 Codex。
- 在输入框底部提供模型和思考强度选择；思考强度使用所选模型返回的 `supportedReasoningEfforts`，并通过 `turn/start.effort` 发送。
- 在输入框提供图片选择、缩略图预览、移除与发送；支持 PNG、JPEG、WebP、GIF，每张最多 8 MB，单条最多 4 张。
- 输入框会识别剪贴板中的图片并添加为待发送附件，粘贴纯文本保持原输入行为。
- 后端只在进程私有临时目录保存图片，服务退出时清理；输入图片不对局域网暴露 URL。

## 实施步骤

1. 扩展本机 API 与 App Server 包装，增加模型列表接口，并把模型和本机图片路径传入 `turn/start`。
2. 在受认证的请求中校验、解码并暂存图片，限制类型、数量和体积。
3. 扩展网页客户端和状态 hook，加载模型并携带图片、模型参数发送 turn。
4. 改造聊天消息、活动状态和输入框的布局与样式，提供图片预览和模型选择。
5. 更新核心开发文档与版本记录，执行生产构建并创建本地 Git 提交。

## 验收标准

- 用户消息显示在右侧并使用 `#2d2d2e` 边框；等待状态与助手正文左边缘一致。
- 模型选项来自当前本机 Codex `model/list` 响应，选择后随下一 turn 传递。
- 可在网页选择最多四张受支持图片，并与文字一起或单独发送给支持图片输入的模型。
- 图片不作为可猜测的局域网静态地址暴露，服务退出后临时文件被删除。
- 不支持图片输入的已选模型会在网页阻止附加图片并给出说明。
- `pnpm --filter codex-remote build` 成功。
