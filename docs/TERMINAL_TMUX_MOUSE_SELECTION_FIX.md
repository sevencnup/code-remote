# tmux 鼠标拖选松手丢失修复

## 分类与目标

本次属于修复 / PATCH：恢复已有的终端选中文字、右键复制和插入聊天框流程。当前版本为 `0.40.0-dev.1`，目标版本为 `0.40.1-dev.1`。

## 已确认原因

- 截图的黄色选区与右上角 `[0/0]` 属于 tmux 复制模式，并非浏览器 xterm 选区。
- 后端为持久终端开启 tmux `mouse on`，xterm 因此停用普通鼠标选择并把鼠标操作发到后端。
- 当前 tmux 的 `copy-mode` 和 `copy-mode-vi` 都把 `MouseDragEnd1Pane` 绑定到 `copy-pipe-and-cancel`，松手立即退出复制模式。前端缓存与触摸高亮无法修复这条鼠标路径，右键菜单也读取不到 tmux 的内部选区。

## 实施步骤

1. 在鼠标上报模式下由网页接管普通左键拖选，使用 xterm 公共选择接口保存文字；普通终端继续使用原有鼠标选择逻辑。
2. 支持正向、反向、多行拖选，以及双击选词、三击选行；结束拖选、卸载时清理文档事件。
3. 保留滚轮事件供 tmux 查看历史；提前接管右键按下，防止 xterm 上报右键时清空选区，再由菜单读取网页保存的选中文字。
4. 用真实浏览器加载 TerminalDialog，模拟 tmux 的鼠标上报和备用屏幕，验证松手后选区保持、无鼠标输入发往 tmux、右键插入文字正确，并检查普通终端与滚轮路径。
5. 构建网页，记录用户可见修复，本地提交本次文件，不推送远端。

## 验收标准

- 普通鼠标拖选显示网页选区，松手后继续保持，终端不会因此进入 tmux 复制模式。
- 正反向与多行选中文字正确；右键“复制”“粘贴到输入框”读取相同文字。
- 滚轮仍能送达开启鼠标上报的终端；无鼠标上报的终端沿用 xterm 原有行为。
