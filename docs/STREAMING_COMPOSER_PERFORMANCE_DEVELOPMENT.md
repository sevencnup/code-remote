# 流式回复输入性能开发文档

## 目标

让移动端和桌面端在 Codex 持续流式回复、长聊天历史和侧栏会话较多时，输入框仍能保持连续、及时的键盘响应。

## 根因

- 每个 WebSocket 回复分片都会立即更新消息状态；高频分片会让 React 连续同步提交渲染。
- 即使历史消息没有变化，消息气泡仍会随父组件重绘，重复解析长文本和代码块。
- 每次消息状态变化都会同步读取并写入滚动高度，长内容会触发额外布局计算。

## 实施步骤

1. 为流式回复建立短间隔合并队列，并把非最终的消息渲染标为低优先级；回复完成时立即提交最终文本。
2. 记忆化消息气泡，并稳定复制回调，使未变更的历史消息不重复解析或渲染。
3. 将自动跟随底部的滚动操作合并到动画帧中，避免同一帧内多次强制布局。
4. 更新版本记录，执行前端构建和差异检查后创建本地 Git 提交。

## 验收标准

- Codex 高速流式输出时，输入框可以连续输入，不出现明显卡顿或丢字。
- 已完成的历史消息不会在每个流式分片中重复渲染。
- 流式内容仍会持续显示，回复结束后最终全文完整可见。
- `pnpm build` 与 `git diff --check` 均成功。
