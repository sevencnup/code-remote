# 文件增删统计与预览差异标注开发文档

## 目标

1. 让文件改动卡片在有可靠内容差异时显示本轮增删总行数，以及每个文件各自的增删行数；覆盖 Codex 原生 diff 和工作区监听兜底。
2. 从文件改动卡片打开预览时，沿用该文件的 diff，在预览代码中用浅绿色标新增行、浅红色标删除行；桌面和移动端均可打开预览。

## 设计边界

- Codex 原生 diff 优先；工作区监听只为缺少原生事件的路径计算兜底 diff，同一路径不重复合并或累加。
- 工作区不依赖 Git。每轮开始时记录受限的 UTF-8 文本基准，结束时只对监听到的变更路径与最终内容比较；不能取得可靠基准或文件不是受支持文本时，显示路径但隐藏行数，不伪造 `+0/-0`。
- 快照只遍历当前工作目录，跳过现有忽略目录；限制单文件、总快照字节数及文件数，避免大工作区导致内存或启动时间失控。快照工作不得阻塞 asyncio 事件循环。
- 新建文件以空内容为基准，删除文件以空内容为最终值；二进制、超限或读取失败的文件仍保留文件记录，但不提供 diff/行数。
- 预览仍为只读；由审核卡片打开时显示完整 diff 行（含删除行），普通文件树打开时仍显示当前文件内容。保持已有语法着色、行号、滚动、复制和路径安全行为。
- diff 内容作为纯文本解析成 React 节点，不通过 `dangerouslySetInnerHTML` 注入。

## 实施步骤

1. 更新文件改动汇总的既有开发文档，记录工作区兜底可在可靠快照范围内计算 diff，以及卡片预览现支持差异标注。
2. 扩展后端每轮工作区监听状态，在线程池中建立有资源上限的文本快照；结束时对净变更路径生成 unified diff 和增删行数，并随现有 `turn/workspaceChanges` 与历史线程数据持久化。
3. 修改前端文件变更解析和合并：读取后端显式行数；原生 diff 优先，兜底数据既补充缺失路径，也补齐原生记录缺失的 diff/行数；缺失路径归并到单个工作区记录，同一路径只统计一次。回复期间在输入框上方同时显示总增删数和可横向滚动的逐文件增删数。
4. 从审核卡片打开预览时传递该文件 diff；桌面预览栏和移动端全屏预览层解析 hunk、上下文、新增与删除行，显示行号并分别使用浅绿、浅红背景。即使删除文件已无法从工作区重新读取，也仍展示已保存的 diff。刷新同一预览时保留 diff；从文件树打开时清除 diff 状态。
5. 增加后端快照、增删计数、忽略路径、超限/二进制文件及原生 diff 优先级测试；验证前端构建、Python 测试、差异检查。
6. 更新版本记录并创建本地 Git 提交；不推送 GitHub，不启动或重启进程。

## 验收标准

- 修改、新增、删除的普通 UTF-8 文本文件显示准确的逐文件 `+/-` 和卡片总计；总计与逐文件统计一致。
- 同一轮同一路径只显示并计数一次；原生 diff 可用时，保留原生 diff，不被监听兜底覆盖。
- 超限、二进制或无法读取的文件仍显示路径，但不出现伪造的行数或差异内容。
- 从改动卡片打开的预览中，新增行浅绿、删除行浅红，上下文保持中性；行号与差异内容对应，语法着色和横向滚动正常。
- 从文件树直接打开的预览仍显示当前文件全文，不残留前一次文件的 diff。
- 移动端可从审核卡片和文件树进入预览；文件树加号仍用于插入路径，关闭预览后保留文件树状态。
- 工作区外及忽略目录文件不被快照、统计或预览；TypeScript/Vite 构建、Python 单元测试和 `git diff --check` 通过。
