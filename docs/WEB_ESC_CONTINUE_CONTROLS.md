# 网页端 Esc 中断与继续操作

## 目标

网页端把第一次 Esc（或空输入框的暂停按钮）作为“暂时中断并可续接”的操作；再次 Esc 取消续接。续接走同线程新回合，不宣称恢复原 turn ID。

## 步骤

1. 核对网页快捷键、输入框按钮、发送流程与排队消息的约束。
2. 在当前聊天/分屏内记录待续接状态；第一次 Esc 请求中断，第二次 Esc 清除待续接；输入框按钮在待续接时发起新一轮“继续”。
3. 保留草稿、附件与队列，避免继续按钮隐式发送用户草稿；聊天/分屏切换和失败时清理或隔离状态。
4. 运行构建与相关测试，记录版本并本地提交。

## 验收

- 回复中第一次 Esc 请求中断，第二次 Esc 取消续接。
- 中断完成后输入框按钮能发起续接，用户草稿不被覆盖或发送。
- 弹窗/输入法组合状态优先处理 Esc；不同聊天不串用续接状态。
- 暂停时排队消息不自动推进；续接当前任务后再按既有顺序发送队列。
- Android WebView 现有按钮行为不变。

分类：PATCH / 改善已有中断与手动续接的操作便利性，不增加新的任务能力。目标版本 `0.28.4-dev.1`。
