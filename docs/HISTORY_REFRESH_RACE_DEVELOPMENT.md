# 历史刷新竞态修复开发文档

## 目标

修复停止上一轮 Codex 任务后立即发送新消息时，旧的历史刷新结果覆盖本地新消息、导致页面闪动且用户消息暂时消失的问题。

## 根因

- `turn/completed` 会异步调用 `thread/read` 刷新完整历史。
- 用户在停止完成后立即发送下一条消息时，前一轮发起的 `thread/read` 可能晚于本地乐观消息返回。
- 原逻辑只校验当前 `threadId`，同一会话内的旧读取结果仍可以替换当前消息列表。

## 实施步骤

1. 为同一会话的历史读取和本地消息变更增加单调递增版本号。
2. 在切换会话、创建会话、启动新 turn、turn 开始和结束时推进版本号。
3. 历史读取返回时同时校验会话 ID 和版本号；过期结果不更新消息、运行状态或缓存。
4. 更新版本记录，执行前端构建、后端测试和差异检查，并创建本地 Git 提交。

## 验收标准

- 停止一轮后立即发送下一条消息，用户消息不会被旧历史刷新清空。
- Codex 收到的新消息仍正常展示回复。
- 切换会话、手动刷新和正常 turn 完成后的历史同步继续有效。
- `pnpm build`、后端单元测试成功，`git diff --check` 无输出。
