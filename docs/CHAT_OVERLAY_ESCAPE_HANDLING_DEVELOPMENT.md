# 共用聊天浮层的 Escape 关闭开发文档

## 目标与分类

修复文件预览和本机终端浮层打开时，按 Escape 可能中断聊天回复而没有关闭浮层的问题。属于 PATCH / 修复：不改变聊天任务能力，只让当前浮层优先响应关闭快捷键。目标版本为 `0.56.4-dev.2`。

## 交互设计

- 共用 `ChatOverlayPanel` 在页面级捕获 Escape，因此输入焦点位于聊天输入框、终端或浮层其他控件时都能关闭浮层。
- 同时打开多个共用浮层时，只关闭最后打开的最上层浮层。
- 文件预览中的右键菜单或选区菜单先关闭菜单；没有菜单时再关闭预览。
- 文件预览有未保存修改时，继续使用原有确认逻辑；取消确认时不触发聊天中断。
- 只有没有可关闭的浮层时，页面级 Escape 才能中断回复。

## 实施步骤

1. 在 `ChatOverlayPanel` 增加 Escape 处理回调及按打开顺序维护的活动浮层栈。
2. 用共用处理替代 `WorkspaceExplorer` 的单独文档级 Escape 监听，保留预览内部菜单优先关闭与未保存修改确认。
3. 确认终端本体、终端加载态和终端错误态都通过共用处理关闭。
4. 更新前端版本和更新记录；运行生产构建及差异检查，不新增或运行测试。
5. 创建本地 Git 提交，不推送 GitHub。

## 验收标准

- 文件预览打开时按 Escape 关闭预览，不暂停正在生成的回复。
- 文件预览内有菜单时，第一次 Escape 只关闭菜单。
- 本机终端打开时按 Escape 关闭终端，不暂停聊天回复。
- 浮层关闭且没有其他快捷键面板时，Escape 仍可中断回复。
- 前端生产构建成功，`git diff --check` 无输出。
