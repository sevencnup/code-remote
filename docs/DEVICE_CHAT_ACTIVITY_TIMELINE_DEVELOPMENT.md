# 设备群聊执行过程同步开发文档

## 目标与分类

群聊中的 Codex 回复展示普通聊天已有的运行状态、思考摘要、操作记录和文件变化；本机绑定聊天在普通模式产生的后续活动也同步到群里。其他设备可看到活动归属和文本信息，不误用本机文件预览读取远端路径。跨设备查看执行过程扩展了群聊原有能力，属于新增功能 / MINOR，目标版本 `0.72.0-dev.1`。

## 实施步骤

1. 核对普通聊天的活动数据格式、Codex 通知、群消息存储和中继链路，确定可序列化的活动快照与更新方式。
2. 在群任务执行与绑定聊天同步路径发布结构化活动及运行状态，控制单条消息大小，保留重连后的历史，保证增量更新不会重复生成消息。
3. 群聊消息使用普通聊天的活动展示组件。标记活动来源设备；远端路径只展示，不调用本机文件预览。保持本机原有文件预览能力。
4. 增加覆盖群任务、绑定聊天、远端中继及历史恢复的测试；运行前端构建和相关回归。
5. 更新版本名与简短版本记录，检查差异并本地提交。按既有 Gitea 授权推送；对正在承载会话的服务只安排当前会话结束后的安全更新，并验证实际在线版本。

## 验收

- 群任务执行时，发送端和其他在线设备都能看到运行中状态、思考摘要、操作记录及文件变化；刷新后仍保留已完成活动。
- 本机绑定的普通聊天产生后续回复时，相应活动同步进群；文字和活动更新不会生成重复群消息。
- 远端文件只显示来源与改动信息；不会被误当成本机文件打开。

## 验证结果

- 群任务流式活动、绑定普通聊天活动及跨设备中继回归通过；相关后端测试共 49 项通过。
- TypeScript 检查、Web 生产构建与 `git diff --check` 通过。
- 远端活动的文件路径只读展示，命令摘要截断并隐藏常见凭证参数；活动快照限制大小，更新沿用同一群消息编号。
- Android 只更新 `versionName`，未生成安装包，`versionCode` 未变。
