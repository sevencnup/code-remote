# 多格式文件附件开发文档

## 目标

让聊天输入框可以附加常见文档、表格、演示文稿、文本/数据文件和源码文件。浏览器在本地提取文本，再沿用现有文档附件通道将文件名和文本交给 Codex；图片继续沿用现有图片通道。

## 支持范围

- 图片：PNG、JPEG、WebP、GIF，保持现有模型能力检查、单张 8 MB、每轮最多 4 张限制。
- 文档：PDF、DOCX/DOCM、XLSX/XLS/XLSM、PPTX/PPTM、Office 模板、ODT/ODS/ODP 及扁平 XML 版本、RTF。
- 文本与数据：TXT、Markdown、CSV/TSV、JSON/JSON5/JSONL、XML/HTML、CSS、YAML、TOML、INI、日志、常见配置和多种编程语言源码。
- 旧版二进制 DOC/PPT、加密/受密码保护的文档、任意未知二进制文件不承诺支持，解析失败时给出明确错误，不把乱码当正文发送。

解析结果是纯文本，不保留 Office 排版、公式计算能力、嵌入对象或 PDF 页面布局；表格以行列文本表示。原文件二进制不上传给 Codex。

## 安全与资源限制

- 单文件上限 20 MB；每条消息最多 8 个文档附件。
- 全部文档提取文本合计最多 120,000 字符，单文件最多 40,000 字符；超限时截断并明确标记。
- 检查实际内容是否为可解析文本/预期格式，不以扩展名作为唯一验证。
- PDF/ZIP/XML 解析失败、加密文档、空文本文档提供可理解的错误。

## 实施步骤

1. 使用项目所属 pnpm workspace 管理 PDF、Office/ZIP 解析依赖。
2. 新增可单独测试的文件分类和文本提取模块，覆盖普通文本、Excel 容器和失败/上限场景。
3. 扩展输入框文件选择器，保留图片的原发送行为，并展示/移除文档附件。
4. 更新产品开发文档和 CHANGELOG 版本记录。
5. 执行测试、生产构建和 diff 检查，创建本地 Git 提交；除非收到明确要求，不推送远端。

## 验收标准

- 可以从桌面和移动端文件选择器附加支持范围内的常见格式。
- 图片与文档均可单独或和文字一起发送；图片能力限制不影响文档附件。
- 不支持的格式、过大文件、超数量、加密或无法提取正文的文件有清楚反馈。
- 提取的文件名和文本沿用现有消息/队列持久化路径。
- pnpm 测试和生产构建通过。
