# 输入框稳定性开发文档

## 目标

让移动端和桌面端在 Codex 流式回复、网络短暂重连和中文输入法组合输入期间，始终可以连续编辑草稿；只有用户明确发送时才清空输入内容。

## 根因

- 输入框随连接状态被禁用，WebSocket 重连会直接打断正在输入的内容和输入法候选状态。
- 中文输入法用 Enter 确认候选词时，现有快捷发送逻辑可能误把它当成发送。
- 草稿状态放在聊天页面根组件；每输入一个字都会重绘消息流，并同步写入浏览器存储，长回复时容易造成输入卡顿。
- 异步发送或新建会话结束后强制聚焦输入框，可能抢走用户正在操作的焦点。
- 浏览器整页刷新会清除 textarea 的焦点和光标位置，即使草稿已从本地存储恢复。

## 实施步骤

1. 将输入区拆为记忆化的独立组件，使流式消息和活动状态更新不重绘输入 DOM。
2. 在输入区内维护草稿、附件和高度，并将草稿存储改为防抖写入，页面隐藏或组件卸载时立即落盘。
3. 增加 composition 保护：输入法组合期间的 Enter 不发送，也不触发全局 Esc 中断。
4. 断线或加载历史时保留可编辑输入框；仅禁用发送、附件和参数选择，并移除异步完成后的强制聚焦。
5. 仅在整页刷新前输入框确实持有焦点时，短暂保存草稿作用域和选区位置；刷新后恢复同一输入框的焦点与光标，不在普通新开页面时主动弹出键盘。
6. 更新版本记录，执行前端构建、后端测试和差异检查后创建本地 Git 提交。

## 验收标准

- 中文输入法按 Enter 选词不会发送、清空或丢失草稿。
- Codex 回复、历史恢复或连接重连期间可以持续输入；网络恢复后草稿仍在。
- 长聊天流式更新时，输入区不因消息更新重新渲染。
- 刷新前输入框有焦点时，刷新后恢复焦点和光标/选区；刷新前焦点不在输入框时，不自动抢焦点。
- `pnpm build`、后端单元测试和 `git diff --check` 均成功。
