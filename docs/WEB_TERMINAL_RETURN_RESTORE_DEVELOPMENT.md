# 网页终端切换页面后恢复

本次属于**修复 / PATCH**：终端原有任务不变，修正切换网页、设置页或浏览器标签后，终端窗口关闭和已有显示内容消失的问题。目标版本 `0.83.2-dev.1`。

## 原因与范围

- 聊天页在显示设置页等内容时会卸载 `RemoteChatPane`，其局部 `terminalOpen` 状态丢失。浏览器重新载入后同样从关闭状态开始。
- `TerminalDialog` 每次挂载或手动重连都新建 xterm 实例，旧滚屏只存在于被销毁的实例里。服务端 tmux 保留 shell，但重新附着主要重绘当前屏幕，不恢复浏览器之前的完整滚屏。
- 浏览器标签从后台返回时没有主动刷新 xterm 画面；WebSocket 已断开时也没有自动重连。

## 实施步骤

1. 将每个并发窗口的终端打开状态按聊天 ID 保存在当前浏览器标签的会话存储中；切回聊天页或标签恢复后自动重新打开。用户主动关闭时清除打开标记。
2. 在终端卸载、页面进入后台时保存同一聊天最近的文字画面及有限滚屏；重新挂载时先恢复画面，再接收 tmux 的实时重绘。缓存只保留有限条目与时长，避免串到其他聊天或显示已结束的旧会话。
3. 浏览器标签回到前台时刷新终端尺寸和画面；连接已关闭时自动重连。恢复操作不得向 shell 发送输入。
4. 更新版本号及简短更新记录，构建网页并检查差异后本地提交；不新增或运行测试，不推送 GitHub。

## 边界

- 仅有聊天 ID 的 tmux 终端可以接回原 shell。文件树“终端运行”创建的隔离临时终端、没有聊天 ID 的终端以及 Windows 临时终端仍随连接结束，不能伪装为原会话。
- 画面缓存位于当前浏览器标签的 `sessionStorage`，只保留最近文字内容；交互程序的复杂彩色布局以 tmux 重新附着后的画面为准。

- 已保存有限文字滚屏，在重新挂载时先恢复画面；标签返回时刷新画面，连接断开时重新附着。
