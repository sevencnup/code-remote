# 流式回复合并开发文档

## 目标

保证同一个 Codex turn 在流式输出、断线恢复或历史重读期间始终只显示一个助手消息气泡，不把已生成的 `commentary` 片段和正在流式生成的 `final` 片段拆成上下两个模块。

## 已确认原因

- Codex 可以在一个 turn 内发送多个 `agentMessage` item，例如 `commentary` 和最终回复。
- 页面在回复进行时执行 `thread/read` 时，历史接口会先返回其中已完成的消息；旧逻辑把它直接替换到消息列表中。
- 随后 WebSocket 的流式消息又以本地临时 ID 新建气泡，导致同一段前缀同时出现在历史气泡和流式气泡中。

## 实施步骤

1. 为当前流式 turn 使用固定的助手消息 ID，并在历史读取发生在运行中时复用该 ID。
2. 将同一 turn 的历史助手消息、本地流式内容按文本重叠部分合并，移除重复的助手气泡。
3. 对同一 turn 的多个 `agentMessage` 保留空行分段，与正常历史恢复的展示一致。
4. 保持用户消息、不同 turn 和完成后的正式历史刷新不受影响。
5. 更新版本记录，执行构建、后端测试和差异检查后创建本地 Git 提交。

## 验收标准

- Codex 回复中即使触发 `thread/read` 或连接恢复，也只显示一个正在更新的助手气泡。
- 已收到的回复前缀不会在新气泡中重复出现。
- `commentary` 与最终内容仍在同一气泡中以段落分隔。
- 回复结束后历史消息显示和复制操作正常。
- `pnpm build`、后端单元测试和 `git diff --check` 均通过。
