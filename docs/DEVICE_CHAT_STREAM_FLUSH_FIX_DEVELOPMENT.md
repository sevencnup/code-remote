# 设备群聊流式正文卡住修复

## 问题与分类

普通聊天已输出完整段落，群聊仍可能只显示首字。群聊发送端目前仅在下一个文字增量到来时检查节流窗口；短段落在 350 ms 内结束、随后执行工具时，剩余正文只能等到下一段文字或整轮结束才发送。此外，群聊未用 `item/completed` 的完整正文校正增量内容。

本次属于修复 / PATCH：恢复已有群聊的实时同步能力，不增加新的用户任务。版本从 `0.70.0-dev.1` 递增至 `0.70.1-dev.1`。

## 方案约定

- 保留首段增量立即发送，未发送正文在 350 ms 窗口到期后补发；即使后续只有工具事件或没有新事件，也不能等待整轮结束。
- 在现有订阅循环中按刷新截止时间等待通知，不创建额外常驻刷新任务；正常完成、异常和取消时都释放订阅。
- 按 agentMessage 的 item ID 汇总正文，完整 item 覆盖同一 item 的增量；不同段落之间保留空行，避免正文重复或粘连。
- `item/completed` 立即补齐该段落；`turn/completed` 携带的正文也参与最终校正。忽略其他 thread / turn 的消息。
- 所有中间正文只用于显示。仅整轮完成后设置自动接力元数据，继续使用现有去重与接力上限。
- 复用现有群聊展示、消息 cursor 与设备传输，不另建聊天页面。

## 实施步骤

1. 增加可控制通知时间的 Codex 测试替身，复现首字发布后短段落结束、工具继续运行而群聊正文未更新的问题，确认现有代码失败。
2. 修复节流尾部补发，处理完整 agentMessage 与整轮完成正文，保持接力时机和订阅清理。
3. 验证无新文字、持续工具通知、完整 item 校正、多段正文、其他会话隔离、整轮完成才接力及取消后无残留更新。
4. 更新 `package.json`、服务版本、Android `versionName` 与 `CHANGELOG.md`；不打安装包，不修改 Android `versionCode`。
5. 使用现有 Python 虚拟环境运行群聊回归测试；使用现有 workspace 依赖构建前端，执行 `git diff --check`。
6. 仅提交本次文件到本地仓库，沿用用户此前授权推送 Gitea。Linux 如仍有运行中的对话，使用已有空闲重启脚本安排自动激活，并在激活后检查健康状态和运行版本。Windows 发送端也需更新并重启后生效。

## 验收标准

- Codex 尚在执行工具、turn 尚未完成时，群聊已显示此前短段落的完整正文。
- 完整 item 可补齐缺失增量，多次完成通知不会重复正文，不同 item 按顺序分段展示。
- 持续工具通知不会推迟正文补发，其他 thread / turn 的事件不会混入当前回复。
- 中间正文中的 `@设备` 不提前交接，完成后的接力仍只执行一次；取消后释放订阅且不继续发布。
