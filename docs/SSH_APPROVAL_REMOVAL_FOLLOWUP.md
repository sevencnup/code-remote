# 清理移除 SSH 后遗留的授权卡片

本次属于**修复 / PATCH**：补齐上一轮移除 SSH 功能时漏清理的 `ssh-mcp`、`ssh_mcp` 授权名称，修正无授权时仍显示设置卡片的情况。目标版本 `0.86.1-dev.1`。

## 问题

- 上一轮启动迁移只清理 `code_remote_ssh`，截图中的授权实际属于 `ssh-mcp`，因此仍显示在设置页。
- 通用 MCP 授权卡片即使没有保存的授权也会显示，造成 SSH 功能仍未删除的观感。

## 实施步骤

1. 扩展旧 SSH 授权清理范围，覆盖内置名称和已出现的 SSH MCP 名称，保留其它工具授权。
2. 设置页在没有授权时不显示 MCP 自动批准卡片，加载期间也不闪现空卡片；读取失败时继续显示错误，并清理设置页残留的远程服务器说明。
3. 通过现有清理迁移即时撤销当前服务数据目录中的残留 SSH 授权，不读取保存的密码、密钥或配对令牌。
4. 更新版本及简短版本记录，检查清理范围和卡片显示逻辑，完成网页构建；本轮未要求测试，不新增或运行测试。
5. 本地提交本次修改，安排当前回合结束后的后端更新，并确认网页构建和残留授权状态。

## 验收条件

- `code_remote_ssh`、`code-remote-ssh`、`ssh-mcp`、`ssh_mcp` 的历史授权被清理。
- 没有其它 MCP 授权时，设置页不出现截图中的卡片。
- 其它 MCP 工具授权及其撤销能力继续工作。
