# 中断后续发消息状态开发文档

## 目标

用户点击停止后立即发送下一条消息时，上一轮回复应立刻结束显示，新消息必须拥有清晰的消息边界；旧轮次的延迟完成通知不能清空或中断已经开始的新轮次。

## 根因

- 前端只用一个全局流式回复缓存，停止请求成功到 `turn/completed` 通知到达之间，旧回复仍显示为生成中。
- 停止状态只按 thread 记录，没有绑定被停止的 turn；新 turn 的 `turn/started` 可能被误判为仍需停止。
- `turn/completed` 当前无条件清空运行状态和所有流式消息，旧 turn 的延迟通知可能覆盖新 turn 的状态。

## 实施步骤

1. 为流式回复和停止意图记录对应的 turn ID。
2. 停止请求成功后立即封存对应旧回复，但保留运行锁直到服务端完成通知到达。
3. 新 turn 开始前封存旧 turn；完成通知只更新对应 turn，不得清空其他正在运行的 turn。
4. 更新版本记录，执行前端构建、现有 Node/Python 测试和差异检查，并创建本地 Git 提交。

## 验收标准

- 停止后旧回复立即移除生成中状态，下一条消息与旧回复清晰分隔。
- 停止旧 turn 后新 turn 不会被自动再次中断。
- 旧 turn 的延迟 `turn/completed` 通知不会把新 turn 标记为完成或清空新回复。
- `pnpm build`、`pnpm test`、后端单元测试和 `git diff --check` 均成功。
