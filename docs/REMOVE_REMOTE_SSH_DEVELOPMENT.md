# 移除内置远程 SSH 功能

本次属于**不兼容变更**：删除设置页服务器配置、内置 SSH MCP 工具及操作记录接口。项目处于 `0.x` 阶段，按项目约定递增中版本，目标版本 `0.86.0-dev.1`。

## 问题与目标

- 内置 SSH 功能为每个 Codex 会话和 Claude 回合注入远程工具，容易让本机操作转向 SSH。
- 为隔离保存的 SSH 凭据增加的 bubblewrap 启动包装隐藏了宿主机 `/run`，使本机 Docker socket 和服务管理接口不可见。移除该功能时一并恢复 AI 进程的原有本机启动方式。
- 系统 SSH 客户端、用户自行配置的 MCP 和通用 MCP 审批机制保留；旧版开发文档作为历史记录保留。

## 实施步骤

1. 删除后端 SSH 配置、连接检查、指纹确认与操作记录 API，停止创建 SSH 存储、代理和专用隔离包装。
2. 清理 Codex、Claude 的 SSH MCP 配置注入、回合日志关联和隔离包装；删除专用模块及 Paramiko 依赖声明。
3. 删除网页设置卡片、SSH 操作日志轮询与展示、客户端 API 和相关样式；通用 MCP 审批卡片移除 SSH 提示并使用独立样式名称。
4. 检查已有会话的配置恢复路径，保证旧 SSH 注入不会因恢复会话重新启用。启动时清理本功能专用的服务器配置、保存凭据、代理文件和操作日志，并撤销内置 SSH MCP 的持久授权；直接删除专用文件，不读取保存的凭据，不改动系统 SSH 密钥和配置。
5. 更新版本和简短版本记录，运行相关现有检查和构建，记录结果。
6. 仅暂存本次文件并在本地提交。当前旧 AI 进程仍在隔离环境中，宿主机服务管理接口不可见；通过已配置的宿主机管理连接，安排现有空闲重启脚本在当前回合完成后激活更新。

## 验收条件

- 设置页没有内置 SSH 配置入口，网页不再请求 SSH 操作记录。
- Codex 和 Claude 的新启动命令没有专用 bubblewrap 包装，聊天启动及恢复不再启用内置 SSH MCP。
- 后端不再注册 SSH API，不依赖 SSH 专用模块或 Paramiko。
- 通用 MCP 审批和原有聊天、本机终端能力继续正常工作。

## 完成记录

- 已移除网页设置入口、客户端 SSH API、操作记录轮询及展示、后端 SSH 路由、工具注入、专用代理与 bubblewrap 包装，删除 Paramiko 依赖声明。
- Codex 启动和恢复请求原先只在内存中注入 SSH MCP 配置，没有写入全局 MCP 配置；移除注入后，后端重启后的会话使用正常配置。Claude 新回合和历史恢复同样不再传入内置 SSH 配置。
- 启动清理迁移只删除此功能专用文件，并撤销 `code_remote_ssh` 的持久授权；已验证重复运行、目录符号链接及保留其它 MCP 授权。
- 后端相关回归两组分别 88 项、78 项全部通过（160 个不同用例）；TypeScript 编译、Vite 构建及差异检查通过。
- 前端客户端检查通过。额外运行的界面静态检查有 5 项原有失败；在临时目录对比修改前提交与当前文件，失败用例完全一致，临时目录已清理。
- 版本更新为 `0.86.0-dev.1`，不构建 Android 安装包，Android `versionCode` 保持原值。

## 激活方式

- 已核对宿主机 `pveubuntu` 的源码版本、`codex-remote.service` 单元、主进程及当前活动回合数。
- 使用项目现有 `scripts/restart-codex-remote-when-idle.py`，由独立临时 systemd 服务等待活动回合结束；重启前复查原服务 PID，重启后检查 `/health`，超时 30 分钟退出。
- 此激活通道用于处理仍在旧隔离环境中的当前进程。更新后的 AI 进程直接在本机启动。
