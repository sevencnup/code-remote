# 移动端原生附件选择器开发文档

## 目标

缩短移动端打开系统附件选择器的等待时间，并从单个入口选择图片、文档或源码文件。

## 方案

- 将可见附件图标作为透明原生 file input 的点击区域，确保选择器由用户手势直接触发。
- 移动端 accept 范围包含 PNG、JPEG、WebP、GIF 及文档附件模块支持的格式；网页按类型继续调用现有图片或文档处理流程。
- Android WebView 使用 `FileChooserParams.createIntent()` 创建系统选择器，遵循网页传入的 accept 类型并保留多选。

## 实施步骤

1. 将 file input 放在附件图标控件内，使用透明覆盖层保持原有图标外观。
2. 合并移动端图片和文档 accept 范围，并分流到现有附件处理流程。
3. Android WebView 根据网页选择器参数创建多选系统文件选择器。
4. 更新版本记录，执行生产构建和差异检查，并创建本地 Git 提交。

## 验收标准

- 手机点击附件图标直接唤起系统文件选择器。
- 同一移动端入口可多选支持的图片和文档。
- 图片预览、删除和发送流程保持不变，文档和 PDF 沿用现有解析/上传流程。
- 图片模型能力限制不影响文档附件。
- 桌面端仍可选择支持的文档和源码文件。
