# 移动端原生图片选择器开发文档

## 目标

缩短移动端点击图片附件按钮后打开系统图片选择器的等待时间，并保证选择器由用户的原生点击手势直接触发。

## 根因与方案

当前页面将文件 input 设为 `display: none`，再通过按钮的 JavaScript `.click()` 间接触发。移动浏览器会把这类隐藏控件的间接调用放入更严格的手势与安全校验路径，可能表现为明显延迟。

将附件图标改为可见控件区域内的透明原生 file input。用户手指直接命中 input，浏览器可以立刻打开系统选择器；选完后仍沿用既有类型、数量、大小校验和预览流程。

## 实施步骤

1. 移除隐藏 input 的 ref 和程序化 `.click()` 调用。
2. 将 file input 放在附件图标控件内，使用透明覆盖层保持原有图标外观。
3. 保持禁用态、键盘焦点、模型图片能力检查和移动端布局。
4. 更新版本记录，执行生产构建和差异检查，并创建本地 Git 提交。

## 验收标准

- 手机点击图片图标直接唤起系统选择器，不经过异步 JavaScript 点击。
- 桌面端仍可选择多张 PNG、JPEG、WebP、GIF 图片。
- 无法发送、模型不支持图片时附件控件不可用。
- 图片选择后的预览、删除和发送流程保持不变。
- `pnpm --filter codex-remote build` 成功，`git diff --check` 无输出。
