# Android Kotlin 原生移动端开发计划

## 目标与分类

以手机浏览器移动端为视觉和交互基准，使用 Kotlin 原生 Android 界面重做 APP。APP 不加载 React 页面，不用 WebView 绘制聊天输入框；消息输入采用 Android 原生控件，由系统输入法直接处理。本次保持用户现有任务能力，主要解决 APP 输入、页面体验和同步流量问题，归类为 PATCH，目标版本 `0.18.1-dev.2`，Android `versionCode` 为 `133`。

## 架构边界

- 使用 Kotlin Android Activity 和原生 View 构建界面；遵循浏览器手机端的内容顺序、模块宽度、字号、控件高度和紧凑间距，不自行放大卡片或增加留白。
- 复用现有 Codex Remote HTTP API、WebSocket 协议和配对流程，不复制或修改服务端业务逻辑。
- 使用原生输入框与 `adjustResize` 处理系统 IME；没有 WebView 键盘高度预测、JS 视口桥接或强制弹键盘逻辑。
- 浏览器移动端是对照基准，不作为 APP 的界面运行时。

## 功能验收范围

- 地址配对、已保存地址重连、连接状态、错误重试和网络恢复。
- Codex / Claude 模式、聊天列表搜索、当前聊天切换、新建、命名、删除、固定、聊天内容和流式回复。
- 模型、思考等级、权限设置；发送、暂停、继续、审批和跨设备状态同步。
- 排队消息的展开、编辑、删除、任意项立即发送和队列状态同步。
- 图片和文件附件、文件树浏览、预览、创建、重命名、删除、复制、剪切和粘贴。
- 终端会话、输入、方向键、复制粘贴和终端记忆。
- 操作记录、已编辑文件、通知及通知跳转、主题与字号设置、系统剪贴板、系统返回和系统栏。

## 实施步骤

1. 核对现有 REST、WebSocket、Codex / Claude 接口及认证协议，确保原生客户端能覆盖网页已有功能。
2. 将 Android 工程切换为 Kotlin；实现 API / WebSocket 客户端、配对与连接状态管理。
3. 按手机浏览器布局实现原生聊天页、导航、消息展示、流式状态、队列和原生输入区。
4. 实现工作区文件操作、预览、终端、通知、模式切换、权限和偏好设置。
5. 移除 WebView 宿主与 Android 专用网页键盘桥接；让原生输入法通过 Android 原生窗口布局工作。
6. 更新 Android、前端和服务端版本号与 CHANGELOG。
7. 构建 APK，使用新文件名保存；安装到当前连接的手机并保留应用数据。
8. 在手机上核对布局、原生键盘、消息往返、队列、文件、终端和通知等关键功能；不重启网页服务、不推送 GitHub。
9. 只提交本次相关修改，保留已有用户文件和历史 APK。

## 验收标准

- APP 页面由 Kotlin 原生控件绘制，不存在承载应用页面的 WebView。
- 手机端模块宽度、字号、间距和交互顺序紧凑贴近浏览器移动端，不出现额外宽大卡片或松散间距。
- 输入框获得焦点后由 Android 系统输入法直接服务原生编辑控件，页面稳定响应原生窗口的键盘布局变化。
- 本节列出的现有功能可通过 APP 继续使用，已保存的配对地址和用户数据在覆盖安装后保留。
