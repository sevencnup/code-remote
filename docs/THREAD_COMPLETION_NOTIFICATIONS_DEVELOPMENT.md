# 会话完成通知开发文档

## 目标

当用户同时打开多个 Codex 对话时，后台会话的回复完成后应提供明确提示：

- 侧边栏对应会话显示绿色完成点。
- 页面顶部弹出该会话已完成的提示，点击可直接打开该会话。

## 实施步骤

1. 保留非当前会话的 `turn/started` 和 `turn/completed` 通知，而不是直接忽略。
2. 在前端维护本次页面会话内的“未查看完成会话”集合及最新完成事件。
3. 新一轮开始或用户打开该会话时清除其完成标记；当前正在查看的会话完成时不重复提醒。
4. 在侧边栏增加绿色状态点，并在主界面顶部增加自动消失、可点击跳转的完成提示。
5. 更新版本记录，执行前端构建、后端测试和差异检查后创建本地提交。

## 验收标准

- 切换到会话 B 后，会话 A 完成回复会显示绿色点和顶部提示。
- 点击提示或侧边栏中的会话 A 会打开 A 并清除其绿色点。
- 会话 A 再次开始回复时，旧的完成提示不会保留。
- 正在查看的会话完成时不会产生无意义的跨会话通知。

## 跨模式来源图标与点击刷新修复

### 目标与分类

跨模式会话完成提示显示实际完成回复的 Codex 或 Claude Code 官方图标；点击提示后打开对应模式和会话，并读取包含最新 AI 回复的权威历史。本次属于 PATCH，目标版本为 `0.16.0-dev.9`。

### 根因

- 完成事件只保存会话 ID 和完成时间，提示组件不知道来源模式，只能显示通用对勾。
- 后台会话完成时会异步刷新列表，但提示可以更早出现。用户立即点击时，目标会话的旧缓存可能仍被元数据规则判为可用，选择逻辑因此跳过历史读取，导致最新 AI 回复不显示。
- 目标会话已经位于另一个并行窗口时，点击提示只切换窗口，也不会主动核对最终历史。

### 实施步骤

1. 在完成事件中保存来源引擎；优先取会话元数据，缺失时按会话 ID 规则识别。
2. 提示窗使用对应引擎的官方品牌图标，并在副标题中标明 Codex 或 Claude Code。
3. 为会话选择增加“强制刷新历史”选项：保留旧缓存作为即时画面，但不能用缓存新鲜度提前结束，随后只发起一次权威历史读取。
4. 点击完成提示时启用强制刷新；目标已在其他并行窗口中时也刷新该窗口。
5. 更新版本记录并构建网页资源；不新增或运行测试，不重启服务，不生成 APK。
6. 检查差异并创建本地 Git 提交，不推送 GitHub，保留用户已有的 Android 开发文档修改。

### 验收标准

- Claude Code 页面收到 Codex 完成提示时显示 Codex 图标和名称，反向场景显示 Claude Code 图标和名称。
- 点击提示会切到完成会话所属模式，不会留在原模式。
- 点击后能看到刚完成的 AI 回复；已有旧内容时先保留画面，再由一次历史请求更新。
- 完成会话已在其他并行窗口时，点击会选中该窗口并刷新最终回复。

### 完成记录

- 完成事件已携带来源引擎，顶部提示改用对应的 Codex 或 Claude Code 品牌图标，并显示模式名称。
- 完成提示点击路径已启用权威历史刷新；旧缓存可先显示，但不能再阻止最终回复读取。目标已在并行窗口中时同样刷新。
- Web、服务端及 Android `versionName` 已同步为 `0.16.0-dev.9`；本次没有 Android 原生改动，不生成 APK，`versionCode` 保持 `128`。
- TypeScript 与 Vite 生产构建通过；未新增或运行测试，跨模式完成事件仍需在实际双模式回复场景中观察。
