# Android 原生界面一致性与终端修复记录

## 目标

统一 Android 原生客户端仍沿用系统默认样式或临时样式的界面，修复右侧文件树侧滑卡顿和终端空白，并让操作记录、最近编辑文件及各类菜单接近网页版的信息结构与密度。

## 修改分类与版本

- 分类：修复 / 体验优化（PATCH）。
- 理由：本轮修正和统一已有功能的交互、布局、视觉与稳定性，没有增加新的用户任务能力。
- 目标版本：`0.19.0-dev.13`，Android `versionCode` 递增至 `158`。

## 实施步骤

1. 检查 Android 原生页面的系统栏、主页面、抽屉和弹层布局，取消文件树顶部与底部的额外留白，使面板占满可用区域。
2. 分析文件树拖动期间的主线程工作和绘制层级，减少手势过程中的布局、遮罩和视图刷新。
3. 对照网页版重组操作记录：默认保持简洁，展开后按操作项分行展示；把最近编辑文件作为独立模块展示并支持打开文件。
4. 压缩模型、思考等级和权限菜单的标题、行高与内边距。
5. 统一应用内图标为简约线性风格，覆盖顶部、侧栏、文件树、设置、重连及常用操作入口。
6. 把聊天操作、文件操作、创建、重命名、删除和重新配对等系统列表或对话框替换为统一主题组件。
7. 排查终端连接和输出渲染链路，修复打开后一片空白并提供清晰的连接或错误状态。
8. 全局扫描仍使用系统默认 UI 的入口，完成同类组件的样式收口。
9. 构建新 APK，保留历史安装包，安装到设备核对主要页面和版本信息。

## 终端链路修复补充

- 终端空白同时受到 EasyTier 文件描述符耗尽影响：服务原先达到 `1024/1024`，其中 socket 为 `1016`，日志提示 `No file descriptors available`。
- 已为 EasyTier systemd 服务设置 `LimitNOFILE=65536` 并只重启 EasyTier。恢复后文件描述符降至 `37`，手机 HTTP 与终端 WebSocket 均恢复。
- 该限制修复恢复了当前链路；仍需在长期运行后观察 socket 数量，确认是否存在持续泄漏。

## `.dev.14` 至 `.dev.17` 长对话性能与界面修正

用户在长对话中复验后发现，操作记录展开约需 3 秒，文件树侧滑和其他操作仍有卡顿；同时发送按钮偏大、最近编辑文件缺少网页版卡片边框，重连图标来源不统一。本轮继续按 PATCH / 体验优化处理。`.dev.14` 至 `.dev.16` 为真机性能复测包；根据抓帧结果继续减少历史视图、缓存图片、撤销会触发整页纹理上传的聊天页硬件图层，并把后台同步改为只替换发生变化的最后一轮，最终版本为 `.dev.17`，Android `versionCode` 为 `162`。

### 实施步骤

1. 操作记录展开时只更新当前记录的详情视图，禁止重建整个聊天列表。
2. 长对话默认渲染最近 12 轮，并提供加载更早内容的入口，减少常驻 View 数量。
3. 合并高频聊天刷新事件，侧栏显示和移动期间暂停后台聊天重绘，缓存已解码的聊天图片；增量同步只替换发生变化的最后一轮。
4. 缩小发送按钮，为最近编辑文件增加卡片背景与边框。
5. 将重连入口替换为 Google Material Icons 的 `sync` 图标。
6. 构建新 APK，安装到真机后复测操作记录展开、左右侧栏、长对话滚动和终端。

### 验收记录

- [x] 操作记录展开不再触发整个聊天列表重建。真机连续展开和收起 6 次，50/99 分位为 `11ms / 42ms`，没有再次出现秒级停顿。
- [x] 长对话默认只挂载最近 12 轮，旧内容可继续加载；后台增量同步只替换最后一轮。右侧文件树预热后连续开关 5 轮，50/95 分位为 `6ms / 11ms`，没有超过 `85ms` 的帧。

## `.dev.18` 至 `.dev.19` 长对话内存、连接与消息区交互修正

用户继续复验发现，长对话会引发 Android 进程持续 Full GC，进而造成侧栏首帧卡顿、WebSocket 心跳超时和文件预览回调迟滞；同时思考状态图标、键盘弹出后的消息区、侧栏对话行、对话菜单和最近编辑文件仍未达到网页版的交互预期。本轮继续按 PATCH / 体验优化处理。`.dev.18` 用于首轮真机核对，随后继续移除长回复合并时的重复字符串拼接；最终目标版本为 `0.19.0-dev.19`，Android `versionCode` 为 `164`。

### 实施步骤

1. 移除聊天增量合并、渲染和缓存写入中的整棵 JSON 深复制；在序列化缓存前先做有上限的大小扫描，并拒绝缓存异常大的内嵌数据。
2. 限制聊天内嵌图片的 Base64 解码规模，并使用尺寸采样，避免大图一次性挤满 Android 堆。
3. 将“正在思考”静态图标替换为原生不定进度动画；键盘出现时保持消息底部锚定，让消息视口与输入区一起缩放。
4. 增强 WebSocket 保活和前台恢复时的陈旧连接识别，缩短半开连接的恢复时间。
5. 移除侧栏聊天标题下面的预览小字，统一对话菜单的顺序和名称，并减少长列表的常驻视图数量。
6. 让最近编辑文件默认折叠且可局部展开；按当前聊天工作目录规范化预览路径，增加加载、错误和重试界面。
7. 构建新 APK，保留历史安装包，覆盖安装到当前设备并核对内存、连接、键盘、侧栏、折叠和文件预览。

### 验收记录

- [x] “正在思考”使用 Android 原生不定进度动画；键盘打开时聊天视口底部由 `1992px` 调整至 `1225px`，最近编辑卡片和思考状态均保持在输入框上方。

- [x] 侧栏聊天为单行标题，对话菜单按“打开、置顶/取消置顶、重命名、删除聊天”展示。

## `.dev.20` 聊天首屏与文件工作区一致性修正

用户复验发现，原生 APP 打开长聊天仍比网页版套壳慢；文件树仍使用单一图标、点击文件夹会替换当前目录，长按菜单也缺少网页版操作；最近编辑文件会等待完整文件下载，随后展示全文且没有差异底色和代码高亮。本轮继续按 PATCH / 修复与体验优化处理：这些能力均已存在，本轮恢复其预期行为并改善加载速度，不增加新的用户任务。目标版本为 `0.19.0-dev.20`，Android `versionCode` 为 `165`。

### 实施步骤

1. 让 Android 历史请求使用不内嵌图片数据的轻量响应，保留图片路径并按需加载，恢复长聊天的本地缓存和快速首屏。
2. 将原生文件树改为目录内原地展开和收起，缓存已读取的子目录，并在普通预览关闭后保留展开位置。
3. 按常见文件类型显示不同图标和颜色；将文件与目录长按菜单的项目、顺序和操作与网页版对齐。
4. 在最近编辑数据中保留 unified diff，点击后直接展示修改片段，渲染新增与删除底色、行号和常见语言代码高亮，不再等待或展示整个文件。
5. 在真机逐项打开顶部入口、左右侧栏、输入菜单、聊天菜单、文件树菜单、普通文件/图片预览、最近编辑和终端，记录响应与异常。
6. 构建并保留新的 APK，覆盖安装到当前设备；完成静态检查、真机核对和本地 Git 提交。

## `.dev.21` 至 `.dev.22` 超长聊天首屏读取修正

真机复验确认 `.dev.20` 已缩小 Android 响应体，但服务端仍会先顺序解析整份 Codex JSONL，再截取最后 12 轮。当前最大会话文件已超过 530 MiB，因此首次打开仍会等待十余秒，且增量刷新会反复消耗磁盘与 CPU。本轮继续按 PATCH / 修复与体验优化处理：使用 Codex 自带的历史投影数据库直接读取最近轮次，并让部分历史的增量同步始终保持相同窗口；不改变用户可完成的任务。`.dev.22` 补齐真机验收时发现的普通文本预览语法着色缺口。最终目标版本为 `0.19.0-dev.22`，Android `versionCode` 为 `167`。

### 实施步骤

1. 为历史读取增加有界轮次参数，优先从 `thread_history_1.sqlite` 读取最近轮次、条目和总轮数；投影不可用或不同步时安全回退到现有 JSONL 解析。
2. 让 Android 部分历史的后续增量请求继续携带轮次窗口，避免每次同步重新解析和投影完整聊天。
3. 在浏览器负载中保留 `historyPartial` 与 `totalTurns`，并修正 Android 合并增量后丢失总轮数的问题。
4. 使用当前超长会话对轻量读取和完整读取做对比验证，再完成后端测试、Android 构建和真机复验。
5. 复验普通代码文件预览，确保 Gradle、Shell、JSONL 及常见语言使用语法着色。
6. 保留新的 APK，覆盖安装到当前设备，并只做本地 Git 提交。
