# Android 长会话滚动与计时卡顿修复

## 分类与版本

- 类型：修复 / PATCH。聊天记录和操作记录原本可查看；本次减少一次展开后同时创建的视图数量，并修复长会话卡顿导致计时跳秒。
- 目标版本：`0.56.3-dev.2`，Android `versionCode 319`。

## 已确认问题

- PJZ110 上“星会计”最近 12 轮缓存含 2,662 条活动记录，单轮含 2,350 条，其中包含 1,941 条命令执行记录。
- 操作记录的“查看其余”会一次性创建剩余全部行。展开长操作记录后，聊天 ScrollView 里会附着数千个 Android View；滚动和消息刷新会占满主线程。
- 正在思考计时器通过主线程 Handler 每秒刷新。主线程卡住时，回调延后执行，时间标签会一次跳过多秒。

## 实施步骤

1. 将操作记录的“查看其余”改为每次追加有限数量的记录，并显示剩余数量；保留逐步查看全部记录的能力。
2. 活动计时改用 `SystemClock.elapsedRealtime()` 计算，按秒边界安排下一次刷新，避免主线程短暂抖动累积成计时漂移。
3. 更新版本号和更新记录。
4. 编译 Android Debug 包，安装到已授权测试设备，复测“星会计”操作记录展开、滚动和计时表现，并查看 Choreographer 日志。
5. 检查差异并创建本地提交，不推送 GitHub。

## 验收标准

- 展开几千条操作记录时，首次最多创建 50 条记录；用户可以继续分批加载直到全部看完。
- 活动计时每秒正常前进；页面卡顿时仍可能延后显示，但恢复后按真实经过时间校准，不会累计变慢。
- 星会计会话的展开和反复滚动不再一次性创建数千个操作视图，设备日志不再出现接近秒级的连续跳帧。
