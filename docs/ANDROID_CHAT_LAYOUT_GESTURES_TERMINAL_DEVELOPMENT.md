# Android 聊天布局、侧滑与终端输入开发记录

## 目标与分类

修复原生 Android 客户端聊天内容越界、左右面板手势区域过窄、文件树返回层级、终端键盘遮挡和临时断网后重复配对问题；同时让同一轮内分段到达的 Codex 助手文本保持在同一条消息中。本次属于 PATCH / 修复与体验优化，不改变用户完成任务的能力，目标版本为 `0.18.1-dev.14`。

## 实施步骤

1. 将消息气泡宽度限制在实际聊天视口内，确保长代码行可在容器内换行，检查文本、图片和操作记录的左右边界。
2. 对照网页端历史映射规则，合并同一轮内连续的助手文本片段，同时保留用户消息及不同轮次的边界，避免把独立回复并成一条。
3. 将关闭状态的聊天手势区域按屏幕左右半区划分：左半区控制对话栏，右半区控制文件树；保留拖动跟手和纵向滚动保护。
4. 将文件树改为右侧抽屉；打开子目录时，系统返回和从左侧边缘开始的返回手势先回到父目录，根目录再关闭抽屉。
5. 检查终端原生输入框的可聚焦性、输入法显示、软键盘布局调整和 WebSocket 输入发送；用 Activity 根窗口的 IME 与状态栏 Insets 计算 Dialog 可用高度，以 Dialog Insets 的 IME 可见状态控制缩放和还原，避免 Dialog 自身 Insets 随尺寸变化造成高度振荡；键盘关闭和返回事件交错时保留一次性返回缓冲，确保首个返回先收键盘、下一个返回再关闭终端；连接未完成或断开时明确显示阶段和原因，并保留未发送的命令。
6. 将配对状态校验区分为令牌失效与临时连接错误。只有服务端明确返回 HTTP 401 才清除令牌；临时网络错误保留令牌并进入可自动重连的聊天页。
7. 递增 Android `versionName` 和 `versionCode`，构建独立命名的 APK；使用 `adb install -r` 覆盖同包名应用以保留已有配对和本机数据。

## 验收标准

- 聊天气泡、长代码行、图片和操作记录不会超出聊天视口。
- 同一轮中的多个助手文本片段显示为一条连续回复；不同用户轮次仍分别显示。
- 从左半区右滑可打开对话栏，从右半区左滑可打开文件树；滑动跟手，纵向滚动不触发面板。
- 文件树作为右侧抽屉显示；在子目录执行系统返回或侧滑返回时回到父目录，根目录返回才关闭抽屉。
- 终端输入框可调出系统键盘、编辑命令并发送，命令结果显示在终端区域。
- 服务暂时断开时不会再次要求匹配码；无效令牌仍会引导重新配对。
- Debug APK 构建成功，目标设备覆盖安装成功并保留应用数据；通过实际界面检查本轮主要交互，包括键盘打开时终端输入和发送控件完整显示、返回键先收起键盘。
- `git diff --check` 成功。
