# 持续下载与输入区菜单遮挡修复

## 目标与分类

修复远程页面仍持续下载大量数据、移动端输入区菜单被裁剪的问题。本次属于 PATCH：减少已有同步能力的流量并恢复菜单完整显示，版本使用 `0.8.0-dev.5`，Android `versionCode` 为 `112`。

## 已知问题

- 上次仅修改了前端历史读取触发条件。WebSocket 仍无筛选地发送 Codex 原始事件，历史接口也包含界面不使用的工具输出等内容。
- 本机 `4173` 目前运行 Vite 开发服务器；需要量化开发资源和正式构建的传输差异，并提供适合日常远程使用的启动方式。
- 输入区菜单是输入区内部的绝对定位元素，祖先容器的裁剪与层叠上下文可能遮挡菜单；移动键盘还会缩小可用视口。
- 上次元数据补同步逻辑仍需核查空页面、辅助聊天窗格与漏收完成通知时的行为。
- 侧栏摘要取首条消息，历史摘要取末条消息；把两者比较成内容版本会反复误判更新。

## 实施步骤

1. 只读取大小与结构，量化列表、历史和网页资源体积；确认运行入口及事件与界面字段的对应关系。
2. 在服务端 HTTP/WebSocket 边界移除界面不使用的工具输出、原始结果和重复轮次内容，保留正文、附件、审批、操作记录和文件差异；按需压缩 HTTP 响应并限制列表摘要大小。
3. 修正元数据刷新与完整读取的重复触发、辅助窗格和漏事件恢复问题；以消息指纹实现增量传输，客户端缺少完整基线时回退全量，确保可靠性校验仍可工作。
4. 增加使用正式构建的日常启动入口与缓存配置，保留明确的开发启动方式；根据手机实际连接地址确认生效范围。
5. 将输入区菜单移出裁剪容器，依照按钮和可视视口定位，支持键盘弹出、屏幕旋转、菜单内部滚动和外部点击关闭，并保持主题样式。
6. 完成代码审查和生产构建，记录已执行的检查及实际测量结果，明确尚未完成的手机端验证；更新版本及简短版本记录后创建本地提交。

## 验收要求

- 大型工具输出不再随未使用的实时事件或历史字段重复传输；消息、文件差异和审批信息完整。
- 无变化聊天不因其他聊天更新而重下整段历史；空页面仍能发现新会话，辅助窗格和断线恢复仍能补同步。
- 手机菜单可完整显示于可视区域，空间不足时可以滚动选择；明暗及自定义主题正确。
- 日常启动使用构建资源，具有适当缓存；不会为切换网页服务终止正在运行的 Codex 任务。
- 检查结果、本地提交和实际运行版本有明确记录；已有 `docs/ANDROID_APK_DEVELOPMENT.md` 改动保持独立。

## 实现记录

- HTTP 历史先裁掉界面未使用的工具结果及重复输出；正文、附件、操作记录所需信息、文件差异完整保留。列表只提供有限长度的摘要和必要元数据。HTTP 响应支持 gzip。
- WebSocket 只向浏览器发送界面消费的事件，移除命令输出流和完成通知中的重复历史。新客户端按当前聊天订阅详细事件；后台聊天仍有轻量的开始/结束通知，审批和送达回执保持完整。订阅协商兼容旧后端。
- `historyRevision` 使用历史文件的纳秒修改时间与大小，取值在读历史前完成；客户端不再比较首末消息摘要。相同请求跨聊天窗格合并，只复用正在进行的请求。
- 历史接口支持 `since`。服务端按轮次和消息指纹返回变动消息、顺序及删除信息，旧图片和差异不随未变的消息重发。客户端按 ID 重建完整历史，遇到缺失基线、无效顺序或重复 ID 时只回退一次全量读取。
- 服务端最多保留 32 组、总计 50,000 个指纹；客户端传输基线最多保留 5 个聊天、总计 8 Mi 个字符。基线被淘汰、服务重启或页面重新加载时允许全量回退；已有 IndexedDB 界面缓存仍会优先使用。此协议减少网络传输，服务端仍需读取并投影历史文件。
- 输入区菜单通过 portal 放到主题根容器下，使用 fixed 定位与可视视口尺寸；监听键盘导致的视口变化和滚动，空间不足时菜单自身滚动，保留外部点击和 Escape 关闭。
- `pnpm start` 构建后运行 Vite preview，带哈希的静态资源长期缓存，HTML 保持可更新。启动脚本无参数时也使用构建资源，兼容已安装的旧 systemd 启动命令；`pnpm dev` 显式选择开发模式。

## 已取得的结果

历史内容只统计体积和字段结构，不输出聊天正文。三份本地历史的紧凑 JSON 测量如下（字节）：

| 样本 | 原始历史 | 投影后的历史 | 投影后 gzip |
| --- | ---: | ---: | ---: |
| A | 73,141,988 | 4,420,753 | 1,688,438 |
| B | 47,217,582 | 3,420,255 | 1,617,596 |
| C | 120,662,602 | 358,329 | 62,838 |

仅字段投影减少了 92.76%–99.70% 的 JSON 体积；这些是本地历史样本的结果，不代表手机所有请求的固定降幅。增量传输是在此基础上避免重复发送未变的消息。

- 前一阶段已执行的前端检查 38 项、后端投影检查 7 项通过；它们发生在补充增量协议之前，不能视为增量协议的完整回归结论。
- 当前前端 TypeScript 与生产构建通过；产物包含菜单浮层和增量合并代码。
- 移动端真机菜单、键盘遮挡和真实网络流量尚待新运行版本上线后确认；本轮未重新执行自动化用例或启动临时浏览器服务。

## 运行版本与生效限制

现场 `/api` 后端 OpenAPI 版本仍为 `0.7.0-dev.1`，本机 `4173` 运行 Vite 开发服务，后端为 `127.0.0.1:18766`。本次修复版本为 `0.8.0-dev.5`，构建文件已准备。

当前命令的进程祖先就在 `codex-remote.service` 的 Codex 子进程内。该 unit 的 `KillMode=control-group` 会在重启时结束当前对话和它管理的其他任务。因此本次先完成代码及本地提交，不在处理当前对话时直接重启；待任务结束并确认切换后，服务重启会加载新后端与构建后的网页。仅刷新手机不能让旧 Python 进程加载本次修改。
