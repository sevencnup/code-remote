# 文件选区文档附件开发记录

## 目标

复用聊天输入框现有的长文本转文档附件流程，让文件预览中的代码选区以 Markdown 文档附件加入待发送消息，而不是把代码正文插入输入框。

## 交互与约束

- 右键菜单保留“复制选中内容”，将“插入引用到输入框”替换为“作为文档添加”。
- 文档正文包含绝对文件路径、选中的行号范围和代码块；生成 Markdown 附件并走现有附件数量/文本长度限制及发送流程。
- 只将附件加入当前草稿，不自动发送、不覆盖输入框已有文字；由用户按现有发送按钮发出。
- 附件命名需安全且能辨认来源文件和行号；内容通过现有文档附件管线处理，不新增上传机制。
- 保留文件树右键菜单、编辑器/预览选区处理与复制能力。

## 实施步骤

1. 查明长文本粘贴转换为附件时复用的文档构造、校验、错误提示和 Composer 暴露接口。
2. 给 Composer 增加受控的文档附件追加操作，复用现有状态和限制。
3. 将选区右键菜单动作改为生成并添加 Markdown 文档附件。
4. 补充文档构造及附件行为测试，运行前端测试、生产构建与差异检查。
5. 更新版本记录并创建本地提交；不推送 GitHub，除非收到明确命令。

## 验收标准

- 右键选区后，输入框正文不出现选中代码，Composer 中出现 Markdown 文件附件。
- 附件包含准确的绝对路径、行号与所选代码，且可以按现有方式随消息发送。
- 附件数量/内容限制正常生效，超限时有明确反馈且不丢草稿。
