# 工作区文件类型覆盖开发文档

## 目标

补齐工作区文件预览的语法着色覆盖范围，并让文件树、预览标题和文件操作入口按文件类型显示可辨认的图标。重点修复 `.sh`、`.jsonl` 等源码或配置文件显示为单色的问题。

## 设计

- 建立一份共享的文件名和扩展名识别表，高亮语言与图标类型都从同一份结果读取。
- 对常见脚本、编程语言、标记语言、配置文件和数据文件使用明确语法，不依赖容易失准的自动识别。
- 未登记但可能是源码的文本仍使用现有按需自动识别；日志、纯文本和表格文本继续保持纯文本。
- 文件图标使用轻量的内置类型徽标，不新增图标依赖；不同类型使用对应缩写、符号和颜色，未知文件使用通用文件图标。
- 提高语法颜色样式的优先级，避免浅色或深色主题的全局文字规则把 token 颜色覆盖成单色。

## 实施步骤

1. 新增共享文件类型识别模块，覆盖常见特殊文件名、多后缀文件和代码/配置扩展名。
2. 扩展 Highlight.js 轻量语言注册，并让 `.sh`、`.jsonl`、JSON Lines、TOML/INI、Ruby、Swift、Dart、Scala、Lua、Perl、GraphQL、Protobuf、Diff 等常见类型走明确语法。
3. 增加文件类型图标组件，接入文件树、预览标题和可点击的文件操作入口。
4. 调整四种主题下的语法 token 与文件图标样式。
5. 检查构建和差异，记录版本更新并创建本地提交，不推送远端。

## 验收标准

- `.sh` 的注释、内置命令和字符串可以明显区分颜色。
- `.jsonl` / `.ndjson` 每行 JSON 的键、字符串、布尔值和数字可以区分颜色。
- 常见源码、脚本、配置及标记文件不再因为缺少扩展名映射而退回单色。
- 文件树和文件相关操作中的图标可以直观看出 Shell、JSON、JavaScript、TypeScript、Python、Markdown、配置文件等类型。
- 未知文件安全回退为通用图标和可信度受限的自动语法识别。
- TypeScript/Vite 构建和差异检查通过。
