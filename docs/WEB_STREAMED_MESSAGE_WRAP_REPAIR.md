# 网页聊天流式正文换行修复

## 问题与分类

普通聊天的回复在流式更新和历史对齐期间，活动时间线记录的正文长度可能暂时落后于消息实际正文。当前渲染将超出该长度的尾部文字放进独立的消息区块，区块间距造成一句话提前换行；长度逐步追上时，文字会从第二块逐字移回第一块。

这是修复 / PATCH：恢复已有消息的正常排版，没有增加新的用户任务。群聊同步修复已在前一版本单独记录，本次目标版本为 `0.70.2-dev.1`。

## 实施步骤

1. 检查活动时间线按长度切分正文的路径，确认尾部文字被放进独立区块的条件。
2. 没有实际工具操作时，直接把完整正文作为同一个消息内容渲染。
3. 有工具操作时，若尾部文字紧接最后一个正文区块，就并入该区块；仍保留工具操作与正文的原有顺序。
4. 更新版本记录及项目版本，构建供 `4173` 页面加载的前端产物。
5. 检查本次差异并创建本地 Git 提交；不推送 GitHub。

## 验收标准

- 同一句话不会因为时间线长度暂时落后而被拆成两块。
- 流式更新时，正文不会在第一、第二行之间逐字迁移。
- 工具操作仍显示在相应正文之间。
