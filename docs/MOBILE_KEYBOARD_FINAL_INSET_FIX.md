# Android 输入法最终位置切换修复

## 目标与分类

修复 Android APP 点击聊天输入框后，输入框先提前跳高、再随输入法动画逐帧上推的问题。本次属于 PATCH / 修复：输入能力不变，只调整已有键盘布局的切换时机。

## 原因

- 输入框按下时，网页会根据历史值预估输入法高度，并在系统输入法真正出现前先给聊天区留出空间，导致页面下方短暂出现大片空白。
- Android 在输入法动画期间会连续发送多帧高度，网页每收到一帧就更新聊天区底部空间，因此输入框会跟随这些中间高度逐步移动。
- CSS 过渡已经移除，但原生高度本身仍在逐帧变化，所以仅删除 CSS 动画无法解决问题。

## 实施步骤

1. 删除聊天输入框按下时的键盘高度预估，不在输入法出现前改变聊天区位置。
2. Android 11 及以上监听系统输入法动画；动画期间只记录系统状态，不向网页发布中间高度。
3. 输入法动画结束后发布一次最终高度，让输入框直接切换到键盘上方。
4. 保留无系统动画及旧版 Android 的即时高度路径，避免键盘关闭或兼容路径失效。
5. 将内部测试版本更新为 `0.18.0-dev.2`，Android `versionCode` 更新为 `131`，生成不覆盖旧包的新 APK。
6. 构建网页和 Android APK，安装到当前连接的手机并保留应用数据；不重启 Codex Remote 网页服务。
7. 只提交本次相关文件，保留用户已有的 Android 开发文档和旧 APK，不推送 GitHub。

## 验收标准

- 点击聊天输入框后，输入框不会在键盘出现前先跳到页面中部。
- 输入法动画期间聊天页面保持原位；动画结束后输入框一次切换到键盘上方。
- 输入法收起后输入框一次回到底部，不随系统动画分段下降。
- 普通手机浏览器继续使用原有 `visualViewport` 布局逻辑。

## 完成记录

- 网页已取消输入框按下时的键盘高度预估，只使用 Android 最终发布的真实高度。
- Android 11 及以上会忽略输入法动画的中间高度，并在动画结束后向网页发布一次最终高度。
- 网页生产构建与 Android debug 构建完成；新 APK 为 `artifacts/codex-remote-android-0.18.0-dev.2-debug.apk`。
- 新 APK 已覆盖安装到当前连接的手机，应用数据保留；安装版本确认为 `0.18.0-dev.2`、`versionCode 131`。
