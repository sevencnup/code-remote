# 网页版助手提问卡片修复

## 目标与分类

修复网页版将已带有 `questions` 的助手提问显示为纯文本的问题，属于修复 / PATCH。目标版本 `0.76.14-dev.1`。

## 实施步骤

1. 从历史记录及实时 `agentMessage` 事件保留结构化题目、提问消息 ID 和异步投递类型，刷新后继续可见。
2. 优先用结构化题目渲染快速选择卡；兼容旧提问文本，在 AI 后续进度文字出现时保留可回答的问题。
3. 对齐 KT 版交互：点选现成答案、填写其他答案、直接“发送并继续”；运行中的异步题目尝试立即插队，失败时保留排队消息。
4. 避免同一提问的原文和卡片重复显示，同时保留其后的 AI 进度文字与现有输入框草稿。
5. 更新版本及简短更新记录，进行有针对性的验证，审阅修改并创建本地提交。

## 完成标准

- 截图所示提问在网页版出现可选卡片、其他答案输入框和发送按钮。
- 当前回复进行中可以回答；忙碌时答案留在队列中，送达未确认时提示先核对记录。
- 重新载入当前对话仍能识别题目；历史已回答题目不再提供活动操作。

## 完成记录

- 历史消息、实时回复和当前对话缓存保留结构化题目；选择卡按原提问位置展示，后续进度文字继续显示。
- 支持选项、其他答案、“发送并继续”和原有“填入输入框”。异步提问尝试立即插队，不能插队时保留服务器排队项；送达未确认时提示核对记录。
- 文字兼容路径识别“是……还是……”提问后的选项，即使后面继续出现 AI 进度文字。
- `node --test tests/messageChoices.test.mjs tests/codexRemoteClient.test.mjs` 通过 36 项；TypeScript 与 Vite 构建成功，4173 预览服务读取新构建入口。
- 本轮没有向真实对话提交测试答案，也没有打包 Android；版本记录更新为 `0.76.14-dev.1`。

## 历史提问卡片恢复（追加修复）

### 目标与分类

恢复网页历史消息中的助手选择题卡片，并将展示与回答权限分开：历史题目保留卡片及选项，只有当前待回答题目可以交互。这是已有选择题功能未按预期显示，属于修复 / PATCH，目标版本 `0.76.15-dev.1`。Android 仅同步 `versionName`，不改 `versionCode`，不生成 APK。

### 实施步骤

1. 保留 `assistantChoiceStartIndex` 对当前可回答题目的边界判断，但不再用它隐藏更早助手消息中的结构化题目或可识别的旧版文字题目。
2. 为选择卡片增加只读状态：历史题目选项禁用，隐藏回答输入和提交操作，并显示“该问题已有后续消息”；当前待回答题目沿用现有选取、填入和发送行为。
3. 更新 `CHANGELOG.md`、`package.json`、服务版本声明（若适用）和 Android `versionName`，不递增 `versionCode`。
4. 检查差异并提交本地 Git；本轮按开发者指令不新增或运行测试。

### 完成标准

- 重新打开包含历史选择题的对话时，题目以卡片和选项显示，不再只显示纯文本。
- 已经有后续消息的历史题目不可选择或提交，并显示说明；最新待回答题目的交互保持可用。
