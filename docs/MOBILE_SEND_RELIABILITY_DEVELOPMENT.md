# 移动端消息可靠发送开发文档

## 目标

解决移动网络、Android WebView 或局域网隧道短暂断开时消息显示 `Failed to fetch`、发送状态不确定，以及对话记录偶发加载失败的问题；恢复连接后不得重复发送同一条消息。

## 根因

- 当前发送请求没有请求唯一标识。客户端收到网络错误时，无法判断后端是在接收前断开，还是已经启动 Codex 后在回包途中断开。
- 因为无法安全重试，前端只能撤回本地消息并恢复草稿，导致后端已收到但手机仍显示发送失败。
- 对话读取等只读请求遇到短暂断网会立即失败，没有覆盖移动端常见的瞬时抖动。
- systemd 当前运行 Vite 开发服务；人工重启期间连接会断开，客户端仍需正确恢复。

## 实施步骤

1. 为开始回答和插队消息请求增加稳定的 `request_id`，复用已有排队消息 ID，刷新或重试后保持不变。
2. 后端按操作、对话和请求 ID 去重；相同请求在执行中时共用同一个任务，执行完成后短期缓存结果。
3. 同一请求 ID 携带不同内容时返回冲突错误，避免错误复用旧结果。
4. 客户端仅对网络层失败重试带去重能力的发送请求；普通服务端错误原样返回。
5. 对安全的只读请求增加短暂指数退避，降低移动端瞬时断线导致的历史加载失败。
6. 保留最终的对话核对逻辑；全部重试仍失败时保留草稿并明确提示送达状态。
7. 更新版本记录并创建本地 Git 提交，不推送 GitHub。

## 验收标准

- 发送请求回包短暂中断时，客户端使用同一请求 ID 重试，Codex 只收到一条消息。
- 重试与原请求并发到达后端时，两次请求得到同一个执行结果。
- 手机短暂断网后，对话列表和历史读取可以自行恢复。
- 持续离线时不无限重试，输入内容仍保留，页面说明送达状态不确定。
- 现有旧版网页请求没有 `request_id` 时仍可正常使用。

## 回滚

撤销请求 ID、后端去重注册表和客户端网络重试改动；保留原有草稿恢复逻辑。
