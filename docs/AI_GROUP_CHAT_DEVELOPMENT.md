# AI 群聊开发文档

## 目标

在网页版提供一个由 Codex 与 Claude Code 组成的群聊视图，让用户可以同时问两边，并在用户确认后让它们相互回应一轮。

## 范围与决策

- 群聊使用两个独立的后端会话：Codex thread 与 Claude Code session；不把模型、工具权限或会话状态混用。
- 新群聊按 Codex / Claude Code 各自保存的模型、推理强度与授权偏好运行；恢复已有群聊时读取对应会话的偏好。
- 群聊面板显示一个用户消息流，并按引擎标识两边的回复。
- 每条用户消息默认并发发送给两个参与者。
- 两边完成后，用户可手动触发一次交叉回应：将 Codex 回复转给 Claude，将 Claude 回复转给 Codex。每条用户消息最多执行这一轮，避免自动循环与不可控用量。
- 传给模型的跨模式历史限制为近期消息并清楚标注来源；对方模型的内容作为引用材料，不构成权限授权。
- 首版仅支持文本消息；通过浏览器本地存储保存群聊会话 ID 与显示记录，实际模型会话仍由服务端按各自模式持久化。
- 两个群聊会话都以「AI 群聊」出现在普通聊天列表，由现有模式图标区分，方便用户单独查看与管理。

## 实施步骤

1. 新增群聊面板，分别通过现有 hook 创建并恢复 Codex、Claude Code 会话。
2. 新增群聊消息流，合并显示双方 assistant 增量回复；用户消息仅显示一次。
3. 添加双发与手动单轮交叉回应；保持模型与权限参数按参与者各自模式传递。
4. 在侧边栏提供群聊入口，并为群聊面板添加主题和窄屏布局。
5. 更新版本与更新记录。本次属于 MINOR / 新增功能，版本更新至 `0.51.0-dev.1`；不生成 APK，因此不递增 Android `versionCode`。
6. 运行 `pnpm --filter codex-remote build` 与差异检查，不新增或运行测试；检查工作区并提交本地 Git，不推送 GitHub。仅更新 Android `versionName`，不构建 APK，因此保留 `versionCode`。

## 验收标准

- 网页侧边栏可打开 AI 群聊，Codex 和 Claude Code 状态分别可见。
- 一条用户文本可同时进入两个不同引擎的独立会话；回复在同一群聊窗口按来源区分并流式显示。
- 用户可在两边都完成后发起一次交叉回应；一条用户消息不会触发重复或无限转发。
- 关闭或刷新网页后可恢复群聊显示记录及两边的会话。
- 不覆盖现有会话，不改变 Codex 与 Claude Code 自己的模型和权限配置。
- `pnpm build` 成功，`git diff --check` 无输出。
