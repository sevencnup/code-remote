# AI 群聊成员点名与排队状态开发记录

## 目标

修复群聊成员改名后，使用「Codex」「Claude」或「Claude Code」点名仍被广播给两位成员的问题，并让用户能从成员状态看出消息正在排队、确认发送或等待核对。

## 修改分类与版本

- 分类：修复 / PATCH。群聊原有的定向发送能力在成员改名后可能无法按预期工作；本次修正路由并补充发送状态，不改变用户可完成的任务。
- 版本：`0.55.1-dev.3`。
- 版本记录：`修复 AI 群聊改名后的成员点名路由并显示排队状态`。

## 实施步骤

1. 将点名匹配提取成可单测的纯函数，匹配成员自定义名称及引擎原名；按最长匹配优先处理「Claude Code」，发生跨成员名称冲突时提示歧义。
2. 直接点名时，在发给目标成员的提示中说明本轮已由界面定向路由，避免自定义名和引擎原名不一致时模型误判对象。
3. 根据成员发送队列展示「确认发送」「排队中」「发送受阻」「送达待核对」等状态。
4. 新增路由测试，执行前端构建及相关测试；不连接或操作用户的真实 Claude/Codex 会话。
5. 更新版本记录并创建本地提交，不推送 GitHub。

## 验收标准

- 成员改名后，`Claude你装死是吧` 仍只路由给 Claude；`Codex ...` 仍只路由给 Codex。
- 同一条消息同时匹配两个成员时不会误广播。
- 「Claude Code」作为前缀时优先于较短的「Claude」匹配。
- 群聊成员正在排队或等待核对时，状态不再只显示为普通已连接。
- 前端构建成功；新增点名测试通过。
