# 文件树目录绑定当前聊天开发文档

## 目标

在右侧文件树的目录右键菜单中提供“绑定当前聊天到此目录”。使用后，将正在查看的聊天绑定到所选目录，继续保留同一条聊天及其历史；不得为了切换目录新建聊天。

绑定关系按聊天 ID 保存在服务端共享状态中，在服务重启及已配对设备之间保留。文件树、聊天标题中的工作目录和后续 Codex 回合都使用绑定目录。Codex App Server 的 `thread/resume` 支持 `cwd` 参数；启动新回合前按绑定目录恢复会话，使其实际运行目录与界面一致。

正在执行的回合不会被迁移到另一目录；它结束后，新回合使用绑定目录。绑定一个聊天不得影响其他聊天或全局默认工作区。

## 设计边界

- 菜单项只在目录右键菜单、且当前聊天已经存在时显示；不创建或切换聊天。
- 所选路径由服务端解析并规范化；拒绝不存在或不是目录的路径。绑定失败时保留原绑定和当前聊天。
- 菜单只修改触发操作的当前聊天；其他并发聊天各自保留原工作目录。
- 服务端列表和历史读取结果叠加聊天绑定目录，确保刷新、重新打开和其他设备打开时显示一致。
- 开始新回合前用 `thread/resume` 的 `cwd` 参数应用绑定目录；排队消息实际发送时也遵循该目录。
- 文件树“加入输入框”、文件预览和原有路径浏览行为保持可用。

## 实施步骤

1. 将本开发文档修订为“绑定当前聊天”，明确不创建聊天及运行中回合的生效时机。
2. 在共享状态 SQLite 中增加按聊天 ID 保存规范化工作目录的读写能力。
3. 增加绑定工作目录接口；校验聊天和目录后再保存，并广播会话元数据变化。
4. 在会话列表、历史读取和恢复/发送流程中应用绑定目录；新回合开始前通过 App Server 的 `thread/resume.cwd` 确保 Codex 实际使用绑定目录。
5. 将文件树菜单改为绑定当前聊天；成功后就地更新当前聊天工作目录，不重置对话历史或聊天 ID。
6. 按语义化版本规则记录本次新增能力，检查差异并执行生产构建；按本机开发规范创建本地 Git 提交，不推送 GitHub。

## 验收标准

- 在目录右键菜单选择绑定后，当前聊天 ID 和消息历史不变，也不会多出新聊天。
- 当前聊天标题和文件树根目录更新为所选目录；刷新页面、重启服务或从另一已配对设备打开后仍然如此。
- 绑定后发送的新回合及排队后发送的新回合都通过绑定目录恢复 Codex 会话；绑定前已经开始的回合继续使用原运行目录。
- 其他聊天的工作目录不变。
- 无效目录或不存在的聊天绑定失败，当前聊天和原绑定保持不变。
- 文件树原有的“加入输入框”功能保持可用。
