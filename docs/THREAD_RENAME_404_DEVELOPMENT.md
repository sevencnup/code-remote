# 会话重命名接口 404 修复记录

## 现象与根因

- 网页请求 `POST /api/v1/codex/threads/{thread_id}/name` 返回 404。
- 当前仓库后端已经实现该路由；检查运行中服务的 OpenAPI 路由清单时，该路由不存在，说明服务进程运行的是旧版后端，而非 Codex 的 `thread/name/set` 调用失败。

## 实施步骤

1. 前端遇到该接口的 404 时显示明确的后端版本提示，不再只显示 `Not Found`。
2. 保留现有后端重命名实现并运行相关后端测试，确认路由确实注册。
3. 更新版本记录，执行前端测试、构建和差异检查，并创建本地提交。
4. 不在本次改动中擅自重启或部署运行中的后端；需要应用修复时，由用户明确指示后再更新服务。

## 验收标准

- 旧版后端返回 404 时，界面提示用户更新并重启 Codex Remote 后端。
- 新版后端仍通过 Codex App Server 修改真实会话名称，并返回成功结果。

## 验证结果

- 检查运行中服务的 OpenAPI 路由清单，确认当前进程确实缺少重命名接口；仓库源码中的路由已存在。
- 前端测试 32 项通过，`pnpm build` 通过，`git diff --check` 通过。
- 后端单元测试因当前 Python 环境缺少 `fastapi` 和 `watchfiles` 未能运行；本次没有改动后端路由实现。
- 未重启或部署运行中的服务，未推送 GitHub。
