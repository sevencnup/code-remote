# 设备群聊穿透地址提示修复

## 用户可见变化与分类

设备通过内网穿透互通时，房间地址应使用另一台设备能访问的穿透域名或地址。界面目前强调局域网 IP，并在通过 localhost 打开时自动填入本机私网 IP，容易生成无法连接的链接。本次修正现有连接流程的地址选择和提示，属于体验优化 / PATCH，目标版本 `0.69.2-dev.1`。

## 实施步骤

1. 保留当前网页的非回环地址作为初始房间地址，包括 HTTPS 穿透域名；通过 localhost 打开时留空，由用户填写穿透地址。
2. 局域网 IP 只作为可选建议，不自动覆盖用户填写的穿透地址；创建端和加入端都说明可以填写设备间可达的 HTTP/HTTPS 域名或地址。
3. 后端地址校验、加入和长连接使用现有域名能力，修正文案，不引入 SSH 或新转发层。
4. 更新说明文档、版本记录，执行构建和差异检查，提交并推送 Gitea。

## 验收

- 通过穿透域名打开房间网页时，该域名直接显示在可复制地址中。
- 通过 localhost 打开时，不自动复制或填入可能不可达的局域网 IP，用户可填写穿透域名。
- 加入端可填写 HTTPS 穿透地址，原有一次性设备加入码逻辑继续使用。

## 验证结果

- 后端 URL 验证接受 HTTPS 域名与非回环地址，拒绝 localhost 和回环 IP；WebSocket 连接代码继续将 HTTPS 地址转换为 WSS。
- TypeScript 检查、Vite 生产构建、Python 编译检查和 `git diff --check` 通过。
