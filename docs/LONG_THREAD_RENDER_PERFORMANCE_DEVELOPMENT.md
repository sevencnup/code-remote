# 长会话页面卡顿优化开发记录

## 目标

长聊天和新聊天保持接近的日常输入、滚动及流式回复响应速度；保留完整聊天历史、文件审核、队列和浏览器缓存。

## 已确认问题

- 消息区一次把当前会话的全部历史挂到 DOM；长会话的布局、滚动与 React 协调成本持续增加。
- 流式回复每次更新消息时，活动会话缓存 effect 都扫描完整消息列表并重置持久化写入计时器。
- IndexedDB 的容量有上限，不能简单归因于缓存无限增长；清除缓存还会影响本地草稿与排队消息。

## 实施步骤

1. 为长会话增加最近消息优先的分段渲染；旧消息按需向上加载，保留现有消息顺序、文件审核卡片和回到底部能力。
2. 加载旧消息时维持当前视线位置；回复继续到来时不能让正在阅读旧消息的用户突然跳到底部。回到底部后收回多余的旧消息 DOM。
3. 仅在空闲或明确离开会话时更新完整持久缓存，避免流式分片反复扫描整段历史；不改变缓存内容及恢复协议。
4. 为分段边界、切换会话和新消息进入增加回归测试；运行前端测试、构建、差异检查。
5. 更新版本记录并创建本地 Git 提交；不推送 GitHub，不重启运行中的服务。

## 验收标准

- 打开很长的会话默认只渲染最近一段，仍能逐段查看所有更早消息。
- 加载更早消息、切换会话及回到底部时没有明显跳动，也不会丢失消息或审核卡片。
- 流式回复时不按每个分片扫描并准备完整持久缓存；完成后仍可正常恢复缓存。
- 相关测试、`pnpm build` 和 `git diff --check` 通过。
