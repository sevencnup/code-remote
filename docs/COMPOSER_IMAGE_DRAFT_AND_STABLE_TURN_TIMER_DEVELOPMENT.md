# 输入图片草稿持久化与回复计时稳定性开发文档

## 目标

修复刷新网页后输入框待发送图片丢失的问题；保证 Codex 回复期间活动提示和耗时模块随同一轮任务稳定显示；并将桌面端活动提示、耗时和输入框字号统一到助手回复正文的字号。移动端字号保持现状。

## 实施步骤

1. 梳理运行状态、活动状态和轮次开始时间在 App Server 事件、历史恢复、重连、切换会话及排队发送中的更新路径，确保活动文字变化不会重置计时；历史恢复时尽可能读取轮次开始时间，缺失时只为该轮次生成一次稳定的本地起始时间。
2. 将输入图片草稿按新建会话/会话 ID 保存至 IndexedDB，避免 localStorage 容量不足；处理异步恢复、会话切换、添加/移除、排队消息编辑、发送成功清理及发送失败恢复。
3. 保持文本草稿与现有 localStorage 逻辑兼容；图片恢复完成前避免发送或覆盖尚未恢复的附件。
4. 将桌面端“正在思考/操作中”、耗时和输入框字号统一为助手消息正文的 12.5px；保留窄屏/移动端已有字号覆盖。
5. 更新版本记录至 0.0.177，执行测试、生产构建和差异检查，并创建本地 Git 提交；未经明确指令不推送 GitHub。

## 验收标准

- 刷新或重新进入同一会话后，待发送图片仍显示且可正常发送；不同会话的附件互不串用。
- 图片添加、移除、排队编辑取消/确认、发送成功和发送失败后，持久化内容与输入框实际草稿一致。
- Codex 正在回复时，思考/操作提示与耗时不会因活动文案更新或历史恢复而无故消失；会话切换及轮次完成后不会残留旧计时。
- 桌面端相关文字字号为 12.5px；移动端原字号规则不变。
- `pnpm test`、`pnpm build` 和 `git diff --check` 均通过。
