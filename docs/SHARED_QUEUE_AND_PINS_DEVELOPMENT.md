# 跨设备共享排队消息与置顶开发记录

## 目标

排队消息及侧栏置顶以电脑端服务为权威状态，手机息屏、网页关闭后仍能继续按顺序发送；所有已配对设备看到相同状态。

## 已确认现状

- 排队消息、恢复屏障和置顶均存储在每台设备各自的 `localStorage`。
- 自动发送依赖网页收到 `turn/completed`；移动浏览器后台暂停时不会继续推进。
- 旧客户端已有发送尝试标记；迁移时必须保留，不能把送达未确认的条目自动重发。

## 实施步骤

1. 在电脑端建立持久化的队列与置顶状态，按会话保存队列顺序、附件、编辑状态及发送尝试；提供经配对鉴权的读写接口。
2. 由电脑端服务监听 Codex 轮次事件并独立推进队列；启动恢复时核对真实轮次，运行中、异常结束或状态不明时停发；发送前持久化尝试，断线/重启不自动重复发送。
3. 网页改用服务端队列作为唯一权威，队列编辑、立即发送、删除和侧栏置顶跨设备同步；离线操作失败时明确反馈，避免显示为已成功。
4. 将旧浏览器排队消息按稳定 ID 幂等迁移；已有发送尝试的项目保持待核对。旧置顶从首次有置顶的设备导入一次，避免其它设备的旧快照重新置顶。
5. 添加服务端队列顺序、息屏场景、重启恢复、并发防重、编辑暂停与置顶同步测试；执行网页构建和既有测试，记录版本，创建本地 Git 提交，不推送 GitHub。

## 验收

- 手机排队后息屏，电脑端仍在回复完成后逐条发送；另一设备可看到并管理队列。
- 同一条队列消息只由电脑端发送一次；响应丢失或服务重启后不会自动重复发送。
- 编辑中的条目暂停自动发送，确认后继续；失败/中断轮次不抢发。
- 置顶在设备间同步，取消置顶不会被旧本地快照再次覆盖。
- 原始 PDF 仍依赖当前服务进程的临时文件；服务重启或附件过期后保留队列并停止自动发送，需重新附加文件。
