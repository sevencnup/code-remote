# 文件语法高亮全局排查

## 目标

排查工作区文件预览中已支持的代码和配置格式，修正扩展名到 Highlight.js 语法的错配，并补齐暗色、亮色、暖色和自定义主题缺少的 token 颜色，避免代码被当作普通文本显示。

## 范围

- `workspaceFileTypes.ts` 中的扩展名和特殊文件名映射。
- `codeHighlight.ts` 中 Highlight.js 语法的静态注册和懒加载映射。
- 文件预览的 Highlight.js token 样式，以及聊天代码块的语法显示路径。
- 非代码文本、图片、归档等类型继续保持普通文本或现有预览行为。

## 实施步骤

1. 自动比对已声明语言与 Highlight.js 已注册/可加载语法，找出错误映射和遗漏格式。
2. 用代表性样例检查主要语法产生的 token 类，找出主题 CSS 未着色的 token。
3. 修正格式映射并补全所有主题的 token 颜色；确保代码块遵循对应语言。
4. 构建前端并核查高亮代码路径与主题样式。
5. 按修复分类递增版本，并在完成回复中说明分类和理由。

## 排查结果

- 已逐项核对文件扩展名映射和 Highlight.js 的静态、懒加载及自定义语法；修正 JSON5、JSONC、TOML 映射，并补齐 systemd `.service`、ProGuard 规则和 Cython 文件映射。
- 聊天围栏代码现在根据语言标记异步高亮；文件预览和聊天代码块统一使用暗色、亮色、暖色和自定义主题的完整 token 调色板。未标注语言的聊天代码不会加载大型自动检测语法包。
- 无语法映射的未知扩展名继续走置信度检测；CSV、TSV、日志和纯文本仍保持纯文本显示。
- 后续实机反馈显示自定义主题下仍是单色：浏览器计算样式确认语法 token 的 `color` 已分色，但文件预览容器继承的固定 `-webkit-text-fill-color` 把实际绘制颜色统一成白色。已移除预览容器的固定填充色，并让 token 的填充色跟随各自的 `color`。
