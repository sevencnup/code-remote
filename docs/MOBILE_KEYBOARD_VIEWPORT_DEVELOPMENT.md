# 移动端键盘视口布局开发文档

## 目标

修复 Android WebView 唤起输入法后，输入框下方出现大块空白的问题，让输入框继续贴在键盘上方。

## 根因

Android WebView 在输入法显示时可能保持布局视口高度，同时把可视视口通过 `offsetTop` 向上平移。页面只使用 `visualViewport.height` 设置应用高度时，应用高度会缩短一次，而可视区域仍保留原布局底部，因而在输入框和键盘之间留下空白。

另一个单独的闪动问题来自输入法被重复唤起：聊天输入框的 `pointerdown` 和 `focus` 都调用原生桥接；原生桥接还会无条件在首次请求后 240 毫秒再次强制显示输入法。首次点击可能因此重复重启输入连接并触发多次视口布局。

## 实施步骤

1. 保留现有布局视口和可视视口的高度计算，继续覆盖键盘只缩小视口或同时平移视口的两种行为。
2. 首次点击仅在输入框获得焦点时请求键盘；输入框已保持焦点且键盘被收起后，再点击才通过桥接重新请求键盘。
3. 原生桥接先检查输入法是否已显示；延迟重试也仅在首次请求仍未显示输入法时执行。
4. 构建网页资源和使用新版本号的 Android APK，不覆盖历史安装包。
5. 更新版本记录并创建本地 Git 提交。

## 验收标准

- 键盘显示时输入框底部贴近键盘顶部，不出现大块空白。
- 点击输入框时页面只经历一次键盘布局变化，不因重复调起而闪动。
- 输入法仍能正常唤起、输入候选词并发送消息。
- 键盘收起后页面恢复完整高度。
- 旧版本 APK 保留，新 APK 使用独立版本号。
