# 移动端键盘视口布局开发文档

## 目标

修复 Android WebView 唤起输入法后，输入框下方出现大块空白的问题，让输入框继续贴在键盘上方。

## 根因

Android WebView 在输入法显示时可能保持布局视口高度，同时把可视视口通过 `offsetTop` 向上平移。页面只使用 `visualViewport.height` 设置应用高度时，应用高度会缩短一次，而可视区域仍保留原布局底部，因而在输入框和键盘之间留下空白。

另一个单独的闪动问题来自输入法被重复唤起：聊天输入框的 `pointerdown` 和 `focus` 都调用原生桥接；原生桥接还会无条件在首次请求后 240 毫秒再次强制显示输入法。首次点击可能因此重复重启输入连接并触发多次视口布局。

真机继续出现整页白屏闪烁，说明剩余问题位于 WebView 外壳：Android 使用 `adjustResize` 并按输入法高度缩小 WebView，网页又根据 `visualViewport` 改写整页高度。键盘动画期间，原生视图尺寸和网页布局同时连续变化，WebView 渲染表面可能在两次提交之间短暂露出空白帧。

## 实施步骤

1. 保留现有布局视口和可视视口的高度计算，继续覆盖键盘只缩小视口或同时平移视口的两种行为。
2. 首次点击仅在输入框获得焦点时请求键盘；输入框已保持焦点且键盘被收起后，再点击才通过桥接重新请求键盘。
3. 原生桥接先检查输入法是否已显示；延迟重试也仅在首次请求仍未显示输入法时执行。
4. 构建网页资源和使用新版本号的 Android APK，不覆盖历史安装包。
5. 更新版本记录并创建本地 Git 提交。

## 后续修复步骤

1. Android 11 及以上的聊天 WebView 改用 `adjustNothing`，保持 WebView 渲染表面尺寸稳定；旧系统保留 `adjustResize` 兼容路径，连接地址页面仍使用输入法 Insets 保证输入框可见。
2. 原生桥接提供实时输入法底部高度，并通知网页重新计算可用聊天高度。
3. Android 页面只使用布局视口减去原生输入法高度，不再同时采用波动的 `visualViewport` 高度。
4. 键盘开合期间暂时停用输入框的背景模糊和发光动画，并给内容高度加入短促过渡，减少大面积重绘。
5. 设置 Android 窗口背景色，避免系统合成层切换时露出默认白色。
6. 更新网页、Android 版本和 APK；构建校验后创建本地 Git 提交。

## 本次完成记录

- 网页与 Android `versionName` 更新为 `0.16.0-dev.4`，Android `versionCode` 更新为 `128`。
- Android 11 及以上使用稳定 WebView 表面和原生输入法高度；Android 10 及以下继续走系统缩放兼容路径。
- 原生输入法已显示时不再触发网页的延迟键盘兜底，兜底等待时间延长到 500 毫秒。
- 网页生产构建和 Android debug 构建通过；新安装包为 `artifacts/codex-remote-android-0.16.0-dev.4-debug.apk`，没有覆盖历史安装包。

## 验收标准

- 键盘显示时输入框底部贴近键盘顶部，不出现大块空白。
- 点击输入框时页面只经历一次键盘布局变化，不因重复调起而闪动。
- 输入法仍能正常唤起、输入候选词并发送消息。
- 键盘收起后页面恢复完整高度。
- 旧版本 APK 保留，新 APK 使用独立版本号。
- 键盘开合时 WebView 本身不再改变尺寸，聊天内容平滑缩放且不露出整页空白帧。
