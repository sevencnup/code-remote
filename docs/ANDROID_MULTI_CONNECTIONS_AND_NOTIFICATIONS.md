# Android 多连接配置与后台通知

## 目标

在 APP 设置中保存多个电脑连接，直接切换当前连接；原有配对信息自动迁移。后台回复完成时，在通知权限已授予且连接可用的情况下收到系统通知。

## 开发步骤

1. 将单个地址和令牌迁移为本机连接列表，保留现有连接、草稿和历史缓存。
2. 在设置的连接模块列出配置，支持新增、切换、重命名与删除；新增连接通过原配对码验证。
3. 切换时清理当前连接的实时状态，按连接隔离上次对话、草稿、会话设置及历史缓存。
4. 修复后台断线后不重连的问题，并提供通知自检入口；设置显示实际可用状态。
5. 递增测试版本，生成独立 APK 并安装到已连接设备。

## 验收要点

- 旧连接自动出现在列表，切换已配对连接无需重新输入匹配码。
- 在两个连接间切换后，聊天、草稿和缓存不会串台。
- 后台断线后 APP 仍尝试恢复通知连接；测试通知能验证系统权限和通知通道。

分类：MINOR / 保存和切换多个电脑是新增能力；通知修复与其合并发布。

## 实机验收

- `0.23.0-dev.1` 已在 `10.126.126.2` 安装；原有连接自动出现在设置的连接列表，添加连接弹窗在键盘显示时三个输入项与操作按钮均可见。
- 设置里的测试通知成功创建 `codex_remote_native` 通道，并在 Android 通知管理器中生成通知记录。
- 检查发现退到桌面后停用 WebSocket 心跳会让半断开的连接无法及时恢复；`0.23.0-dev.2` 保留通知开启时的后台心跳。
- `0.23.0-dev.2` 离线构建成功，已通过 ADB 覆盖安装到 `10.126.126.2`；设备显示 `versionCode=207`、`versionName=0.23.0-dev.2`，通知通道仍存在。
- 测试通知仅证明手机本地通知链路可用；真实回复完成事件仍取决于后台 WebSocket 在线。系统杀掉 APP 进程时，需要推送服务或前台服务才能保证即时通知。

## 只填写局域网 IP 时连接失败

截图显示新增连接时输入了局域网 IP，但没有端口；当前地址规范化会使用 HTTP 默认的 80 端口，项目网页服务常用 4173 端口。手机到该 IP 的 4173 端口已确认可建立 TCP 连接。

1. 对未填写端口的纯 IPv4 地址自动补全项目默认端口 4173；明确填写端口、域名和 HTTPS 地址保持原样。
2. 新增连接弹窗提示 IP 可省略端口，并保留直接填写完整地址的能力。
3. 递增内部测试序号与 Android versionCode，构建独立 APK 并安装到手机。

分类：PATCH / 修复已有新增连接入口对局域网 IP 的默认处理。
