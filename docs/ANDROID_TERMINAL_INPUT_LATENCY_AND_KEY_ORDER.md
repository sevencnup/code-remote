# Android 终端输入延迟与方向键顺序

## 目标与分类

把终端底部方向键排成“左、上、下、右”，降低键盘输入到终端回显的等待时间。保留左下角“复制到输入框”和右下角“键盘”：前者把选中终端文字送回聊天输入框，后者重新唤出系统键盘。

本次属于修复 / PATCH：终端的能力和用法没有扩展，修正已有输入的响应速度与操作布局。最终目标 Android 包为 `0.62.0-dev.14`，`versionCode 338`。

## 已确认的延迟来源

1. 当前隐藏输入控件允许输入法组合文字；微信输入法可先积累候选文本，直到 `commitText` 才发送给 PTY。中文候选需要等待用户选词；英文键位不应无谓地等待预测和组合。
2. 每段 WebSocket 输出在 Android 主线程处理时，`TerminalScreenBuffer.append()` 立即生成一次完整屏幕字符串，但调用方丢弃它；32 ms 后正式绘制又生成一次。输入量大时会占用主线程，也给回显加固定等待。
3. 服务端用异步线程写 PTY；当前没有证据表明这条路径是主要瓶颈。本轮优先修复设备端明确可见的等待和重复工作，不改正在承载用户聊天的服务端。

## 实施步骤

1. 调整方向键顺序，保持原来的 ANSI 转义序列。
2. 调整终端输入目标的 IME 配置，让无需候选的按键尽早通过 `commitText`；保留中文候选、删除、回车和硬件键处理。
3. 取消每个输出块上的无用全屏渲染，把正式绘制间隔缩短到一帧，并避免内容未变时重新设置文本。
4. 更新 Android 版本与简短版本记录，构建独立 APK 并安装到手机；核对按钮布局、系统键盘及输入回显。
5. 清理临时调试内容，检查差异，创建只含本次修改的本地提交；不推送 GitHub。

## 实机发现

首次构建的 `0.62.0-dev.13` 已装机，方向键布局与键盘位置正常。微信输入法报告终端输入控件为可见密码类型后，系统弹出 Bitwarden 自动填充提示，遮住快捷键，因此禁用该控件的自动填充并另建 `dev.14`，保留 `dev.13` 安装包作追溯。微信输入法仍显示“中英”切换入口。

使用单独创建、无聊天标识的本地 PTY 会话做 10 次字符回显测量：最短 0.4 ms、中位 0.5 ms、最长 0.6 ms。测量结束后已关闭该会话；这只能排除本机 PTY 写入为主要延迟源，不能代表手机输入法与网络往返。

## 交付检查

- `:app:assembleDebug --offline` 构建成功；`0.62.0-dev.14` / `versionCode 338` 已安装，手机包管理器回报的版本一致。
- 新包保存在 `artifacts/codex-remote-android-0.62.0-dev.14-debug.apk`；`dev.13` 包没有覆盖。
- `dev.13` 的真机截图确认方向键区、左下角复制按钮、右下角键盘按钮和微信输入法可见；`dev.14` 只增加终端输入控件的自动填充禁用标记。
- 安装 `dev.14` 时手机正在使用别的应用，没有再强制切回 Codex Remote；因此新版的 Bitwarden 弹窗是否完全消失、用户手指输入的体感延迟和中文候选提交仍待真机交互确认。

## 验收标准

- 快捷键由左至右是“左、上、下、右、Tab、Esc、Ctrl+C”。
- 键盘按钮在右下角，复制到输入框在左下角；无独立命令发送框。
- 普通字符输入后尽快回显；中文候选选定后完整发送，不把拼音半成品发给终端。
- 不覆盖旧 APK，也不影响当前真实终端会话中的程序。
