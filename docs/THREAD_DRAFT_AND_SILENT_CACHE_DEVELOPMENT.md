# 会话草稿隔离与静默缓存开发文档

## 目标

切换已访问过的聊天时立即保留缓存画面，不被同内容的服务端校验结果再次刷新；每条聊天拥有独立草稿，切换会话不会携带或覆盖另一条会话的输入内容。

## 根因

- 会话命中内存缓存后仍立即调用 `thread/read`，并无条件替换消息数组和活动会话对象，即使内容完全相同也会触发消息区重绘与自动滚动。
- 输入组件的草稿只使用一个全局浏览器存储键，因此所有会话共享同一份未发送文本。

## 实施步骤

1. 为消息、附件和会话显示字段增加等值判断；后台校验返回的数据与缓存一致时复用现有状态引用，不触发消息区重绘或滚动。
2. 缓存命中的会话改为先直接显示缓存，再延后执行静默校验；首次未命中才保持前台加载。
3. 将草稿存储键按会话作用域拆分，并迁移旧的全局草稿；无会话时使用独立的“新对话”作用域。
4. 切换会话时以草稿作用域作为输入组件键值，保存离开会话的草稿并恢复进入会话的草稿；自动创建首个会话时转交尚未发送的“新对话”草稿。
5. 更新版本记录，执行前端构建、后端测试、差异检查，并创建本地 Git 提交。

## 验收标准

- 已预热的聊天切回时不出现二次消息重绘、闪动或自动滚动；后台校验只在内容真的变化时更新画面。
- 在聊天 A 输入草稿，切到 B 后输入框显示 B 的草稿；切回 A 能恢复 A 的草稿。
- 新对话自动创建或手动创建时，不丢失尚未发送的初始草稿。
- `pnpm build`、后端单元测试和 `git diff --check` 均成功。
