# SSH 首次连接信任入口开发文档

本次让用户在网页设置中完成此前需要进入服务器终端处理的 SSH 主机信任，属于**新增功能 / MINOR**，目标版本 `0.83.0-dev.1`。

## 用户流程

1. 用户保存 SSH 服务器后点击「检查连接」。若是首次连接，设置页显示服务器地址和 SHA256 主机指纹，并给出「信任并重试」按钮。
2. 用户确认后，后端再次读取同一服务器的主机公钥。只有指纹与页面展示的一致、且该地址尚无已保存的不同主机密钥时，才写入服务账户的 `known_hosts`。
3. 页面自动重试连接，并显示成功或密码等后续错误。已信任的服务器按原流程检查；指纹变化时拒绝覆盖并提示重新核对。

## 边界

- 获取指纹不发送 SSH 密码或私钥；信任操作只保存目标服务器的公钥，不读取或输出用户凭据。
- 仅已配对的设备可调用新增接口；服务器 ID 从服务端配置读取，浏览器不能指定任意主机写入 `known_hosts`。
- MCP 工具授权与 SSH 主机信任分别生效；AI 调用不会自动信任未知主机。

## 实施步骤

1. 后端增加读取主机指纹、确认后写入 `known_hosts` 的能力，并在连接检查接口返回首次连接信息。
2. 设置页加入简短的首次连接确认卡片与自动重试。
3. 更新版本和简短更新记录，构建网页并完成本地提交；不推送 GitHub。
