# 远程聊天同步流量优化开发记录

## 目标

减少手机端和电脑端远程会话的重复下载。会话缓存命中且没有新内容时，不重新下载完整聊天历史；用户消息、流式回复、排队消息核验和断线恢复仍保持正确。

## 根因

- 活动会话每 4 秒调用一次 `thread/read`，每次都下载完整会话历史，且没有先检查缓存或更新时间。
- 任意 `threads.changed` 事件都会在 700 毫秒后重读当前会话。Codex 历史文件变化和新建其他聊天都会触发该通用事件。
- 活动会话收到 `turn/started` 后可能先读取一次历史，`turn/completed` 又会无条件读取一次；长会话和带图片会话会重复传输大量内容。
- 服务端的 `thread/read` 会为本地产生的图片嵌入 Base64 数据，放大每次完整读取的流量。

## 实施步骤

1. 删除活动会话每 4 秒读取完整历史的定时任务。初次恢复、切换到未缓存或已过期的会话、手动刷新和连接恢复路径继续按现有缓存策略工作。
2. 将 `threads.changed` 处理改为防抖刷新轻量会话列表元数据；比较活动会话的服务端更新时间与缓存更新时间，只有会话确实变化时才读取完整历史。新增其他会话不应重读未变化的活动会话。
3. 活动会话收到 `turn/started` 时不再提前读取整段历史。可解析的实时用户消息继续直接插入；缺少内容的用户消息事件保留一次历史回退读取。
4. `turn/completed` 继续完成流式消息并刷新会话元数据；只有排队消息需要核验送达时才读取完整历史。队列核验、歧义发送恢复、重连恢复和手动刷新保留完整读取。
5. 更新 `CHANGELOG.md`、`package.json`、FastAPI 版本和 Android `versionName`；本次属于 PATCH 性能修复，开发版本从 `0.8.0-dev.3` 升至 `0.8.0-dev.4`，Android `versionCode` 从 `110` 升至 `111`。
6. 运行前端生产构建与 `git diff --check`，不运行测试；创建本地 Git 提交，不推送 GitHub。

## 验收标准

- 页面空闲时不再每 4 秒请求完整活动会话历史。
- 新建或更新其他聊天只刷新会话列表元数据，不触发未变化活动会话的完整历史下载。
- 活动会话的用户消息和助手流式回复仍实时显示，完成通知仍正确收尾。
- 有待核验排队消息时仍读取服务端历史确认送达；重连、未缓存会话、手动刷新和必要的事件回退仍可读取完整历史。
- 前端生产构建成功，`git diff --check` 无输出，提交不包含已有的无关工作区改动。
