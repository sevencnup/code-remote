# 网页终端粘贴与字号同步

## 目标

修复桌面网页版终端剪贴板读取失败时弹出独立输入框的问题，并让终端字体与右侧文件树字号一致、随全局字体设置变化。

本次属于修复 / 体验优化（PATCH）：保留现有终端操作能力，改善粘贴回退和字体一致性；目标版本 `0.21.7-dev.5`，仅修改网页版，不改 Android 原生端。工作区中已有的历史 APK 保持原样，不纳入提交。

## 诊断

- “粘贴到终端”先调用浏览器剪贴板 API；读取失败时在所有设备上打开手动输入框。
- xterm 已允许浏览器处理 Ctrl/⌘+V 原生粘贴，因此桌面读取失败时可聚焦终端，让用户使用浏览器原生粘贴，无需额外输入框。
- 右侧文件树字号使用 `calc(14px + var(--mobile-font-offset))`，终端则固定为紧凑布局 12px、其他布局 13px，且没有响应全局字号调整。

## 实施步骤

1. 保留剪贴板 API 可用时的直接粘贴；桌面读取失败时关闭右键菜单、聚焦终端并提示使用 Ctrl/⌘+V，不显示独立输入框；触屏端保留现有手动粘贴兜底。
2. 将终端基础字号改为与文件树相同的 CSS 字号，并在全局字体设置、视口/设备布局变化时更新 xterm 字号及终端布局。
3. 添加回归测试，更新适用的版本记录；运行专项测试、完整测试、生产构建与 `git diff --check`。
4. 仅暂存本任务文件并创建本地提交，不推送 GitHub、不构建 APK。

## 验收标准

- 桌面剪贴板 API 可用时，点击粘贴按钮将剪贴板内容直接送入终端。
- 桌面剪贴板 API 不可用时，不显示独立粘贴输入框，终端重新获得焦点并提示 Ctrl/⌘+V。
- 触屏端原手动粘贴回退仍可用。
- 终端字号与文件树字号相同，并跟随全局字号设置和设备布局变化。
- 回归测试、生产构建与差异检查通过；本地提交中不包含工作区既有的其他修改。
