# 网页并发回复性能优化

## 需求与分类

两个并发窗口同时回复时，输入和滚动出现卡顿。本次属于修复 / PATCH：降低已有并发聊天的渲染开销，用户工作流保持兼容，目标版本为 `0.79.1-dev.1`。

## 已确认的开销

- 多个远程控制器在页面根组件中运行，任一窗口的流式更新都会重新执行所有窗口的渲染。
- 控制器返回值、窗口回调和缺省空数组在每次渲染中重新创建，使消息组件已有的 `memo` 缓存失效。
- 历史 Markdown 和已完成代码块被重复渲染，滚动同步还同时经过布局 effect、动画帧和尺寸观察器。

## 实施步骤

1. 用两个窗口和固定历史消息构造浏览器回归场景，记录流式更新时历史消息与相邻窗口的渲染次数。
2. 稳定远程控制器、排队消息、窗口回调和缺省集合的引用，为窗口建立有效的渲染边界。
3. 缓存未变化的消息正文与代码块，将流式滚动同步合并到每帧一次。
4. 验证双窗口流式更新、输入、手动滚动、窗口激活与消息选择；检查最终消息完整性。
5. 更新版本记录、执行生产构建与差异检查，清理临时验证脚本和进程，创建本地 Git 提交。

## 验收要求

- 一个窗口收到流式文本时，未变化的另一个窗口和历史消息不会重复解析正文。
- 两个窗口均持续显示回复；最终内容不丢失，切换窗口后的操作目标正确。
- 用户上滑后不会被新文本强制拉回底部，回到底部和切换聊天仍然正常。
- 记录验证结果；浏览器模拟结果与用户设备的实际表现分开说明。

## 实施与验证结果

已稳定控制器和队列的引用、窗口事件回调与缺省集合，启用窗口及未变化正文/代码块的渲染缓存。滚动尺寸读取通过动画帧合并；事件回调读取最近提交的控制器，避免缓存旧聊天目标。

浏览器模拟使用本机无界面 Chromium、1500 × 900 视口和真实页面组件，每个窗口保留 79 条历史消息及 1 条流式消息。远程连接被隔离，附件、队列等请求使用模拟响应，不向真实聊天发送消息。

| 场景 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 单窗口增加一段文字：历史消息重绘 | 158 次 | 0 次 |
| 单窗口增加一段文字：相邻窗口重绘 | 2 次 | 0 次 |
| 双窗口各更新 15 次：历史消息重绘 | 2370 次 | 0 次 |
| 双窗口各更新 15 次：Markdown 解析 | 2400 次 | 30 次 |

以下操作在同一浏览器场景通过：双窗口持续输出期间输入完整文本、激活另一窗口、手动上滑保持位置、加载更早消息保持原锚点、回到底部恢复最近 80 条消息、回复完成后显示完整内容及复制按钮、原窗口切换聊天后将选择题答案发送至新聊天、关闭并发窗口。浏览器没有未捕获异常。

`pnpm build`、消息窗口/选择题/连接生命周期相关的 6 项检查和 `git diff --check` 通过。临时浏览器脚本及服务在验证后清理。

以上数据说明重复渲染已消除，不代表已测得用户设备上的 CPU、内存或实际帧率；真实模型输出和网络延迟也不在此模拟范围内。
