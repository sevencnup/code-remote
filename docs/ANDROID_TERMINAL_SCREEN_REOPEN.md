# Android 终端关闭后恢复屏幕

## 目标与分类

同一聊天关闭并重新打开终端时，立即显示上次的终端屏幕，并继续连接原 tmux shell。修复键盘高度变化时终端缩小而丢掉命令和提示符的问题。已有终端能力不变，属于修复 / PATCH。最终 Android 版本 `0.62.0-dev.19`，`versionCode 343`。

## 现状与证据

- APP 每次打开终端都新建 `TerminalScreenBuffer`，关闭时释放显示控件；因此重连前画面为空。
- 有聊天 ID 时，后端 tmux 会话仍保留。独立临时会话实测：写入标记、关闭客户端、再以同一聊天 ID 连接，标记会重绘回来。
- 没有聊天 ID 的“新聊天”使用临时 shell，关闭时服务端会结束它；本次不把旧画面伪装成仍然存活的会话。
- 缩小终端行数时，原来的 `resize()` 从顶部复制，可能丢弃光标所在的命令和提示符。

## 步骤

1. 按连接与聊天 ID 缓存少量当前终端屏幕；同一聊天重开时先显示缓存，再接收 tmux 重绘。切换聊天或连接时不串屏。
2. 缩小行数时保留光标附近的可见内容和 tmux 状态行，并同步调整光标坐标。
3. 固定每次终端打开时的聊天 ID，阻止已经关闭的旧 WebSocket 回调写入新终端。
4. 更新版本记录，构建新 APK，设备可用时安装并核对关闭重开；保留旧包。
5. 检查差异，提交到本地 Git；不推 GitHub。

## 真机复核与补充

`0.62.0-dev.16` 已安装并在同一聊天里关闭、重开终端。重开后 `cd` 命令、工作目录提示符和光标仍在，后台 tmux 会话也接回；重连中曾短暂显示被隐藏的 tmux 状态行。为避免该闪现，缓存屏幕时同时保存其持久终端标记，并另建 `dev.17` 包，不覆盖 `dev.16`。

`dev.17` 真机快速重开仍捕获到状态行：tmux 在重新同步行数前将它短暂写到旧位置。显示层现在识别项目 tmux 状态文本并隐藏该行，不依赖它刚好位于最后一行；另建 `dev.18` 包，不覆盖旧包。

`dev.18` 真机重开后，原有命令和提示符可见，状态行未再出现。复核缩小行数时发现从底部固定复制仍可能裁掉靠上的光标行，因此改为以光标行选择保留窗口；另建并安装 `dev.19` 包，不覆盖旧包。

`dev.19` 真机复核：关闭后立即重开，在“正在连接电脑终端”阶段已显示旧命令；连接完成后内容仍在，状态行未显示。唤起键盘压缩终端高度后，命令与提示符仍可见。没有向用户终端发送测试命令。

## 验收

- 同一聊天重开终端立即看到上次当前屏幕，随后继续接收同一个 tmux shell 的输出。
- 其他聊天不会看到这个终端的内容；新聊天仍明确是临时终端。
- 键盘使终端变矮时，光标所在的命令与提示符不因屏幕复制方向而丢失。

范围：APP 内存只缓存最多 8 个聊天的当前屏幕；更早的滚屏历史没有加入屏幕缓存。APP 进程重启后，仍由后台 tmux 重绘当前屏幕。服务端会清理空闲 30 分钟或超出数量上限的会话，新聊天的临时 shell 则随连接关闭。
