# 消息发送回包与恢复稳定性开发文档

## 目标

修复消息发送后短暂显示、随后退回输入框的问题，降低旧会话与新会话之间的发送稳定性差异；已经获得送达回执的消息不得因 HTTP 回包中断被误撤回。

## 已确认的问题

- 请求函数直接返回 `response.json()`，没有在重试的 `try` 中等待正文读取；响应头已经收到后发生的断线绕过了网络重试。
- 首次继续旧会话必须调用恢复接口，该接口返回完整历史，但发送路径只需要确认恢复成功。大历史增加手机端回包读取失败的机会。
- 安全重试没有覆盖网关暂时返回的 502/504。
- 发送失败时仅依赖一次历史读取核对；HTTP 和历史回包都失败时，即使实时通道已确认送达，也会恢复草稿。
- 历史核对没有限定消息的新旧边界，部分缓存未包含的旧短消息可能被误认为本次已送达的消息。
- 发送结果晚于切换对话或实时完成事件时，可能覆盖当前对话的运行状态。

## 实施步骤

1. 先用可重复的断线模拟验证正文读取失败绕过重试，保留针对该故障的回归测试。
2. 将正文读取纳入重试范围；只读请求和带稳定请求 ID 的写请求允许有限次数重试网络错误及 502/504，明确的业务拒绝保持原样。
3. 为会话恢复增加可选的精简回包，发送路径只接收会话信息，旧客户端默认仍返回完整历史。
4. 通过请求 ID 接收精确的实时送达回执，阻止已确认消息被 HTTP 回包失败撤回；历史核对只接受已知消息之后的新消息，避免迟到的结果改变其他对话或重新激活已结束的轮次。
5. 验证正文中断、网关中断、业务拒绝、大历史恢复、实时回执和切换对话等场景；运行前端构建、后端测试及差异检查。
6. 更新版本记录，清理一次性测试脚本及临时进程，创建仅包含本次修复的本地 Git 提交。

## 验收标准

- 正文读取中断可按原请求 ID 重试，同一消息不会重复启动。
- 恢复旧会话的发送请求不再下载整段历史。
- 实时送达回执已确认的消息不会退回输入框；确实无法确认时仍保留草稿。
- 401、409、422 等业务拒绝不盲目重试。
- 迟到回包不串到其他对话，已完成的轮次不因迟到回包重新变为运行中。
- 不推送 GitHub，不中断现有 Codex 任务。

## 回滚

撤销本次请求重试、精简恢复回包和送达回执相关改动；保持现有请求 ID 去重功能。

## 验证结果

- 原实现的正文断流模拟失败；修复后 `pnpm test` 的 11 项回归测试通过。
- 后端单元测试共 32 项通过，覆盖精简恢复、兼容旧请求、并发去重、HTTP 请求取消和送达回执。
- 使用实际 React Hook 和 DOM 环境模拟的 14 个状态场景通过，覆盖迟到回包、跨对话切换、回执晚于 HTTP 失败、旧短消息误匹配和排队插话。
- `pnpm build` 和 `git diff --check` 通过。
- 当前网页开发服务已提供修复后的请求代码；运行中的 Python 后端需在当前任务结束后重启，才能启用精简恢复回包和实时送达回执。
