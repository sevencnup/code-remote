# 工作区文件预览语法着色开发文档

## 目标

为桌面端工作区文件只读预览增加按文件类型识别的语法着色，让代码、注释、字符串、关键字等更容易区分。Windows `.bat` / `.cmd` 脚本为重点验收场景。

## 设计边界

- 不改变文件预览接口、路径校验、只读能力、复制、行号和滚动行为。
- 使用共享依赖仓库已有的 `highlight.js`；常见扩展名走轻量语言模块，未知类型才按需加载全量语言包，避免增加聊天页首屏资源。
- 已知文件名和扩展名优先精确选择语法；未知类型按需加载 `highlight.js` 全量语法进行自动识别，不要求每种新扩展名都先登记映射。
- 自动识别必须通过置信度门槛；普通文本、日志和无法可靠判断的内容保持原样。Highlight.js 本身不支持的语言仍按纯文本显示。
- 将高亮器输出解析为 React 文本和带类名的片段，不把工作区文件内容作为 HTML 注入页面。
- 颜色在深色、浅色、暖色和自定义主题下均须有足够对比度。
- 手机端继续沿用现有文件面板行为，不增加预览视图。

## 实施步骤

1. 将 `highlight.js` 声明为项目依赖，复用共享 store 中已有版本；不在项目目录内单独安装依赖。
2. 新增文件名/扩展名到语言的映射和轻量语言注册，支持 Windows 批处理、JavaScript/TypeScript、Markdown、JSON、Python、Shell、HTML/XML、CSS、Java/Kotlin/Groovy/Gradle、C/C++/C#、Go、Rust、PowerShell、YAML、SQL 等常见类型。
3. 对未映射类型按需加载全量语言包，在文件开头的有限样本内自动识别；明确的纯文本扩展名跳过自动识别，其他文本只有达到置信度门槛才着色，再用识别出的语法处理全文。
4. 将高亮结果安全转换成逐行 React token，保持换行、空行、原始文本、现有行号和水平滚动。
5. 为四种主题补充高亮 token 配色。
6. 更新版本记录，运行 TypeScript/Vite 构建、批处理和未知扩展名自动识别样例检查、普通文本回退检查及 `git diff --check`，然后创建本地提交，不推送远端。

## 验收标准

- `.bat` / `.cmd` 文件中的 `rem` 注释、命令/关键字、字符串等可以区分着色。
- `.md` / `.markdown` 文件中的标题、列表、强调文本、行内代码和链接可以区分着色。
- 常见代码文件和可自动识别的未知扩展名有语法颜色；纯文本、日志和低置信度内容不被误判。
- 新增到 Highlight.js 的语言无需单独增加扩展名映射，即可通过未知类型自动识别。
- 高亮前后的行数一致，行号连续；长行仍可横向滚动，空行和文件末尾换行显示正常。
- 文件内容不会被解释为 HTML，原有复制内容保持不变。
- 深色、浅色、暖色、自定义主题下文字清晰；TypeScript/Vite 构建和差异检查通过。
