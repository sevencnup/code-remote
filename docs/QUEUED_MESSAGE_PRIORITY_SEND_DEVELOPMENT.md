# 手动优先发送任意排队消息

## 目标

回复结束或失败后，用户可以从队列中选择任意一条带单独模型/思考设置的消息立即开始新一轮。未选择的消息留在队列中，之后仍按原有顺序自动发送。

## 原因

- 带单独模型或思考设置的排队消息必须启动新 turn，不能通过 `turn/steer` 插入正在运行的 turn。
- 前端把这类消息的“立即发送”限制为队首，后端 idle-only 接口也强制队首，因此用户在确认异常结束的 turn 后无法选择后面的消息。
- 自动发送应继续保持 FIFO；允许越过队首只用于用户明确点击某一条的“立即发送”。

## 实施步骤

1. 空闲时允许任意未核对的队列项点击“立即发送”；回复进行中仍禁用带单独模型/思考设置的消息。
2. idle-only 手动发送接口接受指定的队列项，不要求它必须是队首；保留运行状态校验和每会话互斥锁。
3. 成功发送后只移除被选消息，其余队列保持原顺序，并展示优先发送说明。
4. 更新开发版本和简短版本记录，执行生产构建、Python 语法检查及差异检查；不新增或运行测试。
5. 创建本地 Git 提交，不推送 GitHub，不重启服务。

## 验收标准

- 对话空闲时，任意一条有模型/思考设置的待发消息均可手动优先发送。
- 发送后，该消息按自身设置启动新 turn，其他消息保留且维持原有相对顺序。
- 对话仍在回复时，带单独模型/思考设置的队列项不能绕过当前 turn。
- 自动队列推进仍按 FIFO，异常结束后的安全确认屏障仍然有效。
