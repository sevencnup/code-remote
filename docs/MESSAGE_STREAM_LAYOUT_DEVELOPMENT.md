# 消息流遗留分隔线与布局开发文档

## 目标

移除聊天回复末尾可能残留的旧版计时分隔线，避免消息流根节点被多个状态节点和聊天节点直接撑开；保留每一条真实聊天记录的独立语义与顺序。

## 已确认的根因

- 截图中的横线宽度与旧版 `.turn-duration` 的 840px 容器完全一致。该组件已从当前源码删除，但长期打开、未收到热更新的浏览器页仍可能保留旧 DOM 和样式。
- DevTools 中的紫色斜纹是 `message-stream` 的 `gap` 可视化，不是页面被切成多个页面；聊天记录、审批和运行状态此前都作为该节点的直接子项。

## 实施步骤

1. 将消息流的直接内容收敛到一个内容栈，统一管理消息之间的较小间距。
2. 为旧版计时行、流式光标和意外的消息流分隔线提供兼容隐藏规则，确保热更新后的样式能清除遗留 DOM 的横线。
3. 保持每条聊天记录、文件变更卡片、审批卡片和运行状态的原有顺序，不跨轮合并对话。
4. 将回到底部按钮放到聊天滚动区与输入框之间的独立布局行，避免覆盖文件变更卡片及其行内操作。
5. 更新版本记录，执行构建和差异检查，并创建本地 Git 提交。

## 验收标准

- 回复下方不再出现 840px 宽的深色横线。
- 选择 `message-stream` 时，消息内容通过单一内容栈排列，间距更紧凑。
- 历史消息、运行状态、审批和文件变更仍按原顺序显示。
- 回到底部按钮使用独立布局行，不与文件变更卡片的可点击操作重叠。
- `pnpm --filter codex-remote build` 与 `git diff --check` 成功。
