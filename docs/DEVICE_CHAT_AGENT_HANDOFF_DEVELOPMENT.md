# 设备群聊 Codex 自动接力开发文档

## 目标

用户在群聊中点名一台设备后，该设备上的 Codex 能在回复末尾明确点名另一台设备，把上下文和处理权交给它。所有消息继续同步到群聊，用户能旁观和插话；设备服务常驻监听，Codex 在每一轮之间保持空闲。

## 方案约定

- 保留现有行为：只有用户明确点名的设备启动 Codex。
- Codex 只在回复末尾独占一行写出 `@设备名` 时发起设备间接力；提到设备但没有独占一行不触发，避免误路由。
- 回复先照常流式显示；只有 Codex turn 完成后才解析接力目标并触发下一台设备，避免流式更新重复启动任务。
- 复用现有 `target_id` / `target_name` 消息字段及每房间 Codex thread，不新增数据库表或 API。
- 自动接力最多 4 次。超过上限时保留已完成回复并显示停止提示；用户再次点名设备会开启新一轮任务。
- 不自动唤醒未被点名的所有设备，也不对自己的消息响应，避免自动循环。
- 目标设备需要运行包含自动接力功能的 Code Remote 版本；旧版仍能同步显示群消息，但不会执行 assistant 接力。
- 向 Codex 提供在线成员名称和最近群聊上下文，并告知仅在确实需要其他设备处理时使用接力格式。

## 实施步骤

1. 在 `device_chat.py` 添加可单测的明确点名解析逻辑，并扩展本机群消息调度：用户消息仍只触发被点名节点；远端 Codex 回复若点名本机则触发本机。
2. 在共享 assistant 消息最终写入时设置接收设备和接力根消息/深度元数据；更新同一流式消息时只在最终目标确定后调度，依赖现有 job 主键保证幂等。
3. 在 Codex 提示中说明房间成员和接力格式；达到自动接力上限时展示明确状态消息，并在群聊标题显示“群消息监听中”。
4. 添加自动化测试覆盖：明确且唯一的设备点名、普通文本不路由、自己不响应自己的消息、接力上限拒绝继续及上限内跨设备消息会被调度。
5. 将功能按新增能力归类为 MINOR；项目当前为 `0.69.12-dev.1`，目标版本递增至 `0.70.0-dev.1`，更新 `package.json`、应用服务版本、Android `versionName` 和 `CHANGELOG.md`。不构建安装包，因此不修改 Android `versionCode`。
6. 运行相关 Python 测试、前端生产构建与 `git diff --check`，检查差异后仅暂存本次文件并本地提交；不推送 GitHub。

## 验收标准

- 用户点名 Windows 后，Windows 的 Codex 回复同步给 Linux 与用户。
- Windows 的 Codex 在回复末尾单独写 `@Linux` 时，Linux 自动收到完整上下文并启动下一轮 Codex；无需用户复制或再次转发。
- Linux 回复中提到 Windows 但未使用独占点名行时，不会意外触发 Windows。
- 同一 assistant 消息的流式更新不会重复调度接力任务；重连/重放不会重复执行同一条消息。
- 自动接力达到 4 次后停止并显示提示；用户重新点名设备可开启新一轮。
- 没有新消息时设备进程保持监听，Codex 不会一直显示生成中。
