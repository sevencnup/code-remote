# 排队消息恢复开发文档

## 目标

让用户在 Codex 回复期间排队的消息在移动端切到后台、浏览器恢复、页面重新加载或开发热更新后仍保留在对应聊天中，并在原回复结束后继续按原顺序发送。

## 已确认原因

- 输入框普通草稿已按聊天写入 `localStorage`，但“已排队”消息只保存在 `useCodexRemote` 的 React 内存状态。
- 移动浏览器恢复页面时一旦重新挂载前端，内存队列会被清空，因此排队卡片和待发内容一起消失。
- 若 Codex 在页面离开期间已经完成，恢复后的客户端还需要安全地继续处理尚未发送的队列。

## 实施步骤

1. 为排队消息增加受校验的本地持久化格式，按 thread ID 保存、恢复，并在移除或发送成功时同步删除。
2. 保护本地存储容量：只恢复结构合法且大小受控的数据，存储不可用时保持当前会话行为而不影响发送。
3. 在活动对话的历史状态确认为空闲、连接可用且历史加载完成后，恢复自动发送队列；运行中的 turn 不会重复启动。
4. 保持队列顺序、模型/推理/授权偏好、文本、图片和文档附件信息不变。
5. 更新版本记录，执行构建、后端测试和差异检查后创建本地 Git 提交。

## 验收标准

- 回复期间排队的文本在页面重新加载后仍显示在原聊天的“已排队”区域。
- Codex 仍在运行时不重复发送；完成后按原顺序自动继续。
- 手动移除、立即发送或发送成功后，恢复页面不会再显示已处理的队列项。
- 损坏、超大或过期的本地数据不会造成页面加载失败。
- `pnpm build`、后端单元测试和 `git diff --check` 均通过。
