# 网页排队消息运行中插队修复

## 问题与分类

本次属于修复 / PATCH：恢复已有 Codex 排队消息的运行中插队能力，目标版本 `0.76.2-dev.1`。

网页把任何保存了模型或思考等级的排队消息都当作必须新开一轮，从而禁用运行中的发送按钮，并调用只允许空闲发送的接口。普通消息也会保存这些设置，因此现有插队能力被普遍挡住。

## 实施步骤

1. 区分用户点击时的两种意图：运行中的 Codex 显示“插队”，空闲时显示“发送”。按钮调用显式携带意图，避免点击后状态变化导致把普通发送意外变成插队。
2. 插队复用服务端 `send-now`，在当前轮次追加消息；排队项保存的模型和思考等级只在新轮次生效，界面明确说明这一点。空闲发送继续使用 `start-if-idle`，由服务端确认状态并保留设置。
3. Claude 运行中继续排队，明确提示当前接入不支持运行中插入消息；编辑、送达待核对及正在提交时继续锁定按钮。
4. 用隔离的共享队列检查覆盖插队不暂停且只发送一次、保留其余队列顺序、空闲发送保留模型设置，以及空闲发送遇到新活动轮次时不插队。
5. 完成相关检查与网页构建、同步应用版本和简短版本记录，只提交本地 Git。

## 验收标准

- 带模型或思考等级的 Codex 排队消息在回复中可点击“插队”，无需暂停。
- 插队沿用当前轮次设置，普通排队和空闲发送继续使用消息保存的设置。
- 新行为复用现有后端接口，网页构建后刷新即可加载。
