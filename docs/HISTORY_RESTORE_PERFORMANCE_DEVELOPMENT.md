# 刷新恢复聊天性能开发文档

## 目标

缩短浏览器刷新后恢复最近聊天的等待时间，让当前会话优先恢复，并在网络读取完整历史期间先展示浏览器缓存内容。

## 根因

- 页面初始化时先等待对话列表和模型列表请求，再调用 `thread/read` 读取当前聊天。
- `thread/read` 返回完整会话历史，历史较长时 JSON 传输和解析会占用较长时间。
- 原实现只保存最近的 `threadId`，没有缓存可立即展示的聊天内容。

## 设计边界

- 服务器返回的完整历史仍是最终数据，浏览器缓存只用于首屏快速展示，网络恢复成功后立即覆盖。
- 只缓存最近打开会话的文本消息和基本会话信息，不缓存图片数据，避免将大图片写入浏览器存储。
- 缓存仅保存在当前浏览器，读取失败、过期或存储空间不足时不影响正常聊天。
- 不改变 Codex App Server 协议和历史数据格式。

## 实施步骤

1. 增加最近会话文本消息缓存，并在页面初始化时恢复缓存内容。
2. 调整初始化顺序，让当前会话恢复与对话列表、模型列表并行执行。
3. 网络读取成功后刷新界面并更新缓存；继续保留历史读取期间的加载状态和错误处理。
4. 更新版本记录，执行前端构建、后端测试和差异检查，并创建本地 Git 提交。

## 验收标准

- 刷新页面时，已有缓存的最近聊天内容可以先显示，不必等待列表和模型请求完成。
- 网络恢复成功后，缓存内容被服务器最新历史替换。
- 历史较长、缓存损坏或浏览器禁用存储时，仍能正常读取聊天。
- `pnpm build`、后端单元测试成功，`git diff --check` 无输出。
