# 已绑定普通聊天漏同步到设备群

## 问题与分类

在线服务已经升级到 0.71.3，但群消息只由群聊任务的临时订阅发布。该轮结束后，在绑定的普通聊天里继续发送消息和回复末尾的设备点名都没有进入群同步。属于修复 / PATCH，目标版本 0.71.4-dev.1。

## 实施步骤

1. 为当前房间绑定的 Codex 聊天增加服务端持续监听，订阅即时通知，并通过历史版本检查补齐外部客户端消息及断线期间的遗漏。
2. 使用房间、会话、轮次生成稳定消息编号，持久化同步状态；群聊自行发起的轮次独立标记，避免重复消息、自触发和接力循环。
3. 新绑定从绑定时刻同步，并接续选中聊天仍在进行的回复；旧绑定通过首次群聊任务确定同步起点，恢复此后的普通聊天消息。历史补齐只恢复可见记录；未来完成的回复末尾准确点名在线设备时接力一次。
4. 保留流式更新，处理重启、切换绑定、退出房间和订阅释放；修正完成后仍显示“正在处理”的群任务状态。
5. 增加针对普通对话同步、重启补齐、群任务去重、点名只触发一次、绑定隔离的回归验证。运行相关测试、编译和构建检查。
6. 更新版本与简短记录、本地提交；沿用本次会话已授权的 Gitea 更新及安全空闲重启，核对在线版本和截图对应消息是否已进入群记录。

## 验收

- 已绑定聊天中新增的用户消息、助手回复和后续轮次可以进入群，不依赖网页停留在群模式。
- 普通聊天中新完成回复的准确设备点名可以接力；历史补齐不会重新执行旧指令。
- 重启不会丢失同步进度，不重复已由群任务发布的消息；其他未绑定聊天不会被同步。
- 退出或切换绑定时不会将旧聊天异步读取结果发到新房间。

## 验证记录

- 设备群聊原有回归与本次持续同步回归共 37 项通过，覆盖流式更新、点名一次接力、重启去重、历史补齐、绑定隔离、同秒新轮次及超过单页历史的恢复。
- 使用真实绑定聊天历史进行隔离恢复，得到 8 条遗漏消息，包含截图中 11:44、11:45 的两问两答；未生成历史自动接力任务，临时目录已清理。
- TypeScript 检查与 Web 生产构建通过。仅更新 Android versionName，不生成安装包，不递增 versionCode。
- 当前维护对话本身运行在待更新服务内；使用独立 systemd 临时单元等待空闲后重启，并自动核对新版本、健康状态和截图对应消息。
