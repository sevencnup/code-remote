# 删除聊天后保留当前模式

## 目标与分类

修复 / PATCH：删除 Claude Code 聊天后继续使用 Claude Code，保持现有聊天管理行为一致；没有新增用户任务。同一测试目标版本递增为 `0.15.0-dev.9`。

## 原因

页面从当前聊天的 `engine` 判断模式。删除当前聊天后该对象变为空，界面和隐式创建聊天都默认使用 Codex；多窗口下删除当前聊天还会关闭窗口，将焦点移到可能属于另一模式的窗口。

## 实施步骤

1. 每个聊天控制器同时保存当前聊天和模式：选择、恢复、创建聊天时更新模式；删除聊天时保留模式。只有聊天 ID 的恢复阶段依据已有 `claude:` ID 前缀识别 Claude Code。
2. 将窗口模式保存到已有窗口布局中，兼容旧数据，使删除后的空窗口刷新后仍使用相同模式。
3. 顶部切换按钮、侧边栏、欢迎页、输入偏好和新建聊天使用窗口模式；空窗口直接发送消息时也使用该模式。
4. 删除当前窗口的聊天时保留空窗口和焦点，避免多窗口之间意外切换模式；删除其他窗口的聊天不改变当前选中窗口。
5. 复查单窗口、多窗口、服务端删除通知、空窗口发送和刷新恢复的调用路径，执行生产构建。不新增或运行测试，不重启现有服务。
6. 同步版本声明、记录简短更新描述并创建本地提交。保留已有 APK 开发文档修改。
