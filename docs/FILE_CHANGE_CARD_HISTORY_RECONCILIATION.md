# 文件改动卡片历史归属修复

## 目标

确保每张“本次已编辑”卡片只显示在所属对话轮次的最后一条消息后面，切换或刷新聊天后不会把失去消息归属的旧缓存卡片集中堆到对话底部。

## 原因

- 完整 `thread/read` 返回后，前端把历史中的文件改动与浏览器旧缓存做只增不删的合并。
- 当最新历史不再包含旧缓存中的某个轮次时，该轮次的文件卡仍会残留。
- 消息流找不到这些轮次对应的消息后，会把所有未归属卡片统一渲染在底部。

## 实施步骤

1. 以完整历史返回的轮次集合为准重建文件改动记录。
2. 回复仍在运行时，只额外保留当前活动轮次尚未进入历史快照的实时文件改动。
3. 移除消息流底部集中渲染未归属文件卡片的兜底逻辑。
4. 更新开发版本和版本记录并执行构建检查。

## 验收标准

- 每个已完成轮次的文件卡跟随该轮最后一条可见消息。
- 旧缓存里不存在于最新历史的轮次不会继续显示文件卡。
- 正在回复的轮次仍可在输入区上方显示实时文件改动摘要。
- 切换聊天或刷新页面后不会在底部出现连续堆叠的无归属卡片。
