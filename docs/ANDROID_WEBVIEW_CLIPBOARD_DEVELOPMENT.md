# 网页与 Android WebView 文字复制开发文档

## 目标

让网页和 Android 安装版都能长按选中文字并显示系统复制菜单，同时让应用内消息和代码块的“复制”按钮写入系统剪贴板。

## 根因与方案

页面曾对整个 `document` 拦截 `contextmenu` 并调用 `preventDefault()`，因此浏览器和 Android WebView 都无法显示文字选择后的系统菜单。移除全局拦截，保留文件和对话列表上已有的局部自定义菜单处理。安装版通过局域网 HTTP 页面运行在 Android WebView 中，网页 Clipboard API 可能不可用；由 Android 原生桥接提供只写剪贴板方法，普通浏览器继续使用网页剪贴板和兼容回退。

## 实施步骤

1. 移除全局 `contextmenu` 拦截，同时保留已有的局部自定义菜单。
2. 在 Android JavaScript 桥接中加入系统剪贴板写入方法，不提供读取剪贴板的能力。
3. 扩展网页的 Android 桥接类型，并让消息与代码块复制优先使用原生方法，保留浏览器回退。
4. 更新版本记录，执行网页生产构建和差异检查，并提交本地 Git 仓库；原生 APK 版本无需变化，因为安装版加载电脑提供的网页资源。

## 验收标准

- 网页和 Android 安装版长按聊天文字后，系统选择菜单可以显示“复制”。
- Android 安装版的消息或代码块复制按钮能写入系统剪贴板，普通浏览器仍使用网页剪贴板。
- 网页生产构建成功，`git diff --check` 无输出。
