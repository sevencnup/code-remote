# 网页排队消息调整发送顺序

本次属于**新增功能 / MINOR**：用户可以调整原本只能按入队先后发送的消息顺序。目标版本 `0.84.0-dev.1`。

## 现状与边界

- 电脑端 SQLite 队列是跨设备的权威顺序，自动发送从队首取消息；只调整网页显示顺序不能改变发送顺序。
- 网页输入框里的队列支持编辑、立即发送和删除。本次在每条消息上增加上移、下移按钮；第一条不能上移，最后一条不能下移。
- 正在提交、发送、送达待核对或编辑中的消息不能参与交换，防止越过已有的送达确认和编辑暂停保护。定时消息移动后仍按队列位置和设定时间发送，排在后面的消息继续等待。
- Android 暂不增加排序按钮，但它读取同一服务端队列，会显示调整后的顺序。

## 实施步骤

1. 为已有队列增加持久化排序字段，迁移时保留原顺序；提供按当前相邻消息 ID 校验的原子交换操作，并与自动发送共用每会话锁。
2. 增加受现有配对鉴权保护的队列移动接口，成功后广播队列变化；跨设备和服务重启后保持新顺序。
3. 网页队列加上下箭头，边界与不可移动状态禁用；请求失败时刷新权威队列并显示错误，移动期间阻止重复点击。移动端保证按钮可点且消息正文有空间。
4. 更新版本和简短版本记录，执行网页构建、Python 语法检查和差异检查；不新增或运行测试。
5. 只提交本地仓库，不推送 GitHub，不生成 Android 安装包。

## 验收条件

- 连续点击上下箭头可按相邻项改变顺序；边界箭头不可点。
- 实际自动发送、其它设备读取及服务重启后的队列顺序与网页显示一致。
- 并发发送或其它设备改动队列时，不会移动错误的消息或绕过送达确认。

## 完成记录

- 服务端新增持久排序字段、相邻交换接口及队列变更广播；自动发送继续按服务端队首推进。
- 网页队列显示上下箭头，首尾与不可移动状态禁用；手机宽度下将操作放到第二行，避免压缩消息正文。
- TypeScript 编译、Vite 生产构建和 Python 语法检查通过；同步 Web、服务端和 Android `versionName` 为 `0.84.0-dev.1`，未生成 Android 安装包，`versionCode` 保持 `372`。
- 当前命令环境没有 systemd 总线，无法重启正在提供服务的宿主机后端；新接口需要宿主机后端加载本次代码后生效。
