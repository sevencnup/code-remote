# 设备群聊复用现有聊天工作区

## 目标与版本

修复 / PATCH：现有设备群聊虽可在主区域打开，但仍重复实现标题、消息列表及输入框，操作体验与普通聊天分裂。目标版本 `0.68.1-dev.2`。版本记录只写「设备群聊复用现有聊天工作区」。

## 验收行为

- 左侧栏切换到设备群聊后，仍使用普通聊天的标题栏、消息滚动区和输入组件；选择普通聊天可返回。
- 群聊消息保留发言设备、Codex 身份、时间、点名对象和发送状态。
- 现有输入框发送到群聊服务；可选择目标设备；房间创建、加入、成员、邀请码和退出在辅助区域完成。
- 桌面和移动端均可使用，普通聊天行为不受影响。

## 开发步骤

1. 拆分设备群聊的数据控制与房间管理视图，不再渲染独立的聊天标题、消息区和输入框。
2. 在现有聊天工作区接入群聊消息及发送，复用现有输入组件；房间管理置于辅助面板。
3. 调整切换、窄屏与返回行为；更新版本及简要版本记录。
4. 类型检查、构建、关键测试、差异检查；本地提交。

## 验证结果

- TypeScript 检查、Vite 生产构建和 `git diff --check` 通过；本机 4173 服务已能返回最新构建资源。
- 前端测试 165 项通过 160 项。其余 5 项为修改前已有的移动端布局断言和主题变量断言失败。
- 外层 pnpm workspace 缺少 `@agentforge/protocol`，因此直接使用项目已有的本地 `tsc`、`vite` 和 Node 测试命令。
