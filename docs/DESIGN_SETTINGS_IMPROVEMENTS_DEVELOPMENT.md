# 设计设置与预览状态修复开发文档

## 目标

修复关闭设置页后旧文件预览自动重新打开的问题；在设置页增加全局字体大小调节；移除白色主题中点击控件后残留的蓝色外框。

## 问题与边界

- 从聊天文件改动卡片发出的预览请求保存在页面父组件中。设置页打开时文件树组件会卸载，退出设置后组件重新挂载并再次消费旧请求，因此旧预览被重新打开。
- 预览请求应是一次性事件；成功交给文件预览组件或进入设置页后立即清除，不影响用户从文件树和文件改动卡片继续打开新预览。
- 字体大小作为当前浏览器的全局显示偏好，适用于白色、黑色、暖色和自定义主题，并覆盖聊天、输入框、侧栏、文件区与设置页；保留移动端现有的紧凑字号修正。
- 字体偏好沿用主题设置的本地存储，旧数据缺少该字段时使用标准字号。
- 白色主题取消控件点击产生的蓝色外框和输入框蓝色外发光；主题现有边框、悬停和选中状态继续用于区分控件。

## 实施步骤

1. 在设置入口和文件预览打开回调中消费并清空父组件的预览请求，阻止文件树重新挂载时执行旧请求。
2. 扩展主题偏好模型，加入有范围限制的字体大小调整值，并生成全局字号 CSS 变量。
3. 在设置页增加独立的“显示”卡片和字体大小滑块，修改后即时预览并持久化。
4. 调整移动端字号变量，让设备紧凑偏移与用户设置叠加。
5. 为白色主题覆盖全局焦点外框和输入框聚焦外发光。
6. 更新内部测试版本与版本记录，执行生产构建和差异检查，创建本地 Git 提交。

## 验收标准

- 打开并关闭任一文件预览后，再进入和退出设置页，不会自动重新打开旧文件。
- 从文件树或文件改动卡片点击新文件时仍能正常打开对应预览。
- 所有主题下都能调节字体大小，聊天、输入框、侧栏、文件区与设置页立即同步变化。
- 刷新页面后字体大小保持；已有主题偏好可以正常读取并使用标准字号。
- 移动端保留原有紧凑字号基线，并叠加用户选择的调整值。
- 白色主题点击输入框、按钮和设置控件后不出现蓝色外框或蓝色外发光。
- 生产构建成功，`git diff --check` 无输出。
