# 设备群聊共用聊天控件与本机文件树开发文档

## 目标和分类

群聊继续在现有聊天页面显示，使输入框可选择发送目标、Codex 模型和思考等级，并恢复右侧文件树。设置必须作用于实际执行消息的设备；文件树必须指向当前网页连接的设备与群聊本机线程。用户因此能在群聊中完成原先无法完成的模型选择与文件浏览，分类为新增功能（MINOR），目标版本 `0.71.0-dev.1`。

## 行为约定

- 群聊仍使用现有消息流、输入框和工作区组件，`@设备` 是输入框内并列的目标选择，而非替代模型设置。
- 群聊模型和思考等级属于群聊草稿，不改普通聊天的偏好；发送时随用户消息传给被点名设备的下一轮 Codex。没有点名时只同步文字，不启动 Codex，也不应用模型设置。
- 模型列表来自当前连接设备。被点名设备不支持指定模型或思考等级时，在群里显示执行错误；默认选项使用目标设备自己的默认值。
- 授权由执行设备的本机设置控制，远端消息不得修改它。输入区清楚标明这一点；本机目标可使用普通聊天的本机授权设置。
- 右侧文件树显示当前网页连接设备的工作区。绑定目录只作用于本机群聊线程；若群聊还没有本机线程，先创建并绑定。文件预览和终端操作也留在本机，不能暗示是在远端设备上操作。
- 附件、暂停、排队等依赖普通聊天独立 turn 协议的功能，需要逐项检查。任何未接通的控件不可假装已生效；跨设备文件传输和远端文件树另行设计。
- 文本与源码文件的提取内容可作为群消息发送，上限沿用 12000 字符；图片、PDF 原件和表格原件暂不提供跨设备附件传输，并在界面显示原因。群聊审批只在执行设备的本机网页显示，用户可在那里允许或拒绝。

## 开发步骤

1. 扩展群聊消息与客户端类型，校验、存储并转发模型和思考等级；目标设备执行 turn 时传入这两个参数，错误回显到群聊。
2. 让群聊输入框并列显示目标、模型和思考菜单，使用独立于普通聊天的群聊偏好；处理默认选项和不同模型的思考等级。
3. 恢复右侧 `WorkspaceExplorer` 和普通布局，按群聊本机线程绑定工作目录，保证文件树操作不会落入当前普通聊天线程。
4. 检查附件与其他控件的真实后端能力，补齐可直接复用的功能，明确跨设备边界。
5. 更新版本描述与版本号；运行针对消息传递和本机线程绑定的测试、前端构建及差异检查，然后本地提交。只在用户明确要求时推送远端。

## 验收

- 在 Linux 页面点名 Windows 时可选模型/思考，Windows 收到的群聊消息携带设置，下一轮 Codex 按设置运行；不支持的值在群里显示错误。
- 取消点名后消息只同步。普通聊天的模型选择不受群聊偏好影响。
- 群聊右侧文件树显示当前连接设备的本机目录，绑定目录不会更改普通聊天线程；无本机群聊线程时可建立后绑定。
- 群聊与普通聊天保持同一聊天页；未实现的远端文件访问不显示成可用的本机文件操作。
