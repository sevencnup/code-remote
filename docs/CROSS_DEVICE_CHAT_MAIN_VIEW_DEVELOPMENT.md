# 跨设备群聊接入主聊天页

## 目标与分类

修复 / PATCH。设备群聊已有创建、加入、同步和点名 Codex 能力，但独立弹窗割裂了聊天操作，也无法沿用主聊天页的整体布局。将设备群聊改为主聊天区中的一种模式，用户从左侧边栏切换进入；创建或加入房间后继续在该页面对话。

- 目标版本：`0.68.1-dev.1`
- 版本记录：`将设备群聊接入主聊天页`
- 不改变设备群聊服务端协议、房间数据和每台设备的群聊专属 Codex 会话。

## 交互要求

- 左侧边栏的“设备群聊”入口切换主聊天区到设备群聊模式，不再打开遮挡页面的独立弹窗。
- 群聊模式在主聊天区显示房间创建/加入流程，成功后显示成员、共享消息、接收设备选择、消息输入框及房间管理操作。
- 创建或加入房间后留在群聊模式；选择普通聊天后回到普通聊天页。
- 群聊模式下隐藏普通聊天的工作区文件面板和 Codex/Claude 输入框，避免误把消息发到本机普通会话。
- 保留当前消息同步、点名设备触发本机 Codex、邀请码复制、成员在线状态和退出/解散流程。
- 兼容桌面、窄屏和移动端，并沿用当前主工作区的布局习惯。

## 开发步骤

1. 将设备群聊状态视图由 modal 改为可嵌入主工作区的页面组件。
2. 将侧栏设备群聊入口接入页面模式切换，并确保返回普通聊天选择时退出群聊模式。
3. 调整工作区网格、消息区和窄屏布局，使群聊页占用普通聊天主区域。
4. 更新版本号和版本记录，执行前端类型检查、生产构建及相关群聊测试。

## 验收

- 侧栏进入设备群聊后没有独立遮罩弹窗，普通聊天侧栏仍可见。
- 可在主聊天区创建房间或加入现有房间，并在同一页面发送同步消息及点名设备。
- 切回普通聊天后原有聊天页面、输入框及工作区正常显示。
- 移动端下群聊消息区和输入框可用，页面不会横向溢出。
- TypeScript 检查、Vite 生产构建和 `git diff --check` 通过。
- 现有前端测试 165 项中 160 项通过，5 项针对既有移动端样式断言和主题变量断言失败；没有设备群聊专用自动化测试。`pnpm test` 还被外层 workspace 缺失 `@agentforge/protocol` 阻断，因此使用 `node --test tests/*.test.mjs` 直接执行。
