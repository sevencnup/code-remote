# 自定义主题背景图片开发文档

## 目标

在设置里的“自定义主题”中增加本地背景图片选择、预览和清除功能，并让图片与现有背景颜色、全局背景透明度和字体颜色设置一起生效。

## 设计边界

- 图片仅保存在当前浏览器的 `localStorage`，不上传后端，不对局域网公开。
- 只接受常见图片格式，并限制文件大小，避免浏览器存储和渲染被超大文件拖慢。
- 自定义主题没有图片时继续使用背景颜色；清除图片后恢复纯颜色背景。
- 背景图片和背景颜色共用独立的全局背景层，由透明度设置统一淡化；侧栏、设置面板等界面模块使用低透明度的背景色玻璃层，在保持可读性的同时让全局背景能透出。

## 实施步骤

1. 扩展主题偏好模型和本地存储读写，兼容已有主题配置。
2. 在自定义主题设置中增加图片选择、预览、清除和文件校验。
3. 将图片作为 CSS 背景应用到独立背景层，通过该层的 opacity 控制全局透明度，并增加可读性遮罩及移动端覆盖规则。
4. 更新版本记录，执行前端构建、后端测试和差异检查，并创建本地 Git 提交。

## 验收标准

- 自定义主题可以选择图片并立即预览背景。
- 调整背景透明度会同时淡化全局背景图片/颜色，不会改变设置面板或侧栏模块的透明度。
- 刷新页面后图片仍能恢复显示。
- 非图片文件或超过限制的图片会提示错误，不会破坏原有主题。
- 清除图片后恢复自定义背景颜色。
- `pnpm build`、后端单元测试成功，`git diff --check` 无输出。

## 全局背景透出修复（0.0.170）

### 根因

背景层本来挂在整个 `.remote-shell` 上，但侧栏、设置页和文件面板使用接近不透明的白色 `88%` 面板底色，并叠加 `18px` 模糊；移动端打开的文件区还直接用纯背景色覆盖。因此背景图在聊天透明区可见，在其他区域被面板遮住。

### 实施步骤

1. 将主要面板底色改为由自定义背景颜色着色的低透明度玻璃层，减弱模糊，让全局背景在侧栏、设置页和文件区都清晰可见。
2. 将移动端文件区从纯色覆盖改为同一玻璃层，避免只显示背景色、不显示背景图片。
3. 设置卡片改用面板玻璃层；保留代码预览、按钮等小范围高对比控件背景，避免牺牲内容可读性。
4. 更新版本记录，执行生产构建和差异检查；不新增或运行测试、不重启服务，按用户明确要求创建本地提交并推送当前分支。

### 验收标准

- 背景图片或颜色在聊天区、侧栏、设置页、文件树和文件预览的面板后方均可见。
- 调节背景透明度只改变全局背景图层，不改变面板玻璃层本身的透明度。
- 移动端展开文件树时仍能看到同一全局背景图。
- 消息文字、设置控件和代码预览保持可读。
