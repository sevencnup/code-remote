# 设备群聊提示词精简开发文档

## 问题与分类

设备群聊每次调用 Codex 都将最近 24 条群消息和当前消息一起写入所选聊天。该聊天本身已有前几轮上下文，重复历史使消息越聊越长；跨设备自动接力时，对方回复已作为当前消息传入，再附整段群历史会进一步重复。较长的当前消息在普通聊天中也占据大量可见空间。

本次归类为修复 / PATCH：精简已有群聊的输入和显示，群聊能完成的任务没有变化。并行提交的界面修复已使用 `0.70.2-dev.1`，本次版本从它递增到 `0.70.3-dev.1`。

## 已确认的边界

- 每台设备当前只保存一个 `room_config`，一次只能创建或加入一个群。多群需要房间隔离的成员、消息、连接、任务和切换逻辑，是独立功能，不在这次提示词修复中混入。
- 每个群有持久化的 Codex thread；后续轮次继续使用该 thread。对方设备的最近一次回复就是当前接力消息，无需把全部群记录重新拼进去。
- 普通聊天已有 `[附件文档：名称]` 文本附件格式，历史解析会把正文显示成文档卡片。它只改善可见长度，模型仍会读取附件内容。跨设备没有共享文件目录，不能仅传文件路径。

## 实施步骤

1. 测试复现：即使群里有多条很长的历史，新一轮提示仍应只包含当前目标消息；自动接力时完整保留对方最新回复和 `@` 接力规则。
2. 移除 `_agent_prompt` 的历史批量拼接，保留本机、房间、在线设备和当前消息的必要信息。
3. 对较长的当前消息使用已有文本附件标记，使普通聊天显示文档卡片；短消息仍直接显示。包含附件结束标记的消息使用普通文本，避免显示解析截断。
4. 运行相关 Python 测试、前端构建和差异检查。仅提交本次文件；保留其他未提交改动。
5. 更新应用版本与更新记录。按之前授权推送 Gitea，并在对话空闲后安全重启 Linux 服务；Windows 也需更新后才能使用新的发起端提示词。

## 验收标准

- 旧群消息不会再次出现在新一轮 Codex 用户提示中；对方刚发来的完整消息只出现一次。
- 长消息在普通聊天历史中以文档卡片承载，模型仍能读取全文；短消息直接可见。
- 自动接力仍按最终回复的独占 `@设备名` 行触发，现有群消息与历史保留不丢失。
- 单群限制如实说明，不通过本次变更破坏既有房间。
