# Stale Codex Turn Interrupt Recovery

## 用户可见分类与版本

- 分类：修复 / PATCH。已有聊天的暂停操作遇到旧会话状态时会报错，网页仍显示持续运行；本次修复暂停与运行状态恢复，不改变用户可完成的任务。
- 目标版本：`0.56.4-dev.1`。

## 问题证据

- 对话历史中的最后一轮仍标记为 `inProgress`，时间戳停留在旧记录。
- 当前 Codex App Server 对该对话的中断请求返回 `thread not found`，导致暂停失败。
- 前端在暂停失败后清除了“正在停止”标记，却继续保持“正在运行”计时。

## 实施步骤

1. 暂停 Codex 对话遇到 `thread not found` 时，先尝试恢复历史会话并重新读取实际运行轮次；只对同一轮次重试中断，避免误停更新的轮次。
2. 恢复后确认运行端已没有该轮次时，将线程记为已暂停并广播一条合成的中断完成事件，不修改 Codex 的 JSONL/SQLite 历史。
3. 对已暂停但历史仍残留 `inProgress` 的会话，API 仅在返回给网页的视图中显示 `interrupted`，避免刷新后重新出现永久计时；继续对话时仍使用原始历史上下文。
4. 更新 CHANGELOG 与项目版本。
5. 执行 Python 语法检查和前端生产构建，检查 diff 与仓库状态，本地提交；不推送 GitHub。

## 验收要点

- 正常活动会话的暂停仍由 Codex App Server 实际执行。
- 线程索引暂时丢失时会恢复会话并重试一次。
- 恢复后确认目标轮次已不在运行时，会停止网页计时、保留原始历史，并在刷新后保持停止状态。
- 若恢复后发现当前活动轮次与用户发出的暂停轮次不同，不会暂停新轮次。
