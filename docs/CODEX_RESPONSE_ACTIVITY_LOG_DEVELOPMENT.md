# Codex 回复操作记录开发文档

## 目标

在网页端 Codex 回复期间及回复完成后，展示这一轮实际执行的操作摘要，例如读取/搜索文件、运行命令、编辑文件和调用工具，并实时更新操作状态。

## 设计约束

- 仅使用 Codex App Server 已推送的 turn/item 事件及 thread 历史，不轮询、不扫描工作区。
- 按 turn ID 关联操作与助手回复；支持实时 item 事件和重新读取 thread 后恢复已有记录。
- 展示安全、简短的操作摘要、文件路径或命令本身；不展示 reasoning 正文或命令输出，命令中的常见凭据参数须脱敏。
- 编辑文件继续复用现有文件变更卡片和 diff；文件变更未完成时也能在当前回复下查看。
- 操作记录可折叠，避免长 turn 挤占聊天区；记录数量和详情长度设上限。
- 不改变审批、命令执行策略、文件读取/预览安全边界和已有消息流行为。

## 实施步骤

1. 基于 `item/started`、`item/completed` 和文件变更事件新增按 turn 汇总的操作记录，解析命令、文件及工具摘要并维护运行/完成/失败状态。
2. 将操作记录并入当前 thread 的内存缓存，并从 `thread/read` 返回的 turn items 恢复近期记录；切换对话时不得串出其他 thread 的活动。
3. 在助手回复下方添加可折叠操作记录列表；进行中的命令和文件变更即时更新，正常回复完成后记录继续保留。
4. 让当前 turn 的文件变更卡片在回复过程中可见，沿用现有审核 diff、文件预览与路径插入行为。
5. 更新 `CHANGELOG.md` 版本记录，运行 TypeScript 检查、Vite 生产构建、相关现有测试和 `git diff --check`，创建本地 Git 提交，不推送 GitHub。

## 验收标准

- 命令开始时显示正在执行状态，结束后显示完成或失败，命令摘要可读且常见 token/password/API key 参数脱敏。
- 文件读取/搜索操作尽可能显示路径或实际命令；文件编辑操作显示文件路径，diff 在编辑过程中即可展开。
- 操作记录出现在对应助手回复下方，正常 turn 完成后仍可查看；线程切换和多窗口不串数据。
- 不显示 reasoning 内容、命令输出或无关原始 JSON。
- 记录数量、命令详情长度有上限；已有活动指示器、审批和文件审核功能正常。
- TypeScript/Vite 构建、现有后端相关测试和 `git diff --check` 通过。
