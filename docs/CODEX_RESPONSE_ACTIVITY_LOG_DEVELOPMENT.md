# Codex 回复操作记录开发文档

## 目标

在网页端 Codex 回复期间及回复完成后，展示这一轮实际执行的操作摘要，例如读取/搜索文件、运行命令、编辑文件和调用工具，并实时更新操作状态。

## 设计约束

- 仅使用 Codex App Server 已推送的 turn/item 事件及 thread 历史，不轮询、不扫描工作区。
- 按 turn ID 关联操作与助手回复；支持实时 item 事件和重新读取 thread 后恢复已有记录。
- 展示安全、简短的操作摘要、文件路径或命令本身；不展示 reasoning 正文或命令输出，命令中的常见凭据参数须脱敏。
- 编辑文件继续复用现有文件变更卡片和 diff；文件变更未完成时也能在当前回复下查看。
- 操作记录可折叠，避免长 turn 挤占聊天区；记录数量和详情长度设上限。
- 不改变审批、命令执行策略、文件读取/预览安全边界和已有消息流行为。

## 实施步骤

1. 基于 `item/started`、`item/completed` 和文件变更事件新增按 turn 汇总的操作记录，解析命令、文件及工具摘要并维护运行/完成/失败状态。
2. 将操作记录并入当前 thread 的内存缓存，并从 `thread/read` 返回的 turn items 恢复近期记录；切换对话时不得串出其他 thread 的活动。
3. 在助手回复下方添加可折叠操作记录列表；进行中的命令和文件变更即时更新，正常回复完成后记录继续保留。
4. 让当前 turn 的文件变更卡片在回复过程中可见，沿用现有审核 diff、文件预览与路径插入行为。
5. 更新 `CHANGELOG.md` 版本记录，运行 TypeScript 检查、Vite 生产构建、相关现有测试和 `git diff --check`，创建本地 Git 提交，不推送 GitHub。

## 验收标准

- 命令开始时显示正在执行状态，结束后显示完成或失败，命令摘要可读且常见 token/password/API key 参数脱敏。
- 文件读取/搜索操作尽可能显示路径或实际命令；文件编辑操作显示文件路径，diff 在编辑过程中即可展开。
- 操作记录出现在对应助手回复下方，正常 turn 完成后仍可查看；线程切换和多窗口不串数据。
- 不显示 reasoning 内容、命令输出或无关原始 JSON。
- 记录数量、命令详情长度有上限；已有活动指示器、审批和文件审核功能正常。
- TypeScript/Vite 构建、现有后端相关测试和 `git diff --check` 通过。

## Hapi 参考：实时操作步骤

### 现状与参考

- 本项目已经从 Codex item 事件构建每轮操作列表，但仅在助手消息结束后显示，且默认折叠；运行中只显示当前活动项。
- Hapi 将工具调用作为聊天时间线中的独立块，根据连续调用生成工具组，并将 `command_actions` 解析为读取、列目录和搜索等可读步骤。相关实现位于 `web/src/chat/toolGroups.ts`、`web/src/chat/codexCommandPresentation.ts` 和 `web/src/components/ToolCard/ToolGroupCard.tsx`。
- 本次沿用本项目已有的 `item/started`、`item/completed` 记录和缓存结构，不引入 Hapi 的聊天状态模型或工具结果输出。

### 目标

- Codex 正在回复时实时展开显示本轮已收到的操作步骤和状态；助手开始输出正文前也能看到已发生的操作。
- 对 Codex 提供的读取、列目录、搜索子步骤进行有限字段解析，便于识别具体操作。
- 完成后操作记录留在对应助手回复下；历史记录仍可折叠查看。

### 实施步骤

1. 在浏览器事件与历史投影中，以数量和字段长度上限保留 `command_actions` 中的类型、名称、路径和搜索词。
2. 将受支持的 Codex 子步骤解析为安全的操作明细；沿用已有命令脱敏、状态和记录数量限制，不读取命令输出或 reasoning 正文。
3. 将当前轮操作记录放入助手流式消息；在助手正文尚未出现时显示在运行状态区域，避免重复显示。流式消息首次挂载时自动展开，完成后保留展开状态。
4. 递增功能版本，构建网页产物，检查差异并创建仅包含本次修改的本地提交，不推送 GitHub。

### 验收标准

- item 事件到达时，操作立即按顺序出现，状态可从进行中更新为完成、失败或停止。
- 可用的 `command_actions` 会显示具体读取、列目录或搜索明细；缺少该字段时仍显示原有命令摘要。
- 回复完成后记录位于该回复下；未开始输出正文时，运行区域已显示记录；线程切换不串记录。
- 命令输出、reasoning 正文及未投影的原始工具参数不出现在操作记录中；命令凭据继续脱敏。

## 按事件顺序展示工具步骤

### 设计决定

- 参考 Hapi 将工具调用放进聊天时间线的做法，但保留本项目自己的事件、缓存和消息组件，不复制 Hapi 源码。
- 使用 Codex 现有 turn item 顺序及 `item/agentMessage/delta`、`item/started`、`item/completed` 事件，把助手正文片段与操作卡片按顺序穿插展示。
- 时间线正文只引用已显示助手消息的字符区间；不收集或呈现 reasoning、命令输出和未投影的工具参数。
- 操作卡片继续使用有界、脱敏后的现有操作摘要；连续工具步骤可以成组折叠，历史线程切换后仍能还原顺序。

### 实施步骤

1. 为每个 turn 构建轻量时间线索引：助手文本项记录字符长度，操作项引用现有操作 ID；从历史 thread items 恢复顺序。
2. 在实时事件处理中按到达顺序插入文本和操作索引，完成事件更新原有索引，不重复插入；切换和缓存 thread 时同步隔离与恢复。
3. 在助手正文中渲染文字与连续操作组，避免再把同一批操作重复放在回复末尾；若正文还没开始，暂时在运行区显示已发生的操作。
4. 递增同目标版本的 dev 序号，更新版本记录；完成实现后创建只包含本次修改的本地提交，不推送 GitHub。

### 验收标准

- 回复中先说话、再调用工具、再继续回复时，网页呈现顺序与事件顺序一致；工具进行中、完成、失败或停止状态即时更新。
- 历史 thread/read 与缓存 thread 能恢复工具相对于助手正文的位置，切换对话不串时间线。
- 无助手正文时操作仍立即可见；正文出现后操作迁入对应回复，不重复显示。
- 沿用既有命令脱敏和操作详情上限，不显示 reasoning、命令输出或原始参数。
