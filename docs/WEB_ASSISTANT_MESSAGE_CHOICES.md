# 网页助手文字选项快速选择

## 问题与分类

助手在回复中用“问题 + 列表选项”询问用户时，网页版目前仅显示文字，无法点选。截图中的两组问题属于普通助手消息；现有服务端只转发审批类结构化请求，没有针对这些文字选项的交互数据。

本次属于修复 / 体验优化（PATCH）：用户原本能在输入框手动回答，新增的点选只是已有回答流程的快捷入口。并行的群聊功能已占用 `0.71.0-dev.1`，本次目标版本顺延为 `0.71.1-dev.1`。

## 方案

- 只识别最后一条助手回复末尾、格式明确的问题组：问题以问号结尾，后跟 2–6 个列表选项；最多三组，支持常见的加粗、标题及编号问题格式，忽略代码块。
- 在当前活动聊天显示可点击的选项；纯问题消息直接用选择区呈现，避免把同一列表重复显示。每组只能选一个，用户选完后点击“填入输入框”，由用户确认或修改再发送。
- 将每个问题及选中的答案一起写入输入框，保留已有草稿；群聊沿用当前发送目标。
- 普通解释性列表与不完整的流式回复继续保持原样显示。

## 实施步骤

1. 增加严格的文字问题组识别逻辑。
2. 在最新助手消息下方显示选项，并把选定答案写入输入框。
3. 补充深色、浅色及移动端样式，保持键盘可操作。
4. 更新版本记录，构建前端供 `4173` 页面加载，检查差异并创建本地 Git 提交。

## 验收标准

- 截图中两组问题可分别选一项，选完后能把两题答案填入输入框。
- 点击不会直接发送，也不会覆盖原草稿。
- 普通列表、代码和历史对话不出现误导性的可选按钮。
