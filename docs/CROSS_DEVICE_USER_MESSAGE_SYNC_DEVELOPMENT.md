# 跨设备用户消息即时同步开发文档

## 目标

当同一条 Codex 对话在电脑端和手机端同时打开时，任一设备发送的用户消息都应在 Codex 回复流式内容前显示在另一台设备上；发送端的本地乐观消息不得重复。

## 根因

- 前端收到当前对话的 `turn/started` 时只更新运行状态，没有同步该 turn 的历史。
- 其他设备因此先收到并显示助手的流式回复；用户消息直到 `turn/completed` 后的 `thread/read` 才进入消息列表。
- 发送端自身已有本地乐观消息，若对所有客户端无差别刷新历史，可能与服务器记录的同一用户消息短暂重复。
- turn 启动时读取历史还可能遇到服务端运行状态尚未更新的快照，不能因此清除刚建立的活动 turn。

## 实施步骤

1. 在当前活动 thread 收到 `turn/started` 时，判断本页面是否有该 thread 的待确认本地发送；发送端沿用现有乐观消息，其他设备立即读取 thread 历史。
2. 对不会产生新 `turn/started` 的 `turn/steer`，在收到尚未显示的 `userMessage` item 时同步历史；本地发送仍由乐观消息即时呈现。
3. 复用历史版本号防止过期读取覆盖新消息，并沿用现有流式助手消息合并逻辑。
4. 对启动事件触发的历史读取保留当前已确认的运行 turn，避免较旧的 `thread/read` 状态清掉活动状态。
5. 更新 `CHANGELOG.md` 版本记录，执行前端构建、测试和 `git diff --check`。
6. 创建本地 Git 提交；除非用户明确要求，不推送 GitHub。

## 验收标准

- PC 端发送时，手机端在 Codex 开始显示回复前已看到对应用户消息；反向发送同样成立。
- `turn/steer` 插入的消息也会在另一设备的回复流中及时出现。
- 发送设备上的乐观消息不会因启动时刷新历史而重复。
- 流式助手回复只显示一个气泡，用户消息顺序保持正确。
- 启动阶段的历史读取不会错误清除当前活动 turn；turn 完成后的正式历史刷新继续生效。
- `pnpm --filter codex-remote build`、`pnpm --filter codex-remote test` 成功，`git diff --check` 无输出。
