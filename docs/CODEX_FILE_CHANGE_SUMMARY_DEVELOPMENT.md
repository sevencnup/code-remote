# Codex 文件改动汇总卡片开发文档

## 目标

将同一轮 Codex 产生的多个文件改动汇总为一张接近官方 Codex 样式的卡片，展示修改文件数、总增删行数、逐文件路径与增删行数，并支持展开剩余文件和审核 diff。

## 技术边界

- 优先使用 App Server `fileChange` item 的路径、diff 和状态；原生事件缺少的路径由有资源上限的工作区文本快照计算兜底 diff，不依赖 Git。
- 同一路径在一轮内被多次修改时合并为一行，并累加增删行数。
- 默认显示前三个文件，剩余文件通过卡片底部按钮展开或收起。
- “审核”在当前页面展开或收起各文件的 diff。
- 审核 diff 时逐行区分新增与删除：新增行浅绿色、删除行浅红色，hunk 与文件头保持中性样式。
- 审核 diff 显示旧行号与新行号；根据 unified diff 的 hunk 起点和增删上下文分别递增，hunk/file header 不占代码行号。
- 每个文件路径旁提供“插入对话”按钮，只将文件路径追加到当前对话输入草稿并聚焦，不自动发送。
- 审核展开时文件改动卡片标题栏在聊天滚动区域内吸顶，顶部紧贴聊天状态栏下沿；卡片自身不得裁切 sticky 标题。回到底部按钮使用滚动区与输入框之间的独立布局行，不能覆盖审核内容或行内操作。
- 文件变更卡片展示可靠的原生或快照兜底 diff；从卡片打开只读文件预览时，新增行浅绿、删除行浅红，普通文件树预览仍显示当前文件全文。
- “本次已编辑 N 个文件”标题保持清晰但使用较小字号。
- 不提供虚假的“撤销”按钮；App Server 的 `thread/revert` 只撤回对话历史，不会恢复本地文件。

## 实施步骤

1. 将消息流中的多个文件改动卡片改为单张轮次汇总卡片。
2. 在卡片组件内按文件路径合并改动并计算总增删行数。
3. 实现前三项预览、剩余文件展开、diff 审核和进行中状态。
4. 将 diff 行解析为带新旧行号和语义 class 的行，突出新增/删除背景色。
5. 在每个文件行添加插入对话操作，将该文件路径追加到输入草稿但不自动发送。
6. 审核展开时为卡片标题栏和文件路径栏提供滚动吸顶样式；移除卡片对 sticky 内容的裁切，将消息流顶部留白移到内容层，并确保标题紧贴聊天滚动区域顶部（即状态栏下沿）；将回到底部按钮放到聊天滚动区与输入框之间的独立布局行；缩小文件数标题。
7. 调整桌面端与移动端样式，使卡片结构、间距、颜色和操作区接近 Codex。
8. 更新版本记录，执行生产构建和差异检查，并创建本地 Git 提交。

## 验收标准

- 同一轮的多个 `fileChange` item 只显示为一张卡片。
- 卡片顶部显示文件总数与总增删行数。
- 每个文件行显示路径及该文件的增删行数。
- 超过三个文件时可以展开和收起剩余文件。
- 点击“审核”可以查看或收起 diff；没有 diff 的文件显示改动类型。
- diff 中删除行呈浅红色、新增行呈浅绿色，其他行不误着色。
- diff 行显示旧/新行号，新增行只显示新行号、删除行只显示旧行号、上下文行显示两者；新 hunk 从声明的起始行号继续编号。
- 点击任一文件的“插入对话”按钮会将其路径追加到正确对话的草稿、聚焦输入框且不发送；已存在的路径不重复插入。
- 审核展开后滚动聊天内容时卡片标题栏紧贴聊天状态栏下沿吸顶，不留滚动区顶部留白或卡片裁切造成的间隙；审核收起后恢复普通流式布局。
- 回到底部按钮位于独立布局行，不遮挡审核 diff 和文件行的“插入对话”操作。
- 从审核卡片可打开只读预览并按 diff 标记新增/删除行；工作区树的预览/插入行为保持不变，不支持编辑保存。
- 桌面端“本次已编辑 N 个文件”字号小于现有 15px。
- 移动端路径不会挤压增删统计或溢出卡片。
- `pnpm --filter codex-remote build` 成功，`git diff --check` 无输出。
