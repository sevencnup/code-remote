# 网页端无提示词续接中断回复

## 目标

Codex 普通回复第一次 Esc 暂停后，点击输入框“继续”直接从已有对话上下文发起空输入回合，不插入“请继续刚才中断的任务”等用户消息。第二次 Esc 取消待续接；草稿、附件和排队消息不被续接操作消费。

## 已核对的接口事实

- OpenAI Docs 列出 `turn/interrupt` 和 `turn/start`，中断会结束当前 turn；因此这是同一线程上的新回合，并非恢复原 turn ID。
- 本机 `codex-cli 0.162.1` 的隔离 App Server 实测：中断后发送 `turn/start` 的 `input: []`，会收到新的 assistant delta，且不提交用户提示词。
- 工作区已有未提交的 Android 暂停/排队修复；保留现有修改并在其上集成，不重置或覆盖。

## 开发步骤

1. 完整核对现有未提交的暂停、续接、排队顺序和客户端回执流程。
2. 为 Codex App Server 封装空输入续接；共享队列维持暂停期间不自动发送，续接优先于排队消息。Claude 暂不改动其独立续接语义。
3. 网页端续接走专用请求和状态更新，不调用普通发消息逻辑，不生成本地或服务端用户气泡；Android Codex 按钮同样不提交续写文本。
4. 补充后端与前端回归测试，验证失败重试、草稿保留、队列顺序和无用户气泡；构建并运行相关测试。
5. 更新版本记录，按用户可见影响分类，只做本地提交，不推送远端。

## 验收

- 中断后点击继续开始生成，不出现额外的用户“继续”消息。
- 连点或网络重试不会重复启动两个续接回合；失败时可再次尝试。
- 排队消息在暂停期间不自动发送，续接结束后按既有顺序推进。
- Android 和网页版的原草稿、附件均不被续接操作清空或发送。

分类：PATCH / 修正已提供的暂停续接行为和排队顺序，用户完成的任务能力未变化。目标版本 `0.28.4-dev.3`。

- 网页版 `pnpm build` 通过；Android `assembleDebug` 通过，生成独立的 `0.28.4-dev.3` 调试包。当前环境无 `adb`，未安装到设备。
- 共享队列测试 30 项通过，包括空消息续接、失败重试、防重复、第二次 Esc 取消及队列等待。

- 第二次 Esc 会调用服务端停止接口：如续接回合已开始，先中断它，再清除持久化暂停标记。中断后的排队消息仍需人工检查，不会静默发送。
