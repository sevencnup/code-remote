# 消息模型选择与手机键盘布局

## 目标和分类

- 新增功能 / MINOR：回复期间可为下一条消息选择模型和思考等级，并支持仅使用一次的临时设置；消息入队后保存自己的参数。
- 修复 / PATCH：手机键盘弹出时不再因可视区域变矮切换成横屏布局，减少键盘重复唤起和高度重复写入。
- 合并版本为 `0.16.0-dev.1`，Android 只同步 versionName，不生成 APK。

## 协议依据

已读取 OpenAI 官方文档：<https://developers.openai.com/codex/app-server>。
`turn/start` 支持模型和思考等级参数；`turn/steer` 只给当前回复增加输入，不接受模型等轮次覆盖参数。现有后台从每条排队消息传递 model、effort 给 turn/start。因此换模型的消息应作为独立轮次执行，不能用插话路径静默丢弃参数。

## 实施步骤

1. 放开回复期间的模型和思考等级选择，保留发送提交期间的锁定；新增可取消的“仅本次”设置，保存成功后恢复原设置，失败时保留当前设置。
2. 排队列表显示该消息保存的模型和思考等级；编辑文字保留原参数。带模型/思考设置的消息通过已有 start-if-idle 接口立即开始，忙碌时保留队列，不插入另一模型的当前回复。
3. 使用设备屏幕方向判断触屏横屏布局，统一 CSS 与输入框高度判断，键盘缩小可视区域不能触发横屏布局。
4. 按动画帧合并高度更新，跳过未变化的值；移动端先由浏览器正常打开键盘，仅在未打开时调用已有原生桥接，程序性聚焦使用 preventScroll。
5. 复查消息快照、成功/失败、切换会话、队列编辑和移动端焦点恢复路径，完成生产构建，不新增或运行测试。
6. 更新版本和简短记录，本地提交。保留已有 APK 文档改动，不重启服务，不推送 GitHub。

## 使用方式与完成记录

- 常用模型保持原有选择方式。在模型或思考菜单先打开“仅本次”，再选择临时参数；成功发送或入队后恢复原参数。失败时保留选择，新建聊天过程中也迁移临时设置。临时选择不覆盖持久化的常用偏好。
- 每条排队消息显示保存的模型和思考等级，后续选择不修改它；编辑文字继续保留它的参数。需要独立轮次的消息等待前序回复结束，使用现有后端接口避免竞态下误走插话路径。
- 回复期间无草稿显示暂停，有草稿显示发送，手机可以直接加入队列。
- 触屏横屏布局改用屏幕方向；键盘缩小网页高度不会隐藏顶部栏或切换输入框高度。视口变化按帧合并，未变化的值不重复写入；聊天原本跟随底部时继续跟随窗口高度变化。
- 输入框聚焦先使用 WebView 正常键盘行为，350 毫秒后仍未显示才调用已有原生桥接。菜单选项保持输入焦点，程序性聚焦不滚动整个页面；编辑期间暂停自动更新引起的整页刷新。
- 生产构建通过（包含 TypeScript 编译），未新增或运行自动化测试，未进行真实模型调用或手机键盘交互验证。最终真机动画表现仍需观察。
- 前端刷新加载，不重启服务，不重新安装 APK；Android versionCode 保持 127。
