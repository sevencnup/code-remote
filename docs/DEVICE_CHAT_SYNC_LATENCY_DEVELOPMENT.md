# 设备群聊消息同步延迟

## 问题与分类

两端设备已保持在线，但群聊网页每 1.2 秒才轮询一次增量状态。消息落到本机服务后，还可能等待下一次轮询才显示；流式回复会重复遇到这个等待。

本次属于修复 / PATCH：改善现有群聊消息的同步速度，不改变用户的发送和接力流程。目标版本为 `0.71.3-dev.1`。

## 实施步骤

1. 在设备群聊管理器中增加可取消的状态等待队列，消息、设备在线状态或房间状态变化时唤醒等待者，并检查注册前后的消息游标以避免漏通知。
2. 为群聊状态接口增加有上限的等待参数；等待最多 20 秒，收到变化立即返回，超时后返回当前增量作为断线和代理兼容兜底。
3. 将网页群聊状态读取改为单请求顺序循环，收到服务端变化后马上合并状态；离开群聊模式时取消未完成请求，网络错误时短暂退避再连接。
4. 更新服务、Web 与 Android `versionName` 和简短版本记录；不生成 APK，不递增 Android `versionCode`。
5. 按当前开发约束不运行自动化测试；运行 TypeScript 检查与 Web 构建，检查差异格式，并只提交本地 Git。
6. 如有活跃 Codex turn，使用现有空闲重启脚本安排服务更新，并确认健康状态和运行版本。

## 验收标准

- 新消息和流式正文更新不再等待固定 1.2 秒轮询周期。
- 同一浏览器只保留一个待处理的群聊状态请求；新消息不会被旧的空响应覆盖。
- 切换离开群聊时取消等待；服务端长轮询超时后会自动再次读取，网络故障后会退避重试。

## 完成记录

- 已完成带 20 秒兜底的群聊状态长轮询；消息游标、设备在线状态和房间状态变化都会唤醒等待中的请求。
- 网页改为串行等待状态变化，模式切换时会取消请求，避免轮询请求堆叠。
- Web、服务端与 Android `versionName` 已更新至 `0.71.3-dev.1`；未构建 APK，`versionCode` 未变。
