# 原始 PDF 附件读取开发文档

## 目标

网页发送 PDF 时不再用浏览器提取 PDF 文字。将原始 PDF 上传到运行 Codex 的主机私有临时目录，并在用户消息中给 Codex 提供由服务端生成的本机文件路径，要求 Codex 使用自己的工具读取原件。

## 约束与安全

- Codex App Server 的 `turn/start.input` 没有通用 PDF 文件附件类型；通过普通文本传递服务端受控的临时路径，让 Codex 在本机读取原始文件。
- 仅 PDF 使用原件路径方式；其余可解析文档继续沿用现有提取文本逻辑。
- PDF 上传必须经过现有配对认证；限制为 PDF、单文件不超过 20 MiB，并验证文件签名。
- 文件以随机名保存在权限受限的进程私有临时目录，不写入项目工作区；服务退出时整体清理，并清理过期文件。
- 请求仅携带服务端签发的随机附件 ID；服务端必须校验 ID 与临时路径的映射，不能接受客户端提供的任意本机路径。
- 排队、编辑和重试只保存附件 ID，不在 localStorage 保存 PDF 二进制；附件 ID 失效时给出可操作错误，提示重新添加 PDF。
- 历史消息应保留文件名并显示原始 PDF 附件卡片，不把临时绝对路径显示给用户。

## 实施步骤

1. 后端增加认证的原始 PDF 上传接口，流式读取并限长，校验 `%PDF-` 文件头，保存到私有临时目录并返回随机附件 ID。
2. 后端维护附件 ID 到文件路径的受控映射、过期清理及关闭时清理；turn/start 请求接受附件 ID 列表并校验映射。
3. 前端选择 PDF 时上传原始文件，不调用 PDF 文本提取；输入框和排队消息显示“原始 PDF，Codex 将读取文件”。非 PDF 文档行为保持不变。
4. turn/start 前由后端将经过校验的路径和“使用工具读取原始 PDF、不可依赖网页提取文字”的指示加入用户消息；无效/已过期附件不得静默降级为文字提取。
5. 解析历史中的受控附件标记，隐藏临时路径并恢复文件卡片；确保排队发送、编辑、发送失败恢复和跨设备刷新不丢附件引用。
6. 增加后端上传/鉴权/文件签名/过期/路径隔离测试与前端附件历史测试，运行相关测试、完整测试和生产构建，再创建本地 Git 提交；未经明确命令不推送。

## 验收标准

- PDF 原始字节由浏览器上传至 Codex 所在主机；网页端发送逻辑不解析 PDF 文本。
- Codex 收到的消息包含后端确认的本机 PDF 路径，并明确要求使用工具读取原件；历史中不向界面暴露该临时路径。
- 未认证上传、非 PDF 文件、空文件、超限文件、伪造/失效附件 ID 均被拒绝。
- 删除或编辑排队消息时附件引用保持一致；服务重启导致临时附件失效时提示用户重新附加。
- 其他文档附件、图片附件和原有排队消息行为不回归。
