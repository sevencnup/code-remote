# 输入框新建聊天后侧边栏未同步

## 现象与根因

- 输入框左下角创建聊天后，左侧聊天列表有时要手动刷新才出现新聊天。
- 并发面板各自维护 remote 状态，侧边栏固定读取主 remote 的线程列表；从其他面板创建时只请求刷新主列表，可能与正在进行的旧列表请求竞争。
- 主线程列表还需要保护新建结果，避免较早发出的列表响应覆盖刚写入的聊天。

## 实施步骤

1. 为线程控制器增加显式的线程列表写入方法，同步更新主列表状态与内部线程引用。
2. 将并发面板创建的新聊天立即写入侧边栏使用的主线程列表；列表刷新期间保留尚未被服务端列表确认的新建项。
3. 将版本升至 `0.59.1-dev.1` 并更新版本记录。
4. 执行 `pnpm build` 和 `git diff --check`，不运行测试；仅暂存本次相关文件并创建本地提交，不推送 GitHub。

## 验收标准

- 在任意并发面板从输入框新建聊天后，侧边栏立即显示对应聊天，无需手动刷新。
- 正在进行中的旧线程列表请求不会把刚创建的聊天从侧边栏移除。

## 验证结果

- `pnpm build` 通过；Vite 有既存的大 chunk 提示。
- `git diff --check` 通过。
- 未运行测试；未部署或重启服务，未推送 GitHub。
