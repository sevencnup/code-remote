# 网页刷新后并发窗口恢复修复

## 分类与目标

本次为修复 / PATCH，目标版本 `0.76.8-dev.1`。修复已有并发窗口在刷新后丢失的体验，保留窗口顺序、当前选中窗口、每个窗口的聊天和引擎。并行 Android 修复已占用 `0.76.7-dev.1`，本次网页修复顺延；仅同步 Android `versionName`，不打包。

## 当前问题

- 布局只保存在所有标签页共享的 localStorage；另一页保存单窗口布局后，会覆盖当前页下次刷新要读取的记录。写入失败也没有独立的回退。
- 布局保存依赖普通 effect，没有在页面退出前补存最新状态。
- 主窗口只读取旧的单聊天记录，不使用并发布局中自己的聊天编号，可能与其他窗口的恢复结果不一致。
- 恢复时按当前视口过滤窗口编号，窗口变窄可能丢弃原本合法的桌面窗口。

## 实施步骤

1. 抽出布局存储与校验，刷新优先读取当前标签页的 sessionStorage，兼容既有 localStorage 布局并保留跨次打开的回退。两种存储独立处理错误。
2. 只按实际可用的五个窗口编号校验已保存布局，保留顺序与选中项；打开新窗口时继续使用现有设备上限。
3. 在布局及聊天绑定更新后及时保存，并在 pagehide 时补存；主窗口优先读取布局保存的聊天编号，只有旧用户没有布局记录时才使用单聊天回退。
4. 更新版本和简短记录，完成 TypeScript 与 Vite 构建及 4173 产物检查。本轮未要求测试，不新增或运行测试。
5. 只暂存本次变更并创建本地提交，不推送远端。

## 完成记录

- 布局改为 sessionStorage 优先、localStorage 回退，两种存储分别读写与容错，兼容既有保存格式。
- 布局提交后立即保存，页面退出与卸载时补存最新快照；各窗口的聊天编号在历史加载前即可恢复，主窗口也优先使用本页布局。
- 恢复合法窗口编号时不再受临时视口宽度影响，保留原顺序、当前选中项和引擎；新增窗口仍遵守当前设备的数量上限。
- TypeScript 与 Vite 生产构建完成，差异格式检查通过；4173 返回 HTTP 200，首页与当前产物一致，无需重启后端。
- 未新增或运行测试，未进行浏览器多窗口刷新测试。旧版本已经丢失且未保存的窗口需要重新打开一次。
- 版本与更新描述记录为 `0.76.8-dev.1`，只提交本次网页修复及文档。
