# 侧栏聊天快捷键切换开发说明

## 目标

在网页版侧栏中增加键盘快捷键，按当前侧栏显示顺序切换聊天。目标版本为 `0.36.0-dev.1`，属于新增功能（MINOR）。

## 设计

- 使用 `Alt + ↑` 切换到上一条聊天，使用 `Alt + ↓` 切换到下一条聊天；顺序与侧栏分组及置顶顺序一致，到达列表边界后循环。
- 搜索时只在匹配结果中切换；当前聊天不在结果中时，向下从第一项开始，向上从最后一项开始。
- 复用现有聊天选择逻辑，切到已在其他窗格打开的聊天时保持现有窗格行为。
- 输入框、文本编辑区、批量选择状态和弹窗中不响应快捷键，避免干扰输入和其他操作。
- 在侧栏聊天记录标题旁显示快捷键提示。
- 仅修改 Web 交互；同步 `package.json` 和 Android `versionName`，不改 Android 原生代码、不递增 `versionCode`、不生成 APK。

## 实施步骤

1. 在网页聊天页监听 `Alt + ↑/↓`，基于当前分组后的侧栏聊天列表循环选择上一条或下一条聊天。
2. 为输入编辑区域、批量选择、弹窗和不可切换状态增加忽略条件，并在侧栏显示快捷键提示。
3. 将 Web 和 Android `versionName` 更新为 `0.36.0-dev.1`，在 `CHANGELOG.md` 记录用户可见更新描述。
4. 执行生产构建和差异检查，创建只包含本次改动的本地提交；不运行测试、不推送远端。

## 验收标准

- `Alt + ↑/↓` 按侧栏可见顺序切换聊天，并在首尾循环。
- 搜索过滤后的结果可切换；当前聊天不在结果中时，从对应方向的结果边界进入。
- 已在其他窗格打开的聊天通过现有选择逻辑切换到对应窗格。
- 在输入框、编辑区域、批量选择或弹窗中按快捷键不会切换聊天。
- 侧栏标题显示 `Alt ↑↓` 提示；生产构建和差异检查通过。

## 完成记录

- 桌面网页支持 `Alt + ↑/↓` 按当前侧栏分组顺序循环切换聊天，提示会显示在聊天记录标题旁；输入区域、弹窗、批量选择和已交还状态会忽略快捷键。
- Web 与 Android `versionName` 更新为 `0.36.0-dev.1`；Android `versionCode` 保持 `279`，未修改原生代码或生成 APK。
- `pnpm build` 和 `git diff --check` 通过；未新增或运行测试。

## 补充需求：设置页录制快捷键

用户指出切换聊天快捷键还应能在设置页录制和自定义。本次扩展为上一条与下一条分别录制快捷键，并提供恢复默认操作。目标版本为 `0.37.0-dev.2`，属于新增功能（MINOR）的后续完善。

### 实施步骤

1. 新增快捷键偏好存储与规范化逻辑，默认值保持 `Alt + ↑/↓`。
2. 在设置页新增上一条、下一条快捷键录制按钮，支持按键组合录制、Esc 取消、冲突提示及恢复默认；设置保存在当前浏览器。
3. 将侧栏切换监听改为使用已保存的快捷键，并动态显示快捷键提示；录制期间屏蔽全局聊天切换。
4. 将 Web 和 Android `versionName` 更新为 `0.37.0-dev.2`，在 `CHANGELOG.md` 记录更新描述。
5. 执行生产构建和差异检查，创建只包含本次改动的本地提交；不运行测试、不推送远端、不生成 APK。

### 验收标准

- 设置页能分别录制上一条和下一条聊天快捷键，并能恢复默认。
- 录制组合键至少包含一个修饰键；Esc 取消录制，重复分配会提示冲突。
- 自定义快捷键刷新页面后仍然有效，侧栏快捷键提示同步更新。
- 录制中的按键不会触发聊天切换；原有输入区域、弹窗及批量选择保护继续有效。
- 生产构建和差异检查通过。

### 完成记录

- 设置页新增上一条、下一条快捷键录制入口，可恢复默认；录制支持 Esc 取消、重复绑定和浏览器保留组合键提示。
- 快捷键保存在当前浏览器，刷新后保留；侧栏提示随自定义组合键更新。
- Web 与 Android `versionName` 更新为 `0.37.0-dev.2`；Android `versionCode` 保持 `279`，未生成 APK。
- `pnpm build` 通过；未新增或运行测试。

## 补充修复：消息输入框聚焦时切换聊天

用户希望在聊天消息输入框有焦点时仍可使用已配置的上一条、下一条快捷键。此前统一跳过所有输入区域，导致这一常见场景无法切换。目标版本为 `0.90.9-dev.1`，属于修复（PATCH）。

### 实施步骤

1. 为聊天消息输入框添加稳定标记，并在侧栏切换监听中仅对该输入框放行快捷键；其他输入与编辑区域维持忽略行为。
2. 保留输入法组合、弹窗、菜单、批量选择等已有拦截条件；带修饰键的 Enter 不作为普通发送处理，仍复用现有聊天选择逻辑。
3. 更新版本与版本记录，执行生产构建和差异检查，只提交本次改动到本地仓库。

### 验收标准

- 消息输入框有焦点时，默认和自定义的聊天切换组合键均可切换聊天。
- 普通输入和输入法组合不触发切换；其他输入、编辑区域及弹窗仍遵守原有限制。带修饰键的 Enter 若被录制为切换快捷键，不会误发送消息。

## 补充体验：快捷键切换后聚焦输入框

用户希望按上一条、下一条快捷键切换聊天后，直接在目标聊天输入框继续输入。目标版本为 `0.90.9-dev.2`，属于体验优化（PATCH）。

### 实施步骤

1. 为输入框组件提供聚焦入口，聚焦后将光标置于当前草稿末尾。
2. 仅在快捷键发起的聊天切换完成后聚焦目标输入框；点击侧栏聊天和外部通知打开聊天不触发自动聚焦。
3. 更新版本与版本记录，执行生产构建和差异检查，只提交本次改动到本地仓库。

### 验收标准

- 按快捷键切换到新聊天后，无需点击输入框即可继续输入；已有草稿保留，光标在末尾。
- 切换到已经在其他并发窗口打开的聊天时，输入框仍获得焦点。
- 在移动端点击侧栏聊天不会因此自动弹出键盘。
