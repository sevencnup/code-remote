# 移动网页版附件选择器延迟修复

## 目标

缩短手机浏览器中点击聊天输入框附件按钮后，系统文件选择器打开前的等待时间。

## 诊断记录

- 网页端按钮由透明的原生 `input[type=file]` 接收点击，点击链没有异步等待。
- 移动端此前把图片类型和文档模块支持的上百个扩展名同时写入 `accept`。移动浏览器需将这些过滤条件传给并映射到系统文件选择器，是最可疑的启动开销。
- 附件实际支持范围已有网页侧格式、大小和数量校验；`accept` 仅控制系统选择器的预筛选，不负责安全校验。
- 本机未连接用户手机，无法在同一设备上做改动前后的实测；使用精简网页回归测试和生产构建验证行为。

## 实施步骤

1. 手机网页不传超长 `accept` 过滤列表，让系统选择器自行展示文件；桌面端保留现有格式筛选。
2. 保留选中文件后的既有图片/文档分类、格式校验、大小限制和错误提示。
3. 增加回归测试，确保移动布局不再传入筛选列表，而桌面布局仍使用原规则。
4. 更新版本记录，运行项目测试和生产构建，检查差异并提交本地 Git；不推送远端。

## 验收标准

- 移动端选择器不再接收由大量扩展名组成的 `accept` 条件。
- 桌面端仍按现有文档格式列表过滤。
- 移动端选择后的支持类型、大小和数量仍由原网页逻辑校验。
- 项目测试、生产构建和 `git diff --check` 通过。
