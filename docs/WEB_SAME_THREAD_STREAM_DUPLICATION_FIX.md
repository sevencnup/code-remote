# 网页同一对话回复重复修复

## 问题与分类

同一 Codex 对话在两个网页中显示不同：后加入的页面可能在已恢复的历史回复末尾再次显示部分回复。原始会话记录中这些回复各只有一份。当前页面将历史正文与 WebSocket 正文按字符串重叠合并；如果网页只收到某个较晚的 `agentMessage` item，历史却已包含更早和当前的 item，字符串首尾没有重叠就会错误追加。

这是修复 / PATCH：恢复现有跨网页同步的一致性，用户可完成的任务没有变化。目标版本为 `0.87.1-dev.1`。

## 实施步骤

1. 从运行中 turn 的历史快照提取最近一条用户消息之后的助手 item，保留 item ID、顺序、正文和完成状态。
2. 按 item ID 将快照与本页已经收到的实时片段对齐；相同 item 取较完整的正文，快照缺少的实时 item 继续保留。
3. 历史重读时直接用对齐后的实时正文合成当前回复，丢弃重读前排队的旧渲染回调，不再把整个页面已有的回复正文重新拼入。
4. 更新版本和简要版本记录，构建 `4173` 页面产物，检查本次差异并创建本地 Git 提交。

## 验收标准

- 两个网页在同一运行中对话里显示相同的助手回复顺序和正文。
- 在回复中途打开或重连网页时，历史中已有的段落不会再次出现。
- 实时内容比历史快照更新时，后续增量仍正常显示。
