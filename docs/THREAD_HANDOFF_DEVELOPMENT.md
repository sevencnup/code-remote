# 网页与本机 Codex 会话交还开发文档

## 目标

让网页端已使用过的 Codex 会话能够安全交还给本机 Codex 打开，避免网页常驻 App Server 持有写入权而使原生端一直显示“占线”。交还不能重启开发服务、SSH 会话或配对状态。

## 根因

- 网页发送消息前会通过 `thread/resume` 将历史会话加载到常驻 App Server；该连接持续存在，因而继续持有会话写入权。
- 仅关闭浏览器标签不会关闭 Python 后端持有的 App Server。
- OpenAI App Server 的 `thread/unsubscribe` 在最后一个订阅者离开后仍有最长 30 分钟的空闲保留期，不能作为即时交还方案。

## 实施步骤

1. 在后端为 App Server 增加“已交还”状态和安全交还方法：有进行中或正在启动的网页 turn 时拒绝交还；否则关闭网页专用 App Server 子进程，释放其持有的会话。
2. 交还状态下拒绝普通 App Server 请求，防止历史预读、WebSocket 重连或后台刷新意外重新启动网页端 App Server 并再次占用会话；提供显式“重新接管网页端”操作。
3. 新增受配对令牌保护的交还和重新接管 API，并在运行状态中返回交还状态；对活动任务返回明确的冲突错误。
4. 前端在当前会话非运行时提供“交还本机”操作和二次确认；交还成功后显示明确状态、关闭网页 WebSocket 自动重连，且不重启网页开发服务。
5. 前端仅在用户明确选择“重新接管网页端”后恢复连接和后台读取，避免网页自行抢回本机正在使用的会话。
6. 为后端交还状态、活动任务保护、重新接管和 API 行为补充测试；更新版本记录，执行前端构建、后端单元测试、差异检查，并创建本地 Git 提交。

## 验收标准

- 空闲网页会话交还后，本机 Codex 能立即尝试打开该会话；网页服务、SSH 和配对令牌保持可用。
- 有网页任务正在运行或尚在启动时，交还请求被拒绝且不会中断任务。
- 交还后，网页的后台刷新、预读和自动 WebSocket 重连不会重新启动网页 App Server。
- 用户显式重新接管后，网页可以恢复正常查看和发送；若本机仍持有同一会话，网页沿用现有“其他 Codex 实例正在使用”的提示。
- `pnpm build`、后端单元测试和 `git diff --check` 均成功。
