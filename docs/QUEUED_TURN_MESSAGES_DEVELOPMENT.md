# 回复中排队消息开发文档

## 目标

让用户在 Codex 正在回复时仍能发送下一条消息。普通发送会按当前聊天排队，当前轮次结束后依次自动开始；每条排队消息提供“立即发送”和“编辑”操作。编辑在主输入框中完成，确认只更新原队列项，不会立即发送。

## 协议与边界

- 依据 Codex App Server 的 `turn/steer` 协议，插话请求必须携带服务端当前活动轮次的 `expectedTurnId`，且不会创建新的 `turn/started` 事件。
- `turn/steer` 不能覆盖模型、思考强度或授权策略；这些设置仅用于排队消息后续自动开始的新轮次。
- 队列按聊天隔离。切换聊天不会丢掉其他聊天尚未处理的队列，也不会把消息发送到错误的聊天。
- 后端以自身记录的活动 turn ID 为准，避免浏览器因网络延迟提交过期 ID。
- 编辑队列项时保留其 ID、顺序、模型/推理/授权设置和附件；编辑期间阻止该队列项自动发送或被“立即发送”。
- 编辑使用主输入框，确认按钮和回车都只保存队列内容；取消编辑会恢复进入编辑前的输入草稿和附件。

## 实施步骤

1. 在 App Server 包装中增加活动轮次的 `turn/steer` 调用；处理 turn 尚在启动中的短暂状态，并拒绝没有活动轮次的插话请求。
2. 增加受现有配对鉴权保护的 HTTP 插话接口，复用图片校验与暂存逻辑；客户端增加对应请求方法。
3. 前端按线程保存排队消息。回复中点击发送只入队并清空编辑器；轮次完成后按顺序创建下一轮。
4. 为每条队列提供“立即发送”、编辑和移除操作。“立即发送”成功后立即在消息流显示用户消息；若当前轮次刚结束，则安全降级为开始队首的新轮次。
5. 在原输入框中编辑队列项；确认或回车只更新原队列项并保持排队状态，取消时恢复原草稿。编辑期间锁住队列操作，避免并发发送或删除。
6. 让输入框在回复中保持可发送，保留停止按钮，同时禁止在排队期间修改模型、思考强度和授权模式，避免用户误以为它们会影响已入队的消息。
7. 补充后端单元测试，更新版本记录，执行前端构建、后端测试和差异检查后创建本地 Git 提交。

## 验收标准

- Codex 回复中可连续提交多条消息，编辑器会立刻清空，队列会按顺序显示。
- 当前回复结束后，队首消息自动开始，后续消息继续等待；不会并发调用多个 `turn/start`。
- 点击“立即发送”会以当前服务端活动 turn ID 调用 `turn/steer`，且不会创建新的 turn。
- 排队消息可在主输入框编辑；点击“确定”或按回车后原消息留在队列原位置，内容和附件更新且不会立即发出。
- 编辑期间队列项不会因当前 turn 完成而自动发送；取消编辑会恢复编辑前草稿，不丢失其原有附件。
- 当前轮次已结束的竞态下，立即发送不会丢失消息，而会作为下一轮开始。
- 排队消息可单独移除，且不同聊天的队列互不影响。
- `pnpm build`、后端单元测试和 `git diff --check` 均成功。
