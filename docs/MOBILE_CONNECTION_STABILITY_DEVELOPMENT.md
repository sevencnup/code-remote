# 移动端连接稳定性开发文档

## 目标

消除手机浏览器从后台返回时页面短暂黑屏、闪动或重复恢复聊天的问题，同时保留网络真实断开后的自动恢复能力。

## 根因

- 页面监听 `visibilitychange` 后，无论 WebSocket 是否仍健康，都会主动关闭并新建连接。
- 每次新连接都会重新读取活动聊天和侧边栏列表；手机恢复时 `visibilitychange` 与 `pageshow` 可能连续触发，造成重复请求与界面状态切换。
- 服务端健康检查正常时，这种客户端主动重连没有必要，反而会放大移动端浏览器后台恢复的渲染抖动。

## 实施步骤

1. 在客户端记录当前连接状态；从普通后台返回时，若连接仍正常则不主动关闭 WebSocket。
2. 仅在连接已经断开、页面从 bfcache 恢复，或浏览器明确报告连接关闭时创建新连接。
3. 为后台恢复请求增加短时间去重，避免 `visibilitychange` 与 `pageshow` 连续触发两次恢复。
4. 保留现有断线指数退避、历史缓存和页面恢复逻辑，不重启当前服务进程。
5. 更新版本记录，执行构建、后端测试和差异检查后创建本地 Git 提交。

## 验收标准

- 手机切到后台再返回，健康连接不会被页面主动关闭，消息区域不出现整页黑闪或重复加载。
- 网络真实断开后，仍能自动重新连接并恢复对话。
- bfcache 返回页面时，最多触发一次恢复连接。
- `pnpm build`、后端单元测试和 `git diff --check` 均成功。
