# 移动端远程连接恢复修复

## 目标与分类

处理访问 `10.126.126.3:4173` 时经常无法连接、断开后恢复不稳定的问题。本次属于 PATCH：改善已有远程连接的稳定性和弱网体验，版本为 `0.8.0-dev.6`，Android `versionCode` 为 `113`。

## 现场与问题

- 地址属于本机 `tun0` 隧道接口，服务本机访问返回 HTTP 200；这只能确认本机服务响应，不能证明手机到隧道的链路始终正常。
- 当前 systemd 服务未发生自动重启，仍运行旧后端 `0.7.0-dev.1`。上一轮修复已提交但尚未确认重启；本次不将用户提供地址视为重启授权。
- 浏览器 WebSocket 只有首次握手超时，没有应用层心跳。手机休眠或网络切换后，浏览器可能继续报告 OPEN，但实际已无法收到消息。
- 切回前台时，已连接状态只恢复历史，没有确认 WebSocket 本身是否可用；普通 HTTP 请求也缺少超时，可能长期占住合并请求。
- Android 启动只做一次 4.5 秒探测；隧道尚未恢复就失败。WebView 强制 `LOAD_NO_CACHE`，会抵消上一轮静态资源缓存优化。

## 实施步骤

1. 保留只读诊断结果，补充前后台与网络变化恢复逻辑，不修改隧道配置。
2. 增加可协商的轻量心跳，失去响应后只重连网页连接；兼容尚未更新的后端，避免旧服务因不认识心跳而反复断开。
3. 给 HTTP 请求设置合理超时，保留现有幂等消息发送与重试约束；前台恢复时检查连接并补同步，避免重复重连造成重复历史下载。
4. 修复 WebSocket 发送任务失败后的清理；保持其他客户端与 Codex 任务运行。
5. Android 恢复正常 HTTP 缓存，给启动探测有限重试；在恢复前台及网络变化时通知网页，不自动销毁已有聊天页面。
6. 完成代码检查、前端构建和可用的 Android 编译/打包，安装包使用新版本文件名，不覆盖历史包；不新增或运行测试。记录结果，更新简短版本记录并创建本地提交。

## 完成标准

- 连接失效能被检测并自动恢复，后台暂停和网络切换不会长期留下“已连接但无响应”。
- 心跳流量很小，正常前台恢复不会强制重下整段历史；失败重试有退避与超时。
- Android 保留带哈希的资源缓存，主页面更新遵循服务端缓存头；旧 APK 仍可使用网页侧改进，原生修复需安装新版 APK。
- 报告源码版本、实际服务版本和真机验证限制；不得在本次工作尚未完成时重启承载本对话的服务。

## 实现与结果

- 服务端通过 `heartbeats` 能力协商允许 ping/pong。前台静默时每 25 秒发送轻量探测，12 秒无响应则重连；后台不发探测，休眠后过期的计时器会先给网络一次新的响应机会。旧后端不会收到不支持的 ping。
- 页面恢复、浏览器网络恢复和 Android 原生恢复通知共用去重逻辑：先确认 WebSocket 能回应，再补同步。健康连接保留原连接；失效连接自动重连，连续失败按退避和小幅随机延迟重试，稳定连接 30 秒后重置退避。
- WebSocket 建连阶段设 15 秒超时，Codex 初始化阶段保留 60 秒。状态接口 10 秒超时；一般读取请求 30 秒，历史和写入请求 120 秒。超时最多自动补试一次，避免慢速大历史被连续重下；写入仍仅对原先允许重试的幂等接口进行重试。
- 服务端发送和接收任务任一退出都会清理该浏览器的订阅，避免失效客户端积压事件；操作只涉及网页连接。
- Android 资源缓存改为 `LOAD_DEFAULT`，移除每次进入的随机缓存参数。启动探测最多 3 次，连接和读取超时均为 6 秒；前台和网络恢复时可重试尚未加载成功的页面，已进入聊天的页面仅收到连接检查通知。
- Android 版本标识直接来自构建版本；增加网络状态权限与原生恢复通知，退出 Activity 时注销通知和回调。
