# 移动网页版附件按钮间歇卡顿开发记录

## 目标

降低移动网页版聊天输入区附件按钮在聊天流式更新期间偶发的响应延迟，同时保留原生文件选择器的直接手势触发。

## 诊断

- 附件按钮由透明的原生 `input[type=file]` 覆盖并直接接收点击，点击处理链没有异步等待。
- 移动布局已经不向文件选择器传递长 `accept` 扩展名列表；文件格式仍在选择后校验。
- 父页面每次渲染都会创建新的远端控制器数组；`sendComposerMessage` 又依赖各远端控制器对象。流式消息频繁更新父页面时，该回调随之变化，导致 `React.memo` 包裹的输入区也重复渲染。

## 实施步骤

1. 使用 ref 保存最新远端控制器数组，供发送回调在调用时读取。
2. 移除发送回调对每次渲染都会变化的控制器对象的依赖，使聊天消息流更新不再单独触发输入区重渲染。
3. 保留移动端原生文件输入框、附件校验和已有选择器过滤规则。
4. 更新 PATCH 版本记录，运行项目测试、生产构建和差异检查；创建本地提交，不推送远端、不构建 APK。

## 验收标准

- 流式回复更新不再导致附件输入区仅因发送回调身份变化而重复渲染。
- 移动端附件按钮仍由用户手势直接打开原生文件选择器；图片、文档的现有类型校验不变。
- 项目测试、生产构建和 `git diff --check` 通过。
