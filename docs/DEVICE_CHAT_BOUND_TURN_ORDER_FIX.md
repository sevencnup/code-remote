# 绑定聊天同步到群聊的问答顺序修复

## 问题与分类

绑定的普通聊天在 Codex 回复期间可能先收到助手实时通知，而用户提问要等历史读取才能取得。同步器因此先发布助手群消息，后发布同轮用户消息。群聊按消息序号显示，导致问答颠倒。修正已有同步行为及历史显示顺序，属于修复 / PATCH，目标版本 `0.72.1-dev.1`。

## 实施步骤

1. 用现有群记录确认同轮消息编号、序号及补齐顺序。
2. 同步器在确认本轮用户内容前暂缓助手群消息；实时轮次缺少用户内容时从持久历史补齐用户内容，同时保留更新较快的助手实时内容。
3. 网页将同一普通聊天轮次的用户消息显示在助手消息前，修复已经存储为倒序的记录，不改写群数据库序号或跨设备游标。
4. 增加覆盖“助手通知先到、用户内容后到”及历史倒序显示的回归验证；完成构建与差异检查。
5. 更新版本记录，本地提交并按既有授权推送 Gitea；当前对话结束后安全更新在线服务并核对版本。

## 验收

- 绑定的普通聊天中，用户提问先于同轮助手回复出现在群里，即使助手实时通知先到。
- 已经存储为倒序的同轮问答，刷新页面后也按用户、助手顺序显示。
- 其他群消息、消息更新、跨设备游标和自动接力保持原有顺序与行为。

## 验证结果

- 实际群记录中，同轮 win 助手消息序号为 84，“然后呢”用户消息序号为 85，证实倒序来源于消息入库顺序。
- 同步器 15 项回归通过，覆盖助手通知先于用户内容、历史修复、流式更新与原有接力行为。
- 网页排序的 2 项回归通过，覆盖已存倒序记录和普通群消息；TypeScript 检查、Web 生产构建、`git diff --check` 通过。
- Android 只更新 `versionName`，未生成安装包，`versionCode` 未变。
