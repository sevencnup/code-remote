# 网页发送消息即时显示开发文档

## 目标

用户点击发送后，聊天消息或待处理队列应立即显示内容，不等待新会话创建或发送接口返回。

## 已确认原因

- 首次发送时，客户端先等待新会话创建，之后才把用户消息加入聊天区。
- 已有会话正在回复或存在队列时，共享队列发送路径等服务端返回后才显示新排队项。
- 空闲会话已有本地即时消息，应保留其回执、历史合并和失败撤回机制。

## 实施步骤

1. 首次发送时先显示本地用户消息；会话创建后保留同一条消息，创建失败时撤回，并继续恢复输入草稿。
2. 对回复中或已有队列的发送，立即显示带“正在确认送达”状态的本地待处理项；按消息 ID 与服务端队列合并，确认后无缝转为正式队列或聊天消息，失败后撤回。
3. 发送中的本地队列项禁止编辑、提前发送和删除；有新项时展开队列，使用户立即看到内容。
4. 核对会话切换、迟到的队列快照、送达回执和发送失败场景；增加必要的队列合并回归测试。
5. 按 PATCH 更新版本与更新描述，运行定向测试、生产构建和差异检查，仅提交本次文件到本地仓库。

## 验收标准

- 首条消息在发出请求时就出现在聊天区；新会话创建期间不会消失。
- 回复中的新消息立即出现在待处理队列，文本和附件可见；服务端确认后不重复。
- 明确失败时撤回本地预览并恢复草稿；送达未确认时继续显示服务端待核对状态。
- 现有空闲会话即时发送、历史同步和跨窗格会话隔离保持正常。

## 分类

PATCH / 修复：改进已有发送流程的即时反馈，不增加新的聊天能力。目标版本为 `0.38.2-dev.1`。

## 完成记录

- 首次发送在创建会话请求发出前显示同一条本地消息；创建失败时撤回，切换会话后迟到的创建结果不会覆盖当前聊天。
- 回复中或已有队列时先显示本地待处理项；按消息 ID 与服务端队列合并，服务端标记为送达未确认时优先显示其状态。
- 本地提交中的排队项显示内容和附件摘要，自动展开队列，并在确认前锁住该项操作。
- 队列合并与历史消息合并的定向测试共 23 项通过；生产构建与差异检查通过。
