# 网页用户消息重复显示修复

## 现象与依据

同一份 PowerShell 输出在网页出现两条用户消息，发送时间相差约 2 秒。对应会话原始记录仅包含一次用户输入及其完成事件。

消息解析中的附件提取函数，无论是否含有附件，都会将三次及以上连续换行压缩为两次。截图中的终端输出包含三次连续换行，本地发送气泡保留原文，服务器回传及历史气泡却被压短，严格文本匹配因此失败。

另外，输入框虽然有同步发送锁，但读取的是 React 渲染时的草稿；请求很快结束、下一次渲染尚未提交时，再次触发可能读到已发送的旧草稿。

分类：修复 / PATCH。目标版本 `0.87.4-dev.1`，纠正已有发送与消息显示行为。

## 实施步骤

1. 附件标记解析仅移除附件块，保留正文和附件内容中的原始空行。
2. 发送入口从同步草稿和附件引用取值，发送后立即清空，避免重复使用旧渲染中的输入。
3. 检查本地发送、实时回传和历史恢复的关联路径，保留按消息 ID、轮次与发送前记录区分真实连续发送的规则；更新渲染缓存版本，从原始记录重新恢复旧消息，并在缓存中保留服务器消息 ID。
4. 更新版本记录，完成 TypeScript 与 Vite 生产构建，更新 `4173` 网页产物。
5. 检查差异并仅提交本地仓库。

## 预期结果

- 含有多行空白的终端输出，发送后与回传、历史显示保持一致，只显示一次。
- 文档附件中的空行保持原样。
- 相同草稿已被发送并清空后，迟到的发送事件不能再发送旧内容。
- 用户重新输入并再次发送的相同内容仍保留为独立消息。
