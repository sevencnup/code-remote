# 会话历史完整缓存开发记录

## 目标

切换会话时优先显示本机缓存，避免每次命中缓存仍重新下载整段 Codex 历史；只在缓存缺失、服务端会话确实更新或需要可靠性校验时读取完整历史。

## 当前问题

- 目前只有单个活动会话的受限 localStorage 快照，以及运行期间最多 6 个会话的内存缓存。
- localStorage 快照会截断较长消息，且不保存文档和图片；内存缓存命中后仍会在后台执行完整 `thread/read`。
- 刷新会话列表会预取最多 3 个未打开会话的完整历史。
- 服务端 `thread/read` 返回整个会话的 turns，因此重复校验和预取都会造成明显流量。

## 实施方案

1. 新增版本化 IndexedDB 历史缓存，存储完整消息、图片/文档、文件变更和操作记录；按最近使用时间淘汰，最多缓存 5 个会话、总量不超过 50 MiB。超限或存储不可用时安全跳过缓存，不影响聊天。
2. 会话切换时先用内存缓存；没有内存缓存时异步恢复 IndexedDB。缓存命中立即显示，不再无条件读取完整历史。
3. 使用会话列表的 `updatedAt`/运行状态与缓存元数据比较；服务端版本较新、元数据不可用、缓存缺失，或有排队消息需要确认时，才在后台读取完整历史。
4. 保留 WebSocket 实时更新；关闭对未选择会话的主动完整历史预取。连接恢复后通过会话元数据判断是否需要补读。
5. 活动会话消息安静一段时间后写入缓存；切换会话前立即保存当前快照。存储写入异步且失败不阻塞界面。
6. 为容量淘汰、缓存恢复/过期判断及“缓存命中不发全量请求”补测试；运行测试和生产构建，并创建本地 Git 提交，不推送 GitHub。

## 验收标准

- 已缓存且服务端未变化的会话切换时立即显示，不发起 `thread/read`。
- 更新过的会话先显示旧缓存，同时在后台同步；同步失败时保留缓存内容并提示状态。
- 新会话仍可完整读取并缓存；排队消息不会只凭缓存状态自动发送。
- IndexedDB 配额不足、不可用或数据损坏时，应用继续工作并退回在线读取。
- 缓存数量和估算体积始终受上限约束，淘汰最近最少使用的会话。
