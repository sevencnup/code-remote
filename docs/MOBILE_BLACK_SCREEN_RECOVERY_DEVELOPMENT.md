# 移动端黑屏自恢复开发文档

## 目标

避免移动端浏览器从后台恢复后出现整页黑屏且必须手动刷新才能恢复聊天。发生短暂渲染或视口恢复异常时，页面应自行恢复，并始终给出可操作的恢复界面。

## 已确认边界

- 当前 Vite 前端和 Python 后端进程均持续运行，健康检查正常；问题发生在浏览器客户端恢复阶段。
- 黑屏时根页面使用深色底色，若 React 渲染树异常卸载或移动浏览器的动态视口高度暂时失效，用户会只看到黑色背景。
- 不能把每次从后台返回都改成整页刷新，否则会重新引入聊天闪动、输入中断和连接抖动。

## 实施步骤

1. 在应用根部加入错误边界：渲染树发生异常时显示恢复界面，自动尝试一次重新挂载应用，而不是留下纯黑页面。
2. 在页面可见、`pageshow` 和窗口尺寸变化时刷新稳定的应用视口高度变量，避免移动浏览器恢复时 `dvh` 短暂失效而使应用容器不可见。
3. 为错误边界提供显式“重新恢复”和“刷新页面”操作，保证自动恢复失败时也无需面对无提示黑屏。
4. 保持上一项连接稳定性优化，不在普通后台返回时主动重建 WebSocket。
5. 更新版本记录，执行构建、后端测试和差异检查后创建本地 Git 提交。

## 验收标准

- 手机后台返回时，应用容器始终保有有效高度，不会因视口计算异常只剩黑色背景。
- React 渲染异常时，页面显示恢复界面并自动尝试重挂，而不是黑屏。
- 不会为了恢复界面而无条件刷新整个浏览器页面或中断健康的 Codex 连接。
- `pnpm build`、后端单元测试和 `git diff --check` 均成功。
