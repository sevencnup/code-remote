# 长文本粘贴上限调整开发文档

## 目标

移除粘贴文本的 24,000 字符拒绝限制，让长文本通过现有文档附件流程发送。

## 根因

- 前端在长文本粘贴处理里将 24,000 字符以上的内容直接拒绝。
- 长文本作为文档附件加入请求后，会进入排队请求和 Codex turn 的 `prompt` 字段；这些字段原先限制为 32,000 字符，移除前端限制仍会在后端被拒绝。
- 每条消息已有 120,000 字符的文档文本总量保护，需要保留并确保较大的请求能通过各层校验。

## 实施步骤

1. 移除粘贴处理中的 24,000 字符检查，保留长文本转为 `pasted-content.md` 文档附件的流程。
2. 将前端队列请求、后端 turn 请求及 Codex App Server 的提示文本长度校验统一放宽至足以容纳 120,000 字符附件正文和包装文本。
3. 保留每条消息 120,000 字符的文档正文上限，并在超出时继续明确提示截断。
4. 将版本分类为新增功能，更新版本号、版本记录和 Android `versionCode`。
5. 执行前端构建和差异格式检查。

## 验收标准

- 超过 24,000 字符的粘贴内容不再被拒绝，可作为文档附件加入输入框。
- 较长附件请求能通过服务端校验；超过每条消息 120,000 字符文档正文上限时仍显示截断提示。
- 前端构建成功，`git diff --check` 无输出。
