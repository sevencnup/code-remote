# 长文本与文档正文长度限制开发文档

## 目标

移除文档正文的字符数截断与请求校验，让长文本粘贴、文档附件和对话引用可以完整进入发送流程。

## 根因

- 长文本粘贴转成文档附件后，文档解析、单条消息合并、排队恢复和 Codex turn 请求仍有字符数上限，会截断正文或拒绝请求。
- 现有每条文档 20 MB、每条消息 8 个文档以及压缩文档解压体积保护可以继续控制附件大小；文档正文不应再按字符数截断。

## 实施步骤

1. 保留长文本转为 `pasted-content.md` 文档附件的流程，不截断粘贴正文。
2. 移除文档解析和同一消息合并文档时的字符数截断。
3. 移除排队消息恢复、后端请求模型、PDF 附件提示拼接和 Codex App Server 的字符数校验。
4. 保留附件文件体积、文档数量及压缩文档解压体积保护。
5. 按新增能力更新版本号、版本记录和 Android `versionCode`。
6. 执行前端构建和差异格式检查；不新增或运行测试。

## 验收标准

- 超过 24,000 字符的粘贴内容可作为完整文档附件加入输入框。
- 超过 40,000 或 120,000 字符的文档正文可以完整排队、恢复并通过服务端校验。
- 前端构建成功，`git diff --check` 无输出。
