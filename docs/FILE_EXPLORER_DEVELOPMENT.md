# 右侧文件资源管理器开发文档

## 目标

在桌面端聊天区最右侧增加类似 VS Code 资源管理器的文件树。文件树根目录跟随当前聊天窗口的 `cwd`，切换并发窗口时加载对应目录。文件和文件夹只把路径加入聊天输入框，由 Codex 在工作区内自行读取。

## 方案

1. 后端提供受配对令牌保护的工作区目录树接口，只允许枚举当前会话工作目录以内的路径，并限制路径长度和目录条目数量。
2. 前端为每个聊天窗口读取并缓存自己的文件树；当前窗口切换时只显示当前窗口的树，避免多个窗口互相覆盖。
3. 资源管理器支持目录展开、文件选择、Ctrl/⌘ 多选、拖拽和文件右键菜单。文件和文件夹统一只把绝对路径加入输入框，不读取或上传工作区文件内容；多选后右键可一次插入多条路径。拖拽同时写入自定义 MIME 和带前缀的纯文本数据，兼容会清理自定义 MIME 的浏览器。
4. 桌面端显示右侧资源树；移动端隐藏常驻面板，保留现有聊天布局和输入框行为，并通过浮层按需打开。

## 实施步骤

1. 增加后端路径校验和目录树接口。
2. 增加前端 API 类型、资源管理器组件和按窗口加载逻辑。
3. 扩展输入框拖拽区域，显示待发送文件并纳入发送请求。
4. 增加桌面端右侧布局及主题样式；移动端通过聊天头部右上角的文件按钮打开浮层，浮层底部自动停在输入框上方，不覆盖输入框。
5. 移动端文件和文件夹条目右侧提供 `+` 按钮，点击后把对应绝对路径插入当前输入框；文件窗口可独立关闭，Android 返回手势也会优先关闭它。
6. 工作台进入聊天页后屏蔽浏览器原生右键菜单；资源树文件使用自定义菜单操作，统一提供路径插入。
7. 更新版本记录，执行 TypeScript/Vite 构建和差异检查，并创建本地 Git 提交。

## 移动端交互

- 文件窗口只在用户点击右上角文件按钮后打开，避免占用聊天页面空间。
- 手机横屏时三列按 `1 : 2 : 1` 分配宽度，让中间聊天区占一半屏幕，两侧面板各占四分之一。
- 手机横屏时中间输入框的模型、思考和授权控件会按列收缩，发送按钮保持在聊天区内，不被右侧文件面板裁掉。
- 手机横屏时输入框默认使用紧凑编辑高度，仍可通过左上角拖拽控制手动调高。
- 浮层顶部直接对齐移动端聊天头部下沿，不重复叠加系统安全区间距。
- 浮层高度取导航栏到输入框之间可用高度的约四分之三，顶部位置保持不变，底部向上收起。
- 浮层通过测量输入框顶部位置计算底部间距，输入框仍可继续编辑、删除和发送已插入的路径。
- 文件和文件夹列表的 `+` 按钮只插入路径文本，不会读取或上传文件内容。

## 限制

- 文件树按目录懒加载，单个目录最多返回限定数量的条目。
- 后端不会接受工作目录外的绝对路径或 `..` 穿越路径。
