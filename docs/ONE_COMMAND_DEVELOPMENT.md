# 单命令开发启动开发文档

## 目标

让 `pnpm --filter codex-remote dev` 在同一终端启动本机 Codex 引擎和局域网页面，避免只启动 Vite 后代理反复连接失败。

## 设计

- 使用项目内 Bash 启动脚本，不增加第三方依赖。
- 脚本优先复用已健康运行的本机引擎；否则使用项目 `.venv/bin/python` 启动引擎并等待 `/health` 就绪。
- 引擎就绪后才启动 Vite，减少页面首次加载时的代理拒绝连接日志。
- 若脚本自己启动了引擎，收到退出信号或 Vite 退出时向该引擎发送 `SIGTERM` 并等待其结束；复用的引擎不受影响。
- Vite 继续监听 `0.0.0.0:4173`，Codex 引擎继续只监听 `127.0.0.1:18766`。

## 实施步骤

1. 新增启动脚本，处理引擎启动、健康检查、前端启动和退出清理。
2. 将 `dev` 与 `dev:lan` 指向该脚本，保留 `engine:dev` 用于单独排查引擎。
3. 更新启动说明和版本记录。
4. 运行前端生产构建，检查改动并创建本地 Git 提交。
5. 用新的 `dev` 命令启动服务，确认局域网页面和引擎端口均在监听。

## 验收标准

- 未单独启动后端时，运行 `pnpm --filter codex-remote dev` 后网页不会再出现引擎拒绝连接。
- 浏览器可通过 `http://192.168.15.22:4173` 访问页面，代理可到达 loopback 引擎。
- 页面服务退出时，只停止由该脚本启动的引擎。
- 已存在的健康引擎不会被启动脚本停止。
