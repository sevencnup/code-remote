# Android 实时活动状态与网页端对齐

## 目标

Android 原生聊天在“正在思考”所在行，根据当前轮实际收到的 item 开始、完成事件显示与网页端一致的状态；线程历史仅用于恢复仍标记为运行中的 item，不把已完成的历史操作显示成当前活动。

## 设计约束

- 状态只根据 App Server / 远程服务的 item 事件和当前 turn 历史确定，不根据助手正文猜测。
- 按当前线程和 turn ID 隔离活动；切换聊天、轮次结束或销毁页面时清除旧的实时活动。
- 保留现有运行计时、状态行布局和 shimmer 效果。
- 不显示 reasoning 正文或工具输出；沿用现有操作详情展示和长度限制。

## 实施步骤

1. 对照网页状态映射补齐 Android item 类型、命令类别和工具名称分类，包括思考、计划、回复、读取、搜索、命令、文件修改、MCP/动态工具、图片和子任务。
2. 让 `item/started` 更新当前活动；`item/completed` 结束该活动并回退到当前 turn 中仍在运行的 item，若没有则显示“正在思考”。
3. 从当前 turn 历史中只选取状态为 running 的最新 item，支持页面重绘或重连恢复，不复用已完成的工具记录。
4. 递增 Android 功能版本，更新版本记录；执行 Kotlin 编译检查和 `git diff --check`，仅提交本次相关文件，不推送 GitHub、不安装 APK。

## 验收标准

- 正在思考、整理计划、生成回复、读取文件、搜索文件/资料、运行命令、修改文件、工具调用、图片处理及子任务状态均对应实际活动 item。
- 工具完成后不继续显示其运行状态；若没有其他运行 item，则回到“正在思考”。
- 切换聊天和 turn 后不串用前一轮的实时活动；重绘时只从状态为 running 的当前 turn item 恢复。
- 不改动现有活动计时和回复结束后的操作记录。
