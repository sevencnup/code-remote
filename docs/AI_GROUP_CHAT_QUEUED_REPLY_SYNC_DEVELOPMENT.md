# AI 群聊排队回复同步修复

## 目标

避免群聊将本地乐观发送状态误当作 Claude/Codex 已启动的真实回复轮次。消息先进入共享队列时，群聊必须继续等待；真实轮次启动后再收集回复并结束等待。

## 修改分类与版本

- 分类：修复 / PATCH。定向消息已经进入普通聊天或队列，但群聊可能提前停止收集成员回复；本次恢复现有回复同步行为。
- 版本：`0.55.1-dev.4`。
- 版本记录：`修复 AI 群聊排队消息的回复同步竞态`。

## 实施步骤

1. 将群聊的“已观察到成员开始回复”状态改为依据服务端确认的 `runningTurnId`，不再依据乐观 `isRunning`。
2. 保留结束条件：真实轮次结束，或成员最终回复已捕获；发送失败仍由发送结果结束等待。
3. 增加回归测试，覆盖乐观运行状态撤回后仍需等待队列实际启动，以及真实轮次完成后结束等待。
4. 执行前端构建、群聊相关测试和后端共享队列测试；检查完整前端测试结果。
5. 更新版本记录并创建本地提交，不推送 GitHub。

## 验收标准

- `isRunning=true` 且 `runningTurnId=null` 的乐观发送状态不会结束群聊回复监听。
- 服务端为排队消息分配真实轮次后，群聊继续收集回复。
- 真实轮次结束后群聊退出等待状态。
- 新增回归测试和构建通过。
